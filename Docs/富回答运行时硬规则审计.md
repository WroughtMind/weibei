# 富回答运行时硬规则审计

状态：方向审计已完成，产品整体仍为“待用户验收”。

本审计执行《魏碑富回答主会话方向收束指令》：停止新增内容、形态、审美和逐题语义硬闸门；自动化只保留解析、安全、来源、资源预算、真实交互与证据真实性的最小硬边界。

## 1. 判定原则

每条规则先回答一个问题：它是在防止系统不可解析、越权、伪造来源、假互动或失控资源，还是在替 Agent 决定答案应该怎样写、怎样画？

- 前者保留为运行时硬规则。
- 后者降为 Skill、能力目录建议、模型自检或开发期观察项。
- 不能提高 Agent 表达能力和真实显示质量、只能让记录更容易变绿的改动，默认停止。

## 2. 产品运行时规则

| 当前规则 | 当前影响 | 分类 | 处理决定 |
|---|---|---|---|
| 只允许调用白名单工具 | 拒绝越过受控工具面的调用 | 安全 | 保留硬规则 |
| `textOnly` 场景禁用富回答工具 | 防止明确应纯文本的场景强行生成 UI | 场景策略 | 保留，但只能由明确场景策略触发，不得由题型偏好滥用 |
| 必须读取当前上下文且版本一致 | 防止旧材料、旧修订冒充当前来源 | 来源 | 保留硬规则 |
| 提交前读取能力目录 | 确认当前渲染能力 | 能力协商 | 保留动作要求；目录不得给出固定题型答案 |
| 富回答提交最多三次 | 防止坏协议反复重试 | 预算 | 保留硬规则 |
| schema、字段、版本、节点量、媒体和文本预算 | 防止不可解析或资源失控 | 解析与预算 | 保留硬规则 |
| 正文场景标记格式、ID、未知引用和重复引用 | 保证显式插入点可解析 | 解析 | 保留硬规则；未写标记的合法场景按协议顺延到正文末尾，不再误拒 |
| 首块必须先有正文、禁止一级标题、限制标题数量 | 拒绝原本可读的回答 | 内容与写作风格 | 降为 Skill 提示；不再运行时拒绝 |
| evidenceLedger 只能引用当前材料、选区或已检索来源 | 防止伪造摘录和越权资产 | 来源 | 保留硬规则 |
| 学习内容必须有当前来源或诚实说明 | 防止无来源内容冒充材料结论 | 来源 | 保留硬规则；普通寒暄、身份、能力问答和明确连通测试等元对话走非课程路径，夹带课程问题时仍须来源 |
| 禁止外链脚本、文件、系统调用和危险协议 | 防止代码与资源逃逸 | 安全 | 保留硬规则 |
| 一刀切禁止所有 SVG | 连可信或专业渲染器产出的 SVG 也拒绝 | 形态与安全混合 | 改为“禁止模型注入不受控 SVG”；可信渲染器输出走受控能力 |
| T1 只能调用本轮目录中存在的组件 | 防止调用不存在的组件 | 解析与能力协商 | 保留；缺能力时返回 capability mismatch，让 Agent 重规划 |
| T1 组件树、ID、参数和状态引用校验 | 防止坏树进入 Web 运行时 | 解析 | 保留硬规则 |
| T2 节点树、数据集、binding 和范围校验 | 防止孤立节点、坏数据和越界控件 | 解析 | 保留硬规则 |
| 控件、图形、标签和状态必须共享真实 binding | 防止假互动和残留标签 | 交互真实性 | 保留硬规则 |
| 固定 scene family 必须命中指定组件或角色组合 | 不匹配即 `weak_ui` 并可能降级为文本 | 内容与形态 | 从运行时硬拒绝移除，改为 Agent 设计建议和开发观察 |
| expressionPlan 的对象、关系、过程和低级图元必须逐项可见 | 关键词或图元未命中即 `weak_ui` | 逐题语义与形态 | 从运行时硬拒绝移除；保留为非阻塞诊断供 Agent 自检 |
| `NarrativeBlock(..., "conclusion")` 禁止 | 因具体写法偏好导致 T1 降级 | 写作风格 | 删除 |
| 笔记生成流程拒绝富回答 | 防止把学习解释产物混入笔记写回 | 产品边界 | 保留硬规则 |
| 渲染器能力不匹配返回诊断 | 允许 Agent 换能力重新规划 | 能力协商 | 保留并接入 Agent 协议 |
| 渲染器网络、WebGL、动画、时长和内存预算 | 防止受控能力失控 | 安全与预算 | 保留硬规则 |

| 当前规则 | 处理决定 |
|---|---|

| 真实 Pi、非 fixture、provider/model/requestID、PNG bytes/hash | 保留为证据真实性硬检查 |
| 来源存在、协议可解析、越权访问被拒绝 | 保留为客观硬检查 |
| 操作前后状态或画面必须真实变化 | 保留为交互真实性硬检查 |
| 截图来自真实魏碑窗口，包含阅读区与 Agent 区 | 保留为证据真实性硬检查 |
| 强制某题使用 T1 或 T2 | 降为开发观察，不再决定题目通过与否 |
| 强制指定组件、角色、点线数量、数据行和 binding 数量 | 移出通过判定，最多作为能力覆盖统计 |
| `text-reflow`、`layout-only`、固定 scene family 合同 | 记录风险，不自动宣布失败；由真实窗口视觉审查判断 |
| 逐题 `semanticObligations`、`requiredClaims`、`forbiddenClaims` | 改为专业人工复核材料，不再作为生成模板式硬闸门 |
| 纯文本和诚实降级必须命中固定关键词组 | 改为 `expertObservation` 开发观察并写入逐题证据；非空、来源、安全、禁止虚假已执行和协议泄漏仍硬查 |
| 视觉脚本的窗格宽度、越界、画布宽度阈值 | 保留客观测量；`warn` 不等于视觉失败，最终由真实窗口复核 |
| 审美、学习结构、视觉多样性、是否像小网站 | 只由 Computer Use、多模态视觉审查和用户判断 |
| 用户确认前自动标记 accepted | 继续禁止；整体状态只能是“待用户验收” |

## 4. Agent 当前真实能力

| 能力 | 当前状态 | 边界 |
|---|---|---|
| T1 OpenUI 深组件 | 已接入 | Agent 先读取目录，再提交声明式 program；质量高但目录仍偏封闭 |
| T2 SwiftUI 组合原语 | 已接入 | 可组合节点、数据、控件和 binding；目前低级原语容易做成文字重排或点线图 |
| 当前材料图片覆盖 | 已接入 | 只能使用当前材料允许的 assetID，不能任意访问图片或文件 |
| 开放渲染器注册表与 `renderPlan` | 第一批已接入 | Agent 可从能力目录选择图表、函数、二维、三维、地图和图像覆盖；最终效果仍须真实窗口判断 |
| 受控 Python 产物链 | 本地产品链已接入 | 白名单计算、规格和哈希证据通过；尚缺 Agent 在真实 Pi 中自主选择该路线的窗口证据 |
| 长尾组合出口 | 已有 T2 与受限 OpenUI DOM | 可处理没有专属组件的题目；受限 HTML 仍按安全、生命周期和真实学习价值逐步开放，不作为固定模板表 |

当前表达自由度约为 8/10：Agent 已能比较成熟深组件、专业 `renderPlan`、T2/受限 OpenUI 组合与纯文本。当前主要缺口不是再加固定模板，而是让真实 Pi 稳定发现并提交这些能力、补齐 Python 自主选用证据，并继续用真实窗口检查长尾质量。

## 5. 候选包版本约束

真实窗口复核只能打开由当前干净提交打出的候选包。必须同时满足：包内 `WeiBeiGitCommit` 等于当前 `HEAD`、`WeiBeiSourceDirty=false`、包内二进制与本次 Swift 构建一致、嵌入的富回答资源与当前源码一致。旧发布包、历史 `dist`、`SourceDirty=true` 的包只能用于故障取证，不能计入本轮验收。

## 6. 已冻结行为

自本审计起，停止：

1. 为单题失败追加新的 required/forbidden claim。
2. 为某类题追加固定 path/line/point、角色数量或 T1/T2 命中要求。
3. 用 `weak_ui`、协议绿灯、截图存在或组件数量代替视觉判断。
4. 在完成 56 题真实窗口复核前，大面积接入固定技术栈或重写运行时。
5. 删除用户已认可的深组件，或反过来把每道新题写成专属组件。

下一阶段先用现有真实魏碑窗口逐题复核 56 题，按 Agent 规划、能力供给、专业渲染器、宿主布局、互动绑定、来源内容和正确纯文本/降级分类；只有跨题共性证据才能触发产品架构改动。
