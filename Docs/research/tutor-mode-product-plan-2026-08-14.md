> 副标题：从“会回答”到“能带人学会”  
> 状态：产品与设计评审稿，不是开发授权  
> 日期：2026-08-14  
> 仓库基线：最新 origin/main，3023128d0f3463f3aaad8de62dfeaaf021955df3  
> 研究工作树：/private/tmp/weibei-tutor-mode-latest-20260814  
> 本轮边界：只做历史取证、源码审计、竞品研究、学习科学研究、体验方案和概念图；没有修改业务代码，没有构建、发布或合并。

## 0. 先给结论

Tutor Mode 不能是“换一个头像、名字和系统提示词”。它应当是魏碑里一种新的教学关系：

> 用户带着课程材料和目标进入；Tutor 根据用户刚刚表现出来的理解，选择下一步教学动作；用户必须亲自回忆、解释或应用；Tutor 再依据可见证据调整讲法，直到用户在少帮助或无帮助时做得出来。

第一版不需要做一所 AI 学校，也不需要再造一套应用。魏碑现有材料、阅读、来源、Chat、笔记确认、学习记忆、持久化和 Visualize 已经构成约 75% 的基础设施；真正缺的约 80% 产品闭环集中在四件事：

1. 明确的 Tutor 会话身份与目标；
2. 一轮一个动作的教学循环；
3. 能区分“看过、提示后会、独立会、能迁移”的学习证据；
4. 暂停后从确切教学断点继续。

因此，推荐先做“一节真的会教的课”：围绕一门课程、一个具体目标、一个当前概念，跑通“尝试 → 教学 → 再作答 → 判断 → 换法或迁移 → 暂停 / 结束”。首版不做百项技能树、课程日历、LMS、主动催学、自由白板或自动写笔记。

视觉上，推荐以第三张“原文旁教学”为首版骨架：保留魏碑最有辨识度的材料现场，把第一张“行进中的课堂”的单步教学和第二张“活的概念纸”的证据关系融入其中。这样 Tutor 是魏碑长出来的新关系，而不是另外一款学习 App。

## 1. 三类事实必须分开

这份计划刻意把“用户已经拍板的边界”“最新仓库事实”“本轮新提案”分开，避免把历史讨论中的 Agent 建议倒灌成需求。

| 层级 | 已确认内容 | 本轮如何处理 |
|---|---|---|
| 用户已经确认 | Assistant 与 Tutor 长期共存；切换 Tutor 要新开一条对话；Assistant 偏知识解答和自己阅读时的辅助；Tutor 更对话主导，可以围绕错误继续教学；旧七阶段 Study Flow 不够好 | 作为不可破坏的产品边界 |
| 用户只方向性认可 | “自习 / 上课”的心智模型还不错 | 不当作最终命名；本稿暂用“助手 / 导师”便于讨论 |
| 最新仓库事实 | 冷启动是新空白 Chat；旧历史与课程恢复点仍保留；现有材料、来源、笔记确认、学习记忆和 Visualize 可复用；当前没有 Tutor mode；旧 RichAnswer 不是现役生成链 | 作为实现约束和复用基础 |
| 本轮新提案 | Tutor 会话最小状态、证据梯度、暂停恢复卡、首版页面方向、阶段划分和验收指标 | 等产品评审后才成为实现要求 |

## 2. 产品定义

### 2.1 一句话定义

魏碑 Tutor Mode 是一个扎根于用户课程材料、由学习证据驱动下一教学动作、并能从明确断点继续的对话式教学模式。

### 2.2 它与普通聊天的真正分界

分界不在“会不会提问”，而在“谁负责教学闭环”：

- Assistant 对用户的问题负责：给出有帮助、有来源的答案，然后停下。
- Tutor 对用户的学习目标负责：在用户允许的范围内，组织尝试、解释、练习、反馈与再验证。

Tutor 不是永远拒绝答案的苏格拉底机器人。用户明确要求直接解释、已完全卡住、或新手缺少必要起点时，Tutor 应当直接讲；区别是讲完后会在合适时机把认知工作交还给用户，并清楚记录“这次是看懂了，还是独立做出来了”。

### 2.3 北极星

Tutor 成功，不是这一轮讲得多漂亮，而是：

> 下一轮少帮一点，用户仍然能独立解释或应用。

首要产品指标建议采用“无提示迁移成功率”：接受 Tutor 帮助后，用户面对表面不同但考察同一原理的新任务，能否在不看答案、不使用提示时完成。

### 2.4 目标用户与首版场景

首版服务已经在魏碑里阅读真实课程材料的个人学习者，尤其是：

- 读懂了字面意思，却无法用自己的话解释；
- 知道一个公式或概念，却不会在新情境里使用；
- 一直问相似问题，却不知道误区在哪里；
- 想继续上次学习，却忘了停在哪一步；
- 想把真正学会的内容整理进笔记，但不希望 Agent 擅自写入。

首版不是教师后台、班级系统、考试排程或校园任务管理器。

## 4. 学习科学如何变成产品规则

这不是要把论文机械做成流程，而是为 Tutor 设置最低行为标准。

| 证据方向 | 产品规则 | 不能过度推断 |
|---|---|---|
| 主动回忆与测试效应 | 关键概念要让用户在看不到答案时产出；延迟复测比“刚讲完答对”更有说服力 | 不等于越频繁考试越好，也不等于选择题分数就是理解 |
| 自我解释 | 少问“懂了吗”，多问“为什么、A 如何导致 B、用自己的话解释” | 字数、语气流畅、自信程度都不是理解证据 |
| 示例与逐步撤除帮助 | 新手可以先看完整示范，再逐步补步骤，最后独立完成 | 机械删步骤不保证迁移；要让用户说出原理 |
| 有边界的先尝试 | 在安全、范围清楚的任务里先让用户预测或初步解题，再用其思路教学 | 不是让用户无目的受挫；儿童、完全新手或程序熟练任务未必适合先失败 |
| 防止 AI 代劳 | 完整答案放在提示阶梯后面；区分“在帮助中答对”和“撤掉帮助后答对” | 不能宣称使用 AI 必然导致认知退化 |

## 5. Assistant 与 Tutor 的产品合同

| 维度 | Assistant | Tutor |
|---|---|---|
| 用户心智 | 我在读、写、查；它帮我 | 我想学会；它带我走完一小段 |
| 谁决定节奏 | 用户 | Tutor 提议下一步，用户可随时改 |
| 开场 | 直接接住问题 | 确认目标和材料范围，做最小校准 |
| 一轮如何结束 | 答案完成即结束 | 原则上留下一个明确的学习者动作 |
| 提问 | 只在完成回答必需时追问 | 为诊断、回忆、应用和验证主动提问 |
| 答错之后 | 解释正确答案 | 判断误区，换解释、例子或提示，再让用户尝试 |
| 直接答案 | 默认可以 | 可以，但会标记为“已讲解，尚未独立验证” |
| 来源 | 支撑当前回答 | 同时支撑题目、反馈、误区修正和概念状态 |
| 视觉 | 有助理解时临时出现 | 可作为教学动作与作答工具，但不逢答必画 |
| 学习状态 | 观察性线索，不能擅自宣布掌握 | 来自真实作答和提示依赖的验证性证据 |
| 笔记 | 提议，用户确认 | 课末提议，用户编辑并确认 |
| 模式切换 | 切换即新建另一模式 Chat | 切换即新建另一模式 Chat |
| 历史 | 保持 Assistant 姿态 | 保持本节目标、断点和教学证据 |

绝对边界：

1. Assistant 不因用户问了一个知识问题，就把普通对话拖进连续测验。
2. Tutor 不因用户一次答对，就写入长期“已掌握”。
3. 两种模式共享课程与经确认的学习事实，但不共享对话人格和未验证推断。
4. Tutor 不是 provider、模型选项或第二个 Agent 后端。

## 6. 首版体验架构

### 6.1 入口

建议在新建 Chat 的真实入口提供两个同等清晰的选择：

- 助手：提问、查资料、协助阅读与笔记；
- 导师：围绕一个目标开始一节教学。

在已有 Chat 内点击另一模式时：

1. 明确告诉用户“将新开一条导师 / 助手对话，当前对话会保留”；
2. 创建新 StudySession；
3. 不改写旧消息，不把旧历史换人格；
4. provider 和模型保持全局设置，不跟着模式切换。

课程首页可以提供两个任务式入口：“问一个问题”和“开始学这个”。最终文案仍需产品评审，不把“自习 / 上课”提前定稿。

### 6.2 Tutor 开场

开场只收集决定第一教学动作所必需的信息：

1. 这次要学会什么；
2. 主要以哪门课程 / 哪份材料为范围；
3. 用户已有理解未知时，用 1—3 个高信息量问题做校准。

时间、难度、先讲后练等可以在有用时补问，不要让用户先填一张学习偏好表。目标允许随时修改；修改后 Tutor 说明哪些进度仍有效、哪些需要重新校准。

### 6.3 核心教学循环

~~~mermaid
flowchart TD
    A["选择导师"] --> B["新建独立 Tutor Chat"]
    B --> C["确认本节目标与材料范围"]
    C --> D["最小诊断：预测、回忆或解释"]
    D --> E["Tutor 选择一个教学动作"]
    E --> F["用户亲自作答、操作或说明"]
    F --> G["记录答案、提示依赖与来源"]
    G --> H{"当前证据"}
    H -->|尚未理解| I["识别误区或先修缺口"]
    H -->|部分理解| J["给较小提示或对比例子"]
    H -->|暂时稳固| K["换情境做无提示应用"]
    I --> E
    J --> F
    K --> L{"迁移是否成立"}
    L -->|否| I
    L -->|是| M["标记本次已验证，安排待复测"]
    M --> N{"继续、暂停或结束"}
    N -->|继续| E
    N -->|暂停| O["保存确切教学断点"]
    N -->|结束| P["已验证 / 仍薄弱 / 下一步"]
    P --> Q["可编辑笔记提案，用户确认后写入"]
~~~

这个流程不是旧七阶段的替代状态机。用户可以随时插入问题、要求直接讲、换例子、查看原文、修改目标或结束。Tutor 只需要始终知道三件事：当前目标是什么、刚获得了什么证据、下一步为什么这样选。

## 7. 教学动作，而不是固定教学阶段

每次 Tutor 回复只选择一个主要教学动作：

| 动作 | 何时用 | 结束时交给用户什么 |
|---|---|---|
| 校准 | 不了解起点 | 一个短预测、解释或选择 |
| 直接讲解 | 完全新手、用户明确要求、已有尝试无法推进 | 一句复述或最小应用 |
| 完整示范 | 结构化问题且用户缺少范式 | 让用户解释关键一步为何成立 |
| 提示 | 用户已有部分正确结构 | 补齐缺失关系，不给完整答案 |
| 对比例子 | 混淆两个相近概念 | 判断新例子属于哪一侧及原因 |
| 回原文 | 判断需要材料证据 | 用原文修正自己的表达 |
| 回忆检查 | 刚学完一个核心关系 | 不看原文，用自己的话说 |
| 应用检查 | 能复述但未用过 | 用同一原理解决近似新题 |
| 迁移检查 | 已通过同型题 | 在表面不同的情境中识别原理 |
| 纠错 | 答案暴露明确误区 | 解释差异后再让用户作答 |
| 收束 | 本节达到目标或用户要停 | 确认已验证、未解决和下一步 |

Host 记录当前动作和证据，模型选择下一动作。首版不需要把所有教学顺序硬编码成复杂状态机。

## 8. 学习证据：不要再用“懂了吗”

### 8.1 可见证据梯度

建议使用一条克制、可解释的证据梯度，不叫“掌握百分比”：

| 层级 | 含义 | 可以怎样证明 |
|---|---|---|
| 看过 | 内容已呈现 | 阅读或听过解释 |
| 能辨认 | 能在给定选项中识别 | 选择、匹配、分类 |
| 能回忆 | 不看答案能说出核心关系 | 简答、自我解释 |
| 能应用 | 能在同型新题中使用 | 独立判断或计算 |
| 能迁移 | 能在表面不同情境中识别原理 | 新材料、新表述、新问题 |
| 待复测 | 当前表现不错，但尚未隔时验证 | 下一次课程或延迟检查 |

界面语言应说“本次已独立应用”“用了一个提示后完成”“尚未验证”，不要说“你已永久掌握”。

### 8.2 每条检查点至少记录

- 本轮考察的具体目标；
- Tutor 给出的任务；
- 用户的原始答案或提交结果；
- 是否看了原文；
- 使用了几级提示；
- 结果是尚未理解、部分理解还是本次暂时稳固；
- 判断依据和来源；
- 下一教学动作；
- 会话、课程和修订号；
- 时间。

反应时间、信心和语气只能作为弱信号，不能单独改变学习状态。

### 8.3 提示阶梯

1. 无提示尝试；
2. 轻提示：指出该关注哪个关系；
3. 对比或来源提示：给反例、关键词或原文位置；
4. 部分示范：展示关键一步，留下一步给用户；
5. 完整示范：必要时给出，但随后换题、撤掉帮助再验证。

只要使用了提示，就不能把这一轮记为“无提示独立完成”。

### 8.4 误区分类

Tutor 不应只输出“错了”。先判断错误更接近：

- 概念关系颠倒；
- 缺少先修知识；
- 会原理但操作失误；
- 题目或来源本身含糊；
- 多份材料冲突；
- 证据不足，暂时无法判断。

一次表现不足以给用户贴长期标签；如果判断不确定，Tutor 应用一个澄清问题确认，而不是编造画像。

## 9. 视觉不是装饰，是教学动作

用户说的“把东西可视化”不能被理解为每一轮都生成一张图。正确目标是：需要空间、因果、变化、比较或操作时，视觉让用户更容易形成和检验模型。

### 9.1 四类视觉职责

| 视觉类型 | 作用 | 首版例子 |
|---|---|---|
| 来源视觉 | 把判断贴回原文 | 高亮段落、页码、引用锚点 |
| 解释视觉 | 表达文字不擅长的关系 | 因果链、公式变化、函数图、过程模拟 |
| 行动视觉 | 让用户真正动手 | 排序、配对、分类、测验、滑块、情境模拟 |
| 证据视觉 | 展示为何选择下一步 | 本次回答、提示依赖、当前待验证项 |

最理想的教学视觉不是孤立制品，而是一条可追溯链：

> 来源 → 当前问题 → 用户动作 → Tutor 判断 → 学习证据 → 下一步

### 9.2 复用与缺口

现役 weibei_visualize 已能做公式、测验、排序、配对、归类、模拟、图表、轻量 3D、稳定 ID 原位更新和局部状态恢复。首版直接复用，不新造渲染器。

真正缺的是一个最小的结构化结果接口：现有 quiz 的本地正确反馈，不会自动把作答、提示、耗时和信心交给 Tutor，因此不能直接作为学习证据。首版应只补“关键提交如何形成检查点”这条接缝；纯展示和本地操作状态继续留在视觉块里。

首版明确不做自由手写白板。只有当真实学习场景证明“画图本身就是必须评估的学习动作”时再做。

### 9.3 视觉一致性

- 继承魏碑纸面、宣纸、墨石、石碑四套主题；
- 用朱砂表达唯一当前焦点，用苔绿表达已经有证据的状态；
- 来源紧贴主张，不放到远处的“参考资料抽屉”；
- 不用紫蓝渐变、游戏化分数、彩色技能卡片和通用 AI Dashboard；
- 所有交互支持键盘、VoiceOver、清晰焦点和非颜色唯一编码；
- 视觉失败时，文字教学与来源仍必须完整可用。

## 10. 三张概念图的检查结论

### 10.1 行进中的课堂

优点：

- 单一当前教学动作非常清楚；
- 用户回答、Tutor 反馈、依据和下一步在同一纵向节奏里；
- 右侧证据梯度能表达“为什么还要继续”。

风险：

- 容易变成一套新的沉浸式课程页面；
- 教学步数 3 / 8 容易被误解为固定脚本；
- 右侧证据梯度若铺得太满，会滑向技能 Dashboard。

决定：保留“每屏一个主教学动作”和“下一步有理由”；取消固定总步数，证据只显示当前概念。

### 10.2 活的概念纸

优点：

- 最能表现用户理解是如何被修正的；
- 原文、公式、用户解释、误区和迁移题形成一张可追溯的学习对象；

风险：

- 对非关系型内容并不合适；
- 图一旦过大，会把教学变成维护概念图；
- 首版实现与交互复杂度高于真实必要。

决定：把它作为 v1.1 的关系型教学视图；首版只保留小型关系图和证据节点，不做全课程知识图谱。

优点：

- 与魏碑当前阅读、来源、Agent 和笔记工作台连续；

- 已有布局和 Visualize 能力覆盖度最高；

- 右栏容易变成拥挤聊天栏；
- 当前教学动作、作答、视觉和检查点同时出现时，需要严格控制层级；
- 当课程没有主文档时，需要复用现有沉浸对话布局。

决定：作为首版主骨架。右栏只保留一个当前教学动作；历史默认收起；复杂关系用可展开视觉块；没有主材料时切到现有沉浸对话，而不是新建第四种页面。

## 11. 暂停、恢复与结束

### 11.1 暂停

暂停不是只保存聊天记录。至少保存：

- 本节目标和稳定材料范围；
- 当前概念；
- 上一次教学动作；
- 用户最后一次回答；
- 当前判断及依据；
- 下一问；
- 已验证与待验证项；
- 暂停时间与原因（若用户提供）。

### 11.2 恢复

魏碑当前冷启动刻意进入新空白 Chat，这一安全原则不应被 Tutor 偷偷改变。推荐在课程首页或 Tutor 空态显示一张显式恢复卡：

> 继续上次教学  
> 你在“实际利率”停下；已经能解释费雪关系，下一步是不看原文判断一个新情境。

用户点击后恢复精确 Tutor Chat 和教学断点。不能仅打开同一历史，然后让模型猜接下来该做什么。

### 11.3 结束

课末只给三类信息：

1. 本次已经用什么证据验证；
2. 哪些地方仍依赖提示或没有验证；
3. 推荐的唯一下一步。

如果值得写入正式笔记：

- 有活动笔记：给出可编辑提案；
- 没有活动笔记：让用户先选择或新建目标；
- 无论哪种情况，用户确认前都不能写入。

## 12. 最小产品状态

这是本轮建议，不是历史确认的架构。

### 12.1 Tutor 会话

- 模式：Assistant / Tutor；
- 课程与优先材料范围；
- 本节目标；
- active / paused / completed；
- 当前概念；
- 当前教学动作；
- 下一问；
- 少量按时间排序的检查点；
- 修订号和时间。

首版只有“一节课 + 当前概念”，不先建完整 Session → Unit → Move 课程树。

### 12.2 检查点

检查点是 Tutor 可验证的最小学习事件，不是普通聊天摘要：

- 问了什么；
- 用户实际怎样回答；
- 用了什么帮助；
- 基于什么来源；
- Tutor 得到什么暂时结论；
- 下一步为何改变。

### 12.3 跨模式记忆

建议：

- 课程材料、用户明确目标和可见的长期学习记忆可共享；
- Tutor 产生的结构化验证证据，在用户可见、可改、可追溯的前提下可影响长期记忆；
- Assistant 观察到“用户重复询问”只能作为弱线索，不能自动降级用户水平；
- Assistant 可以利用已验证信息调整解释，但不能因此主动启动教学循环；
- 不把整段原始历史塞给模型当“记忆”，优先传递少量结构化事实。

## 13. 首版纵向切片

### 13.1 必须包含

1. 助手 / 导师入口；
2. 切模式必新建 Chat；
3. Tutor 会话标题、目标、状态和稳定材料范围；
4. 最小诊断；
5. 一次一个教学动作；
6. 文本作答的结构化检查点；
7. 答错后至少能换一种解释或提示；
8. 撤掉帮助后的独立应用；
9. 精确来源与原文跳转；
10. 暂停、显式恢复和结束；
11. 已验证 / 仍薄弱 / 下一步；
12. 笔记提案继续由用户确认；
13. 复用至少一种现有 Visualize 互动；
14. Assistant 行为完全不被 Tutor 污染。

### 13.2 明确不做

- 全课程自动规划；
- 100 多项技能树；
- 掌握百分比、连胜、积分和庆祝；
- LMS、课程日历、考试倒计时、系统通知；
- 后台主动催学；
- 固定学习风格人格标签；
- 自动写正式笔记；
- 自由手写白板；
- 第二套 Store、第二套 provider 或第二个模型设置；
- 复活整个旧 RichAnswer；
- 把旧七阶段 Study Flow 直接当 Tutor 引擎；
- 把本地 quiz 的对错直接当长期掌握；
- 每轮必画图；
- 无限制的自主后台循环。

## 14. 分阶段推进

| 阶段 | 要解决的问题 | 交付物 | 退出条件 |
|---|---|---|---|
| 0. 产品合同与评测样例 | Tutor 到底应该怎样教、哪些行为绝对禁止 | 模式合同、黄金教学脚本、错误样例、评测准则 | 人可以稳定判断一轮回复是 Assistant 还是 Tutor、证据是否成立 |
| 1. 一节真课 | 证明 Tutor 能围绕一个概念完整教学 | 模式新会话、目标、诊断、动作、文本检查点、纠错、独立应用、暂停恢复、结束 | 一条真实材料路径端到端可运行，答错后会换法，重开能继续 |
| 2. 互动结果接缝 | 让 Visualize 参与作答而不是只展示 | 一种互动练习产生结构化结果，四套主题和无障碍验收 | UI 局部状态与学习证据不混淆，文字失败兜底有效 |
| 3. 课程内证据与复测 | 让一次课程影响下一次，但不误判长期掌握 | 可见、可改的课程证据；待复测；显式继续上次教学 | 跨会话恢复正确，Assistant 不被污染，一次正确不会永久掌握 |
| 4. 关系型概念视图 | 在确有价值的学科呈现理解变化 | 小型活概念纸，点节点继续教学 | 比纯文字明显提升理解或定位误区，否则不做 |
| 5. 可选学习计划 | 真实需求出现后再安排何时学 | 课程内一个可解释下一步；之后才评估日历或提醒 | 用户明确需要且不会造成权限、通知和错误截止日期负担 |

阶段之间不按日期硬排。每一阶段只有前一阶段真实可用、指标成立后才继续。

## 15. 评测与验收

### 15.1 主要指标

| 指标 | 定义 | 为什么重要 |
|---|---|---|
| 无提示迁移成功率 | Tutor 帮助后，用户面对不同表述的新任务能否无提示完成 | 最接近“真的会了” |
| 提示依赖下降 | 同一目标后续所需提示是否减少 | 证明 Tutor 正在撤除帮助 |
| 证据完整率 | 每次状态变化是否能回到真实回答、提示和来源 | 防止模型凭感觉评估 |
| 教学断点恢复成功率 | 重开后能否回到同一目标、当前概念和下一问 | 区分继续聊天与继续学习 |
| Assistant 污染率 | Assistant 是否开始无授权追问或循环 | 保护双模式边界 |
| 错误掌握声明数 | 没有足够证据却宣称用户已掌握 | 目标必须为零 |
| 笔记越权写入数 | 未确认就写入正式笔记 | 目标必须为零 |

不采用：

- 总对话时长；
- 消息轮数；
- 生成了多少测验、图和笔记；
- 用户刚听完时说“懂了”；
- 单次选择题正确率；
- “使用越久越成功”。

### 15.2 黄金场景

| 用户操作 | 应该看到什么 | 通过标准 |
|---|---|---|
| 从正在读的材料进入导师 | 新 Tutor Chat，带入课程与材料但要求确认目标 | 不改变原 Assistant Chat |
| 用户说“我完全不知道” | 先给最小起点或示范，再让用户完成一个小动作 | 不进行无目的拷问 |
| 用户自信地答错 | Tutor 指出具体误区、贴回来源、换解释后再问 | 不只说“错了”，不羞辱 |
| 用户提示后答对 | 状态显示“提示后完成，待独立验证” | 不标为独立掌握 |
| 用户换情境仍答对 | 显示本次迁移已验证，并说明证据 | 不宣布永久掌握 |
| 用户要求直接答案 | 给出答案，明确“已讲解，尚未独立验证” | 不阻挠用户，也不伪造证据 |
| 用户打开另一材料 | 可作为临时参考，但本节范围不静默漂移 | 当前目标保持稳定 |
| 两份来源冲突 | 明确展示冲突，停止下掌握结论 | 不混成一个确定答案 |
| Visualize 失败 | 文字、来源和下一动作仍完整出现 | 不能吞正文 |
| 用户暂停并重开 App | 冷启动仍是空白；课程页出现显式恢复卡 | 点击恢复同一下一问 |
| 结束时无活动笔记 | 先让用户选择或新建笔记 | 不自动创建、写入 |
| 切回 Assistant | 新建 Assistant Chat，直接回答并停下 | 不继续 Tutor 循环 |

### 15.3 自动与真实 App 门槛

开始实现后，至少验证：

1. 旧工作区没有 mode 时能安全解码为 Assistant；
2. 切模式必定创建新 Chat，历史、Pi 目录和教学状态不串线；
3. 生成中切换沿用现有停止确认与正文保留；
4. provider / model 改变不改变会话模式；
5. Tutor 范围不随临时焦点漂移；
6. 过期、重复、跨会话检查点被拒绝；
7. 一次正确不会直接写长期掌握；
8. 互动局部状态与结构化提交分开；
9. 来源仍能精确回到页 / 章节；
10. 笔记冲突、外部修改、确认和撤销仍有效；
11. 冷启动原则不变，恢复卡回到精确断点；
12. 四套主题、键盘、VoiceOver 和结果播报可用。

真实 App 轻量路径：

> 从课程材料进入 Tutor → 学一个概念 → 答错 → Tutor 换法 → 无提示再答 → 查看来源 → 暂停 → 重开 → 从恢复卡继续 → 结束并确认笔记 → 新建 Assistant 对话验证其仍直接回答。

## 16. 风险与防线

| 风险 | 对用户的伤害 | 防线 |
|---|---|---|
| Tutor 只是新提示词 | 看似会教，无法恢复和验证 | 会话状态与检查点必须是产品对象 |
| 永远苏格拉底式反问 | 用户被卡住、效率低 | 允许直接讲、示范与用户节奏控制 |
| 一次答对就掌握 | 错误画像影响后续教学 | 分清提示后、独立、迁移和延迟复测 |
| 追问过多 | 教学变审讯 | 一轮一个主动作；问题必须改变下一步 |
| 原文与通用知识混在一起 | 用户无法核验 | 材料内判断与外部补充分层标示 |
| 视觉过度 | 页面拥挤，认知负荷上升 | 只有明显帮助关系、变化或操作时才用 |
| 视觉作答没有回传 | 看起来互动，实际 Tutor 不知道发生了什么 | 为关键提交增加结构化结果接缝 |
| 范围漂移 | 从一门课学着学着串到另一门 | 会话开始固定稳定范围，临时焦点不改目标 |
| 记忆跨模式污染 | Assistant 变成 Tutor，或误区被永久化 | 分离历史姿态；只共享可见、可改、带证据事实 |
| 自动写笔记 | 数据和作者权被侵犯 | proposal → edit → confirm → persist → undo |
| 恢复变自动续课 | 冷启动打扰、打开错误现场 | 只提供显式“继续上次教学” |
| 大状态 / 原始日志全塞模型 | 成本高且不一定有效 | 少量结构化证据优先 |

## 17. 实现准备，不是本轮实现

- 复用现有 StudySession、Chat 隔离、课程材料、来源跳转、学习记忆、笔记确认和 Visualize；
- 不新增第二套 Store、Agent runtime 或 provider；
- 在现有阅读 / 对话 / 笔记工作台上长出 Tutor；

## 19. 最终产品判定

Tutor Mode 只有同时满足下面四件事，才值得叫 Tutor：

1. 它知道这节课要学会什么，而不只是知道用户问了什么；
2. 它会根据用户刚刚做出来的东西改变下一步，而不只是继续生成；
3. 它能说明“为什么认为你现在会到这里”，并允许用户纠正；
4. 它暂停后能从教学断点恢复，而不是只续上一段聊天。

少任何一项，都更接近 Assistant 的新皮肤。
