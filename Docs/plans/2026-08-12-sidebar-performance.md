# 课程侧边栏性能修复方案

## 目标

修复课程侧边栏的三个用户可见问题：

1. 点击打开或关闭后，动画不能立即开始。
2. 侧边栏内部滚动沉重、掉帧。
3. 打开过一次以后，即使侧边栏已经关闭，DOC / CHAT / NOTES 仍持续迟缓。

同时保持三个主窗格的宿主身份、草稿、滚动位置和当前内容不变，不回退课程与文件的真实删除能力。

## 已确认根因

- 打开路径在动画前重设整棵 SwiftUI root，并强制执行两次布局。
- 外层 `LazyVStack` 只懒加载三个分组，分组内普通 `VStack + ForEach` 仍一次创建全部行。
- 文件行在渲染期间重复读取并解析 Markdown 标签，课程行反复扫描成员关系和计数。
- 关闭只把面板移到屏外；长驻 `NSHostingView` 仍观察整个 `WorkspaceStore` 与窗格状态。
- 每行常驻菜单放大行创建成本，但不是生命周期根因。

## 最小成熟方案

- 保留覆盖式 AppKit 抽屉，不改成挤压 DOC / CHAT / NOTES 的系统分栏。
- 内部改用 SwiftUI `List`；真实规模探针中，当前结构创建 540 行，`List` 只创建 19 行。
- 侧栏只接收带稳定 ID 的纯值行投影；标题、标签、计数和关系在渲染路径外计算。
- 打开时挂载侧栏观察树；关闭动画完成后清空 root、取消任务并卸载宿主。
- 面板保持固定尺寸，只通过 AppKit animator 改变 x 原点；不在动画前重设 root 或强制布局。
- 只有清除以上根因后，2,000 行压力测试仍证明 SwiftUI `List` 本身是主要瓶颈，才升级为 `NSOutlineView`。

## 产品验收 seam

自动检查只守四个用户可见边界：

1. **抽屉动作**：打开和关闭的指令到开始移动不超过一个显示刷新周期，完成不超过 150ms。
2. **目录滚动**：行按需构建，渲染路径没有同步文件读取和 Markdown 解析。
3. **关闭后安静**：关闭完成后，连续无关工作区与窗格更新不会触发侧栏投影、body 或磁盘读取。
4. **主窗格连续性**：开关侧边栏前后 DOC / CHAT / NOTES 的三个宿主身份不变，性能相对从未打开侧栏的基线劣化不超过 5%。

## 实现边界

- 不重写三个主窗格。
- 不改变课程、资料、笔记的持久化和删除语义。
- 不增加第三方依赖。
- 不以回退旧版本或隐藏动画伪造顺滑。
