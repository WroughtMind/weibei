# 课程文件完整支持计划

日期：2026-09-14。状态：已确认的支持计划；现代 Word/PPT 已在独立候选中接入，尚未合入正式产品。本文第 3、7 节保留定案时的研究快照，当前进度以[实施与验收记录](2026-09-14-课程文件实现与验收.md)为准。

本计划覆盖 Word、PPT 从导入到阅读、搜索、提问、笔记和再次回访的完整流程，并列出旧版 Office 文件和电子书的扩展顺序。本计划替代此前结论中的 OCR 建议；此前文档保留为实验记录。

## 1. 结论与交付目标

**推荐沿用魏碑现有阅读器，增加按格式显示正文的能力。原文件直接导入、原件保留，普通文字直接读取，不增加 OCR，不要求用户事先转格式。公式、表格和图片显示正确是采用组件和交付功能的前提。**

完整体验应当是：

> 老师发来讲义或课件 → 放入课程 → 在现在的阅读区打开 → 搜索或选中文字 → 提问、摘抄、批注 → 关闭重开 → 点击笔记回到对应原文。

已经确定的产品要求：

- PDF、HTML、Word、PPT 共用现有阅读布局、搜索入口、划词浮层、笔记和对话；按文件特点显示页码、幻灯片或章节。
- 公式不能缺失、错符号、上下标错位或被裁切；表格数据不能错行错列，图片和图表不能悄悄丢失。
- 图片中的文字不额外识别，也不增加截图选字功能。图片正常显示即可；本次不增加公式编辑或求解器。
- 阅读保持本地、离线可用。用户发起 AI 提问时沿用现有模型与费用，不在导入时自动调用模型。
- 笔记、引用、课程归属和文件维护继续使用现有保存规则。

## 2. 格式支持范围与交付顺序

| 文件 | 支持计划 | 完成标准 |
|---|---|---|
| 现代 Word（`.docx`） | 首个完整交付；普通内容、原生公式和旧嵌入公式一起验收 | 显示正确，并走通搜索、划词、笔记、重开回跳 |
| 现代 PPT（`.pptx`） | 首个完整交付；保留幻灯片顺序、文字、公式、图片、表格、图表及已有备注内容 | 正确显示与按页导航，正文检索和引用能落到对应对象 |
| 旧版 Word / PPT（`.doc`、`.ppt`） | 后续独立交付；先验证成熟旧格式读取引擎 | 同一批真实资料通过显示和学习流程验收，不能仅改扩展名或复用现代格式解析器 |
| 电子书（`.epub`） | 后续独立交付；按书籍章节和目录接入现有网页阅读能力 | 目录、阅读顺序、脚注、图片、书籍位置和笔记回跳正确 |
| 现有 PDF、HTML、Markdown、文本 | 沿用现有实现，列入受影响流程的回归验收 | 新格式接入后现有体验不退化 |

这是实现顺序建议。旧格式和电子书仍是独立的待交付项，不能用 DOCX/PPTX 完成代替整个范围完成。Office 编辑、PPT 动画播放、宏执行不属于本次阅读功能。

`.doc/.ppt` 的候选路线需要另做本地引擎验证；例如成熟办公引擎可以生成内部阅读数据，用户仍直接导入原件。但是否采用、安装增量、中文字体和公式还原质量均未验证，本轮不把这种引擎加入默认依赖。EPUB 也需独立核定组件，不能交给 Word/PPT 库。

## 3. 当前证据与组件判断

| 项目 | 已经确认的事实 | 当前判断 |
|---|---|---|
| 现有阅读器 | PDF 与 HTML 使用不同显示组件，但共同接入阅读区域、搜索状态、划词提问和批注入口 | 可以延续这个模式 |
| Word 候选组件 | 普通文字、表格、图片和一份原生分式样本已在隔离实验中显示；上游不承诺完全重现 Word 动态分页 | 可以继续验证，尚未定选 |
| 旧试卷公式 | 旧实验漏掉或裁切 16 个公式实例，涉及 13 个旧图片资源；本轮已定位并修复实验中的多项记录解释错误 | 有具体修复路径，尚未完成全部保真验收 |
| PPT 候选组件 | 常见正文、表格、图片、二维图表有实现；上游明确未支持原生公式、完整旧矢量图、嵌入对象和备注渲染 | 不能直接作为完整方案采用 |
| 大课件 | 100 页偏文字合成样本的单页显示、搜索与第 100 页跳转通过；连续列表及媒体密集真实课件尚未通过本轮验收 | 不能据此承诺大型课件性能 |
| 系统预览 | 之前能显示这份旧试卷的公式，但另一个原生公式样本缺失；公开接口也没有满足现有学习交互所需的统一定位能力 | 不作为默认完整阅读器 |

候选版本是 Word 阅读组件 `docx-preview 0.4.0` 和 PPT 阅读组件 `@aiden0z/pptx-renderer 1.2.4`。两者许可证均为 Apache-2.0；所试旧矢量图解码组件 WMFJS 的文件带 MIT 许可。采用时固定版本、随包保存许可和必要修改，所有运行资源本地提供。[Word 官方说明](https://github.com/VolodymyrBaydalka/docxjs/blob/0.4.0/README.md)、[PPT 官方支持边界](https://github.com/aiden0z/pptx-renderer/blob/v1.2.4/README.md)、[Word 包清单](https://github.com/VolodymyrBaydalka/docxjs/blob/0.4.0/package.json)、[PPT 包清单](https://github.com/aiden0z/pptx-renderer/blob/v1.2.4/package.json)。

**主路线明确，具体组件有条件采用。** 先验证能否用有限的格式适配补齐关键缺口；如果需要长期自行维护大面积 Office 排版能力，就重新选择成熟引擎。不能通过删掉公式要求、用占位内容或改成单纯系统预览来算交付成功。

## 4. 公式和复杂内容怎样处理

| 内容 | 实现办法 | 必须核对的结果 |
|---|---|---|
| Word、PPT 原生公式 | 读取文件中的数学结构，使用可验证的数学排版能力显示。Word 候选已有部分实现；PPT 必须补原生公式入口，优先复用经验证的公式处理逻辑 | 分数、根式、上下标、求和与积分上下限、矩阵、分段、重音、括号、中英混排均不改变含义 |
| 旧公式对象 | 读取原文件中保存的对象显示资源，正确解码其坐标、符号、字体、字距和边界；原始对象仍保留 | 本次真实试卷的 16 个实例逐个完整显示，再扩展其他旧公式样本 |
| 图片公式 | 按原图和原始比例显示 | 清晰、没有裁切，不声称图片内部文字已经可搜索或可复制 |
| 表格、图片、图表 | 使用组件的真实内容和布局；同时核对内容数量、标签、坐标轴、数值及视觉结果 | 单元格不能错位，图表不能改含义；不能把三维图自动改成二维后视为通过 |
| 流程图、组织图等复杂图形 | 读取文件中实际保存的图形内容或可验证的显示资源 | 箭头、连接关系、标签和层级完整；不可用普通图片样例替代验收 |
| 脚注、原作者批注、PPT 备注 | 保留它们与正文或幻灯片的关联，以附属原文呈现 | 内容可回访，不混入用户新写的魏碑笔记，也不冒充正文 |

Word 已有公式处理代码可供评估复用，但仍需补齐样例覆盖；不能把内部未承诺稳定的接口直接当成产品长期接口。PPT 原生公式是选型前的必过项，不能放到普通课件接入之后才发现缺失。[Word 公式解析源码](https://github.com/VolodymyrBaydalka/docxjs/blob/0.4.0/src/document-parser.ts)。

导入解析时记录公式、图片、表格和图表的来源及数量，显示完成后核对是否遗漏。**数量对上只证明没有整块漏掉，不能证明符号和布局正确。** 正式验收必须结合真实视觉对照；运行时对已识别的解析失败如实报错，不能把不完整内容标记成正常可用。

### 本轮旧公式实验的实际进展

问题有两层：Word 库没有处理试卷中的旧对象入口；把对象接进来后，旧图片解码器又没有完整执行文件的文字绘制规则。

本轮依次验证了：

1. **只修坐标不足以修好公式。** 原文件要求从此前记录的位置绘制，库却把多个符号画在 `(0,0)`；修正后符号出现，但仍有重叠与失真。
2. **再按原始大小、逐字符间距、Symbol 符号编码、字重与斜体显示。** 回归式中的希腊字母和上下标恢复；继续检查发现帽子符号和中文仍错误。
3. **按原编码读取英文符号和中文。** 帽子符号、中文“和”等在实验画面恢复。最终 13 个资源、16 个实例均加载；原始位置、希腊字母、帽子符号、中文解码的程序检查通过。

这些是依据文件格式规则修正显示，不是 OCR 或重新猜公式。微软明确规定文字的当前位置、对齐、编码及逐字符间距。[文字位置规则](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-settextalign)、[旧图片文字记录规范](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-wmf/7d07c44a-a828-4b82-9af0-e0a81cced5a8)。

边界：已查看全部 13 个公式资源的实验画面；此前的空白、重叠、帽子符号乱码和中文乱码已在这些画面中修正。一个资源中的 `age` 仍触发字体边界框提示，截图可见完整字形，不能仅凭边界框断言实际裁切。尚未与 Word/PowerPoint 的受控输出完成全部逐项对照，也没有覆盖全部旧图片格式。因此当前结论是“关键根因已经定位，修复路径有实测依据”，不是“公式兼容已全部完成”。系统预览图只作为辅助对照，它自身也有失败样例。

## 5. 如何接进现有产品

| 部分 | 复用什么 | 实际要补什么 |
|---|---|---|
| 导入与资料管理 | 原件复制校验、重复文件处理、课程归属、目录维护 | 格式识别、选择文件入口、拖入、文件夹扫描及课程文件重新发现要一起支持新格式 |
| 正文显示 | 现有阅读区域、网页容器、资源加载与外层控件 | Word/PPT 显示适配；只使用组件显示正文的能力，不搬入它的整套演示界面 |
| 导航与阅读位置 | 现有内容导航和阅读状态 | PPT 按真实幻灯片顺序与身份跳转；Word 按章节和段落定位，不把重新排版后的页码当永久位置 |
| 搜索与 AI 资料读取 | 现有课程索引、资料范围校验和读取工具 | 按段落、表格、幻灯片、备注建立索引；结果带原文件位置，未挂载的 PPT 页也应能搜到 |
| 划词、提问、摘抄、批注 | 现有选区状态、浮层、对话和保存入口 | 将新正文的选区传入原流程，并把位置带进笔记与引用 |
| 重开与回跳 | 现有记录保存、资料身份、回访入口 | 文件版本、原文范围、段落/幻灯片/对象位置的保存与解析；先加载目标内容，再定位和高亮 |
| 文件更新、移动与删除 | 现有文件维护和变更通知 | 旧解析任务取消，受影响索引与显示缓存失效；引用不得跳到已变化的错误内容 |

搜索读取真实文字和表格内容。原生公式必须保留结构边界，不能把上下标等随意压成一串文字后冒充准确公式；图片中的文字不进入新增全文索引。AI 的资料覆盖信息要反映这些边界。是否针对某个图片公式提问沿用既有视觉能力另行处理，不增加截图识字系统。

位置只保存确有需要的信息：当前文件版本、原文所在部件或幻灯片、段落或对象、文字范围，以及引用原文。画面坐标每次显示时计算。文件内容变化后核对引用；不能确认新位置时保留摘抄内容并明确位置已变化，不猜测回跳目标。

## 6. 开发顺序与每步完成标准

| 顺序 | 交付内容 | 通过条件 |
|---|---|---|
| 1. 定选型 | 真实资料样例、内容清单、Word/PPT 公式和复杂内容的隔离显示验证 | 旧试卷公式、PPT 原生公式和关键图表样例全部正确；给出采用组件、必要修改与维护边界 |
| 2. 接通阅读 | 原件导入、资料类型、Word/PPT 正文、章节/幻灯片导航、阅读位置 | 导入一份讲义和课件，在现有阅读区完整阅读；切换文件、缩放、窗口变化与重新打开正常 |
| 3. 接通学习 | 全文索引、AI 读取、划词提问、摘抄、批注和来源位置 | 每个入口使用同一资料身份和原文；PPT 未显示页可检索；普通文字交互与 PDF/HTML 一致 |
| 4. 接通回访 | 重开恢复、笔记回跳、文件更新、移动与改名处理 | 关闭应用后能回到原文；原件改变不出现旧结果串入新文件或跳错位置 |
| 5. 做完整验收 | 真实资料、大课件、资源释放、离线、打包和现有功能回归 | 没有已知公式/内容错误，性能和完整操作链通过，候选包证据齐全 |
| 6. 扩展格式 | 旧版 Office 与 EPUB 分别完成选型和上述流程 | 每种新格式独立达到相同显示、学习和回访标准 |

导入入口、现有索引接点与资料样例整理可以并行推进；组件定型依赖第 1 步。不得先交付“只能看看”，再把同一功能里的划词、笔记和回跳无限后移。

## 7. 验收清单

验收资料优先使用已经拿到的真实试卷、讲义和课件，并补足它们没有覆盖的公式、复杂图形和大文件样例。预期显示以受控的 Word/PowerPoint 原生输出及原文件内容为依据；测试生成的小样例用于定位单个问题，不能替代真实资料。

| 用户怎么操作 | 应该看到什么 | 当前状态 | 问题备注 |
|---|---|---|---|
| 导入单文件、多个文件和资料文件夹 | 正确加入课程，原件保留，重复与同名处理符合现有规则 | 未接入 | 多处格式白名单和导入入口需同步 |
| 阅读含原生公式、旧公式、图片公式的资料 | 公式全、符号对、上下标和分式关系对、放大不裁切 | 部分实验通过 | 旧试卷有修复证据；PPT 原生公式仍是缺口 |
| 查看表格、图表和复杂图形 | 行列、坐标轴、数值、标签和连接关系正确 | 部分实验通过 | 三维图不能用二维近似充数 |
| 搜索一段原文，包括 PPT 尚未显示的页 | 搜到准确位置并跳到目标内容 | 仅隔离 PPT 样例通过 | 尚未接入课程索引 |
| 划词提问、摘抄、写批注 | 沿用现有浮层与保存流程，来源准确 | 未接入 | 程序选区实验不能替代实际鼠标操作 |
| 关闭重开，再从笔记回原文 | 到同一段或幻灯片，标记对应原文 | 未验证 | 需持久化与真实应用证据 |
| 缩放、调整窗口、键盘查找和切换格式 | 焦点、滚动、选择与快捷键稳定 | 未验证 | 同时回归 PDF、HTML |
| 外部改原文件、移动或改名 | 正确采用新文件状态；不污染笔记、不跳错原文 | 未接入 | 复用既有资料维护和写入规则 |
| 打开媒体密集大课件，快速切换再关闭 | 界面可操作，旧任务取消，内存及临时资源能释放 | 未验证 | 已有 100 页纯文字实验不代表大媒体文件 |
| 离线打开，或遇到损坏/加密/无法正确读取的文件 | 正常本地阅读，异常如实说明且原件安全 | 未验证 | 不把失败文件当空白资料或纯文本处理 |

自动检查覆盖文件范围、解析结果、公式结构、资源数量、来源位置、重复文本定位、取消与保存；真实应用验收覆盖视觉、鼠标、键盘、焦点、缩放、重开和引用回跳。对象计数、编译通过、单张截图均不单独代表完成。

## 8. 体积、性能与维护成本

| 成本 | 计划与现有证据 |
|---|---|
| 软件体积 | 已测阅读脚本和解压库约 1.25 MB，加试用旧图解码约 1.40 MB；这是实验脚本大小，不是正式安装增量。最终要计入公式、字体和实际采用的资源 |
| 阅读性能 | 先显示需要的内容；PPT 按需挂载页与解码图片，搜索依赖原文索引；切换或文件更新时取消旧工作 |
| 缓存 | 使用文件版本区分结果，复用现有索引；不保存整份课件的所有页面大图，不另起一套全库扫描和独立数据库 |
| 运行费用 | 本地阅读方案不产生按页服务费；AI 提问沿用现有费用。未选择付费引擎，不能把其费用计为零 |
| 开发和维护 | 主要工作是格式正确性、位置与索引接入、实际交互。公式和复杂图形决定选型风险；新增导入按钮本身不是主要成本 |
| 排期 | 先完成第 1 步并记录真实工作量，再给实现工期；目前没有完整验证依据，不承诺固定天数或周数 |

导入的文档属于外部输入：复用现有安全文件访问，限制解压资源规模，阻止越界路径和主动脚本/宏执行。内容解析不应自行联网读取外部资源。这是必要的内部实现约束，不新增用户操作流程。
