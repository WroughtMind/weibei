# 魏碑 Agent 资料查找、阅读与引用整改计划

日期：2026-09-09  
状态：方案经对抗审查后定案，正在实施。  
范围：从提问时的阅读位置，到资料工具、模型获得的正文、答案引用及点击定位。

本次补充的三个旧功能问题，纳入同一份整改计划：

| 问题 | 修好后的行为 | 实施方式 |
|---|---|---|
| 读取量不听要求 | 工具不擅自抬高 Agent 请求的读取额度 | 去掉现有 1,000 字符下限；保留正常的单次输出预算和续读 |
| 目录只能看前面 | 长文档后面的章节也能通过目录找到 | 在现有目录工具内补齐章节分页，返回下一页游标 |
| 笔记引用跳不到位置 | 点击引用打开对应笔记，并定位到引用的那一节；重开会话后仍能跳 | 将来源中的章节位置传入现有笔记编辑器跳转命令，沿用消息保存与恢复 |

**100 字只是说明“不要擅自加量”的例子，不是新的最小值、最大值或固定读取量。** 这三项是补完整现有功能。最终在真实 App 中走通一次“找到后面章节 → 读取 → 引用 → 点击跳转 → 重开还能跳”，作为交付验收，不写成 Agent 每次回答的必经流程。

## 一、建议采用的方案

**保留现有 Agent 循环和资料解析能力，将资料工具收拢为“列目录、查原文、读指定位置”三个明确职责。Agent 的内容搜索改为在已有缓存原文上做字面匹配；引用只由答案实际使用的原文片段生成。**

这里的“字面匹配”就是：模型给出要查的连续文字，工具返回确实包含这些文字的位置。模型可以换词、翻译关键词、缩小或扩大范围；工具自身不把一句查询偷偷拆成一堆“命中任何一个都算”的条件。

实现继续使用现有 SQLite 数据库、PDF 文本提取、文字识别、章节定位、分页读取、会话账本和引用组件。现有全文索引仍服务 App 的手工搜索；Agent 不再借用手工搜索界面的排序和截取结果。两者共用同一份解析缓存，不维护第二份资料或第二套索引。

这次不引入向量检索、独立搜索服务、额外模型评审、查询规划器或新的 Agent 框架，也不重做笔记、记忆、教学模式和会话渲染架构。

本轮同时核对了安装版和远端主线：安装版为构建 **1802**，对应提交 `429a86fc`；调查时远端主线为 `d193dcad`。本计划涉及的核心检索、工具、阅读位置和引用生成代码，在这两个提交之间没有变化。本计划随本次实现纳入源码仓库。

| 环节 | 已确认的实际行为 | 对用户的影响 |
|---|---|---|
| 当前阅读位置 | 请求已经知道材料编号、标题和页码，但给模型的位置文本有标题时省略编号；已有章节定位也没有完整传入 | 明明正在读某一页，模型仍被引导先搜索材料 |
| 两个搜索工具 | “课程搜索”实际可搜所有已登记课程；另一个“工作区搜索”默认当前课程，内部又使用手工搜索流程 | 工具名称、说明和实际范围不一致，模型难以准确选择 |
| 匹配方式 | 查询自动拆词后以“任意词命中”搜索；之后还经过课程上下文构造器再次评分、截取 | 问金融概念也会带回只出现了 why、international 的论文 |
| 原文读取 | 读取参数有 query；query 非空且未提供位置时，读取内部回到搜索 | 调用了“读取”也不一定拿到连续原文 |
| 读取额度 | 参数处理把小于 1,000 字符的有效读取额度抬到 1,000 | Agent 请求少读一点时，工具仍可能多返回正文 |
| 章节目录 | 默认只取前 24 条、内部最多 80 条，单份材料的目录没有续页入口 | 后面的章节不能通过目录取得 |
| 续读说明 | 工具说明要求一直翻到游标为空 | 简单问题也可能被引导穷尽搜索或读完整份文档 |
| 来源生成 | 搜索候选自动写入已读材料，并全部加入答案来源 | 来源区出现答案没有引用的材料，课程关联也会被候选结果影响 |
| 引用定位 | 来源主要按材料编号去重，引用标签依赖标题，页码和章节没有从返回片段准确传到来源 | 同一材料的不同页、同名材料以及实际引用摘录无法准确区分 |
| 笔记引用打开 | 公共来源打开入口选中笔记后就返回，没有把来源章节传给编辑器；编辑器已有按章节跳转能力 | 点击只能打开整篇笔记，无法到达被引用的那一节 |

用户截图对应的真实一轮问答，只调用了一次课程搜索。五条返回内容共 **11,816 字符**，其中四条无关材料共 **9,600 字符，约占 81%**。答案正文只标注金融课件，来源区却列出全部五条。三个同名论文条目来自三个课程，并不是模型连续搜了三次。

这也限定了结论：现有运行器已经支持多轮工具调用。“只搜一次就回答”本身不构成错误；关键是材料是否足够相关、返回内容是否足够回答，以及来源是否准确。整改不规定必须调用多少次工具。

## 四、用户应当得到的行为

| 用户正在做什么 | Agent 的正常处理 |
|---|---|
| 选中的原文已足以回答 | 直接解释，需要引用时引用这段选区 |
| 选中的是概念标题，正文还不够 | 用本轮已有的材料编号和页码直接读取当前页，再判断是否需要相邻页或其他资料 |
| 点名某份课件，但没有具体位置 | 从目录定位课件，再在该课件内搜索关键词，读取相关位置 |
| 问“这个课程里哪里讲了……” | 在当前课程查找；结果不足时可以换词或继续阅读 |
| 问“我所有资料里有没有……” | 明确搜索整个资料库，结果带课程、材料和页码/章节 |
| 使用中文询问英文课件中的概念 | 模型根据问题选择英文词或原文词，再显式查询；工具不承担自动翻译 |
| 闲聊或不依赖个人资料的知识解释 | 正常回答，资料工具不是必经流程 |
| 索引尚未完成或页面识别失败 | 工具如实返回当前可用正文和覆盖状态，答案据此说明实际查到的范围 |

当前课程只是默认上下文和相关性线索。仍然是一个 Chat，模型可以根据任务扩大搜索范围，不增加跨课程授权弹窗，也不制造新的 Chat 分类。

## 五、三个工具的具体职责

优先沿用三个现有工具名，减少无关改名：目录工具 `weibei_course_map`、工作区搜索工具 `weibei_search_workspace`、正文读取工具 `weibei_course_read`。删除重复的 `weibei_course_search` 入口及其专用转接路径。

### 1. 列目录：回答“有哪些材料、编号是什么、有哪些章节”

输入：查询范围、可选范围编号、可选名称筛选、分页游标、数量上限。

返回：材料编号、标题、类型、课程归属，以及已有页数或章节目录。指定一份材料时返回该材料目录。名称筛选只用于找课程或材料，不与正文匹配混在一起。

材料列表和单份材料的章节目录都能分页。当前章节读取默认只返回 24 条、内部最多 80 条，宿主又没有提供章节续页；这条路径需要一并修正，不能把当前默认的目录片段当成完整目录。目录仍使用同一个工具和分页约定，不另外增加章节工具。

目录结果不自动算作已读正文，也不产生课程事实引用。

### 2. 查原文：回答“这些文字在哪一页、哪一节出现”

输入：`query`、查询范围、可选范围编号、分页游标、数量上限。

返回：实际命中的页或章节、匹配附近的原文、材料与课程标识、可引用标签，以及是否还有结果。一个命中对应一个具体位置，不能把几个不相邻的页面拼成一段没有边界的摘录。

查询规则只有一种：**不区分大小写的连续文字匹配**。查询内容保持原样，标点和空白按原文处理；本次不增加正则、全部词、任意词、语义搜索等模式。

模型可以继续发起不同查询。例如先查 `Market Imperfections`，没有结果时再查 `imperfection`。这是模型做出的下一次行动，工具不会偷偷放宽条件，也不自动轮询或遍历所有结果。

### 3. 读指定位置：回答“这里的连续正文是什么”

输入：必填材料编号 `itemID`，可选页码 `page` 或章节定位 `location`，续读游标 `cursor`，可选读取额度 `maximumCharacters`。保留单次输出预算，取消现有把额度强制抬到至少 1,000 字符的行为。

材料编号可以来自当前阅读位置、选区、目录、搜索结果或会话中已知的资料。移除“必须先搜索得到编号”的说明和“没填就读取上一次搜索结果”的隐式行为。

页码从 1 开始，与用户看到的页序一致；进入现有阅读器和存储模型时只转换一次。章节定位使用宿主返回的完整标识，与显示标题分开，按标识精确匹配；移除现有的任意子串匹配，避免 `markdown-heading-1` 同时读到第 10、11 节。PDF 按页序定位，带文字识别标记的同一页仍能正常读取，不把展示文字作为模糊定位条件。首次没有给页码或章节时，从文件开头顺序读取。

**删除读取工具的 query 参数及内部转回搜索的分支。** 读取始终返回指定范围的连续正文。游标表示这次读取还有内容，模型根据任务决定是否续读；没有游标也不等于整个文件的所有页面都已被识别。

### 共用的范围和分页约定

| 参数 | 含义 |
|---|---|
| `scope: material` | 指定材料；省略范围编号时使用本轮当前材料 |
| `scope: course` | 指定课程；省略范围编号时使用本轮当前课程 |
| `scope: library` | 全部已登记资料与笔记 |
| `scopeID` | 搜索其他材料或课程时，使用上下文或目录返回的稳定编号 |
| `cursor` | 将上次返回的 `nextCursor` 原样传回；三个工具使用一致的命名 |

目录、搜索的范围由调用明确给出；当前上下文会告诉模型可以使用哪个材料、哪个课程。请求当前材料或课程、但实际没有对应上下文时，工具返回缺少目标的正常错误，不悄悄改成全库。

结果带实际执行的范围，便于模型和现有日志说明查了哪里。范围在匹配和数量截断之前生效。输入仍使用现有结构检查，访问仍限定在 App 已登记的资料中。

### 上下限的具体取舍

| 项目 | 处理 |
|---|---|
| 读取额度下限 | 删除 1,000 字符下限，正常正整数即可。返回正文遵守请求额度；100 字仅是例子，不新增任何读取量门槛。原实现抬高的是额度，也不保证实际正文一定有 1,000 字符 |
| 单次输出上限 | 保留，控制一次返回给模型的内容量。现有读取上限 12,000 字符可作为初始输出预算，超过后通过游标继续；它不是整份材料最多可读多少的限制 |
| 目录的 24/80 条限制 | 不再作为不可继续的总量截断。按实际目录分页，后面的章节始终有入口可取；章节定位值完整返回，长标题只在显示时缩短 |
| 搜索结果数量 | 作为单次返回数量使用，有剩余结果就提供续页。Agent 路径不继承旧检索的固定词数、命中块数或二次候选截断 |
| 页码和游标 | 保留类型、实际范围和读取位置检查；不沿用把偏移硬夹到 1,000,000 这类与实际结果无关的上限 |
| 工具调用次数 | 不设至少查几次、最多读几轮。当前主循环已没有固定工具步数上限，继续使用模型判断、正常取消及上下文管理 |

输出预算在工具返回边界统一处理，底层按需要的预算提供内容，不再逐层重复截掉同一份结果。PDF 解析进程自身的内存、文件大小和执行时间限制是独立的设备资源约束，本次不做无依据的全量清除。

## 六、底层如何保持简单且准确

### 搜索复用缓存，读取按需取得原文

现在的数据库已经保存了材料编号、分块顺序、页码/章节位置和提取出的原文。Agent 内容搜索从所选范围读取这些记录，按真实页或章节恢复连续文字，再用系统字符串匹配能力查找。现有的解析队列、取消处理和文件变化刷新继续使用。

读取与搜索分开：文本和 Markdown 直接读取当前文件，未保存笔记使用当前草稿；PDF 先复用同版本目标页，缓存命中不复制整份文件；缺页时只提取该页。页面没有原生文字或绘制了图片时，使用已有文字识别补齐正文，并保留识别未覆盖的原生文字；识别失败仍保留失败状态。识别结果写入已有页缓存，后续读取和后台索引复用；原生文字没有最低字数要求。按需读取不等待全篇索引，不新建缓存、解析队列或识别系统。每次工具调用刷新现有资料状态，已删除资料不继续访问。

PDF 的技术分块约为 1,900 字符，其他文本分块为 2,000 字符。恢复同一页或章节时，需要去掉缓存为每块重复加入的页码/标题前缀，按原顺序拼回正文，避免一个词刚好被技术分块切开就漏找。不同页、不同章节仍保持分离。

逐页或逐章节处理即可，不一次把整个资料库装入模型上下文。返回片段必须包含真实命中，展示附近的必要上下文；更多正文交给读取工具。排序使用当前阅读材料优先、当前课程优先及稳定的资料和位置顺序，不再经过另一套上下文评分器重排。

当前编辑中的笔记继续使用宿主已有的内存正文，与其他材料使用相同的字面匹配和章节读取规则；无需先强制落盘或建立另一份索引。

章节解析规则改变后，已完成的旧笔记缓存也必须刷新。将 Markdown 的解析版本纳入现有缓存签名，沿用原有按需刷新路径，只让受影响的 Markdown 缓存失效；签名生成和文件读取检查使用同一版本。文件本身未修改也能获得新目录。PDF 混合扫描页的提取规则也纳入现有版本签名，避免复用只含页码的旧缓存；其他类型保持现有版本。不建立迁移器。

### 为什么不直接把“任意词”改为“全部词”

现有全文索引存的是去重后的派生词表，原文列没有参与全文索引。中文还会生成连续两字的组合。这份词表不能直接承担“原文包含这段文字”的承诺。

本轮用内存数据库核对了一个明确反例：原文是“公开市场操作与政策利率”，查询是“公开市场操作”。按现有拆词结果直接要求全部词命中，结果为零；原文字面匹配为真。继续为这一差异补分词、词组和排序规则，会增加这次并不需要的复杂度。

SQLite 确实支持短语、AND 和 OR，但它匹配的是被写入索引的词序列；这不等于当前魏碑的去重词表保留了原文词序。[SQLite 查询语法](https://www.sqlite.org/fts5.html#full_text_query_syntax)、[默认分词器说明](https://www.sqlite.org/fts5.html#unicode61_tokenizer)。

### 当前数据支持这个取舍

本轮只读核对的缓存包含 **39 个文件、922 段、984,537 字符**。在现有原文中查询 `Market Imperfections`，得到金融课件中的四段命中；截图中的四条无关材料都没有命中。

这证明该查询可以通过已有缓存准确执行，不构成新实现的速度承诺。字面搜索耗时随所选文本量增长，沿用现有后台任务和取消能力即可；不为尚未测出的规模问题提前建立第二套索引。实现时在扫描处用一条简短注释记录这一复杂度边界。

### 搜索状态不再冒充正文命中

只将真实命中的正文放入结果列表。索引中的、尚未覆盖的、识别失败的材料，通过现有可用性和覆盖元数据表达，不因为“这是一个 PDF、有总页数”就塞进命中列表。

分页截断与索引未完成是两件事：`nextCursor` 表示还有可返回内容；已有覆盖信息表示哪些内容尚未可用。沿用现有状态即可，不建立索引状态中心或额外告警界面。

## 七、引用如何从原文准确到达答案

### 同一份定位信息贯穿整个流程

本轮上下文补齐当前材料编号、标题、课程编号、页码或章节定位，并保留已有选区正文。只有定位时，不把它当成正文证据；选区已经有正文时，直接为该选区提供可引用标签。

搜索或读取每次真正返回原文，都附对应定位和一个唯一标签。可以沿用现有标签语法，例如 `[材料：r4.1]`、`[选区：r4.2]`；编号由宿主生成，模型只需在相关句子后使用。用户看到的仍然是“金融课件 · 第 17 页”，内部编号不进入产品界面。

使用现有来源对象承载材料编号、课程归属、页码/章节和摘录，使用现有 `label` 字段承载标签。不根据标题猜材料，也不只按材料编号合并所有页面。同一份资料的第 17 页和第 21 页可以各自被准确引用。

搜索片段如果已经足够支持回答，可以直接引用；目录条目和只有覆盖信息的记录没有原文，不能自动生成事实引用。是否还需读取更多上下文由模型判断。

### 答案来源只从实际使用的标签产生

已有工具结果处理处记录“可用来源”，正文引用解析得到“实际使用来源”。最终消息只持久化实际使用者。读取记录只在正文读取成功时更新，搜索候选不再写进已读记录，也不再导致无关课程关联。

同一个标签重复出现只显示一次来源；不同页或不同材料不因同名而合并。引用位置与摘录来自那一条被使用的原文记录，不能取“这个文件第一次搜到的片段”代替。

复用现有引用标签到链接的转换和普通资料打开入口。宿主只负责解析真实编号、显示标题和打开位置，不增加模型评审、相关性打分或引用真实性审批。无法对应到真实记录的标签不生成链接，不猜另一个材料来补。

### 补齐笔记的章节跳转

公共来源打开入口的笔记分支目前只选中笔记和展开面板，随后直接返回。这里接上来源中已有的章节位置，复用笔记目录点击时使用的 `scrollToHeading` 命令。主聊天与浮动来源入口都走这条公共路径，在此修一次，不在各个按钮中分别补逻辑。

跳转命令必须归属于目标笔记，沿用编辑器现有的文档切换和待执行命令机制，在目标文档加载后执行；不能在切换期间把命令绑定到原先的笔记，也不靠固定延时等待。定位继续保存在已有来源对象中，点击时直接使用，重开会话不重新搜索。

章节编号也要在这条路径上对齐：资料端当前用逐行正则数标题，编辑器按解析后的真实标题节点计数，代码块中的 `#` 和下划线式标题会让两者顺序不同。资料端复用项目已引入的 Markdown 解析库（`swift-markdown`）取得标题及原文范围，但普通 Markdown 解析不能直接视作与编辑器等价：先按编辑器已有规则分离文件头元数据，并对齐公式块等会改变标题识别的现有规则。标题序号按实际可跳转标题的顺序计数，空标题可以不展示，但不能让后面的序号前移。目录、分节读取和引用使用同一位置；原文范围保留与源文件的对应关系。内部从零开始的序号与界面从一开始的节数只转换一次。

这些改动只补齐现有章节识别与跳转口径，不扩展 Markdown 语法、不重写编辑器，也不另建章节数据库、标题猜测或锚点服务。

### 流式显示、跨轮和重开会话都沿用同一结果

沿用现有文本进度事件，随累计正文传递已经被引用的来源，使流式阶段和回答完成后的来源一致。共用现有未完成标签处理，避免内部标签一边生成一边漏到界面。

本轮来源映射保留在内存，最终实际引用直接随现有消息的 `sources` 保存，重开后点击就使用这份定位数据。工具返回内容本来就会写入现有账本；后续轮次引用仍在模型当前上下文中的旧标签时，从对应的工具结果或历史消息来源取得映射。不新增账本事件字段、不复制保存一份来源表，也不为恢复映射扫描整个历史账本。编号含现有轮次信息，避免新一轮覆盖前一轮的标签。选区也进入同一映射，不能只有工具读取才支持引用。

会话摘要不替代原文。后续问题需要先前未保留的具体正文时，再按已知材料和位置读取。重新打开会话时，最终来源直接使用消息已经保存的定位信息，不重新跑搜索。

已有历史问答保留，不批量改写旧回答或重建旧来源。新回答统一使用新契约，删除的工具不保留备用执行入口。

## 八、提示词只保留必要的使用说明

删除当前“先课程搜索、再工作区搜索、必须把所有游标读完”等固定链条。系统提示只需要表达以下意思：

> 先使用本轮已有内容。需要原文且位置已知时直接读取；位置未知时查目录或搜索。工具结果不足时可以换词、扩大范围或续读。引用资料时使用返回的引用标签。

范围、匹配方式、页码和游标的具体含义写在对应工具说明中，系统提示不再重复整份工具教程。不增加最低调用次数、强制二次阅读、穷尽检索、回答前评审等执行条件。

## 九、实施顺序与改动位置

整个整改作为一个完整实施任务推进，不把每个步骤拆成独立上线功能。步骤之间以结果衔接，不设日历期限，也不逐步要求用户重复确认。

| 步骤 | 具体工作 | 这一阶段应达到的结果 |
|---|---|---|
| 1. 打通已知位置 | 补齐本轮材料与章节编号；读取去掉 query、上次搜索结果默认值和不合理的额度下限；沿用选区来源；返回带位置的连续正文 | 用户在第 17 页提问时，模型可以直接读取该页，无需先搜材料编号 |
| 2. 收拢目录和搜索 | 保留三个工具职责；范围显式化；章节目录可续页；Agent 搜索使用缓存原文字面匹配；结果按具体位置返回；移除重复搜索与二次评分截取 | 搜什么、在哪里搜、实际命中哪里都准确可见，中文查询不因派生词表漏找，目录后部可以继续取得 |
| 3. 贯通引用和正常显示 | 原文附唯一标签；实际引用才进入答案来源；笔记章节位置接入现有编辑器跳转，对齐章节编号并等待目标文档加载；覆盖选区、搜索片段、读取正文、流式显示、跨轮和重开；删除旧自动挂来源行为 | 答案中每个来源都能对应实际使用的片段，点击回到正确资料和位置，长笔记后部章节重开后仍能到达 |
| 4. 收尾并验证 | 同步精简工具和系统说明；更新必要调用方与现有检查；编译、定向验证、一次完整 CI、一个真实候选闭环 | 完整方案可在真实魏碑入口使用，交付时证据齐全 |

| 位置 | 负责内容 |

| 资料工具宿主：`WorkspaceStore+NativeAgent.swift` | 范围解析、原文结果、目录、工具合并与分页 |

| 运行器与请求/结果模型：`NativeAgentLoop.swift`、`StudyAgentRuntime.swift` | 区分候选、已读与实际引用，贯通选区和跨轮来源；复用已有消息来源与工具记录，不改账本存储结构 |

避免把新逻辑继续堆进宿主主文件。新的小数据结构只有在需要表达“具体位置的原文片段”时才增加，不建立通用检索接口或服务层。

手工搜索继续使用的 `WorkspaceStore+GlobalSearch.swift` 和全文索引调用方需要核对共享接口，但不在这次重做其产品行为。课程上下文构造器仍有初始上下文的用途，只从工具的搜索/阅读返回路径移除重复处理，不整套删除。

### 直接删除和继续复用

| 直接删除 | 继续复用 |
|---|---|
| 重复的课程搜索工具和 Agent 专用的手工搜索转接 | 现有多轮模型—工具循环、取消、上下文压缩 |
| 读取中的 query 搜索分支、默认读取最后搜索材料的行为 | PDF 提取、文字识别、原文缓存、页码和章节定位 |
| Agent 查询自动拆词 OR、二次评分和无位置片段拼接路径 | App 手工搜索仍在使用的全文索引能力 |
| 搜索即已读、所有候选自动成为答案来源 | 已有来源对象、链接渲染、普通点击打开资料、笔记编辑器的章节跳转与文档加载机制 |

## 十、只做与这次问题直接相关的验证

本轮研究只进行了源码、会话和数据库的只读核对，以及一个内存数据库反例验证；没有运行产品测试，也没有把方案写成已修复。

实施时优先修改或补充现有检查，不引入测试框架、测试调度器、提示词快照或源码形状检查。按下面三类已确认的行为复用检查，分类不是测试条数配额，已有有效覆盖不重复补：

| 必要检查 | 用产品话说保护什么 | 做法 |
|---|---|---|
| 已知位置直接读取、连续续读 | 正在看的那页能直接读，读取额度不被抬高，章节不串号，续读接得上，不会又变成搜索 | 扩展现有阅读位置与正文续读检查；复用已有 PDF/文稿检查材料 |
| 范围与字面匹配 | 指定材料或课程时只搜那里；原文有这段字就能找到，其他散落词不算命中 | 使用很小的临时材料，覆盖一个中文连续词、一个技术分块边界及范围差异；检查返回正文和位置 |
| 实际引用及重开 | 搜到但未引用的不出现；同名材料和不同位置能区分；笔记引用到达正确章节，重开后定位仍在 | 复用现有运行器、来源模型和编辑器检查，检查实际引用、保存后的章节位置及目标笔记收到的跳转；章节材料中包含会影响计数的普通 Markdown 语法，不另建格式组合测试集 |

同一行为不在宿主、运行器、界面各写一套。来源规则可以用固定模型输出隔离宿主错误，但固定输出通过不能代替真实模型和真实 App 的使用验证。

已有页识别状态、文件变化和游标连续性检查继续运行；章节目录续页复用相同的分页检查，确认能取到目录末尾，不锁死默认每页条数。缓存刷新在现有检查中使用一份未改正文的旧版 Markdown 缓存，确认新解析版本能带来新目录即可。不为这些修订增加格式、边界或版本组合矩阵，不顺手清理全部测试。改过接口导致原检查失效时，更新其行为断言，不删除实质保障。

执行节奏：所有相关代码完成后完整编译一次，运行相关的现有原生运行器检查和搜索/读取自检，通过后运行一次完整 CI。失败只修复并重跑受影响部分；不在每个小改动之后反复全量跑。

### 一次真实候选闭环

由 Agent 准备完整候选 App，先完成能自动完成的检查。需要操作桌面时使用画中画。最后给用户一次简短体验，不要求用户提交日志或截图，也不要求逐个模型、文件格式和调用组合排列测试。

| 用户怎么操作 | 应该看到什么 | 是否通过 | 问题备注 |
|---|---|---|---|
| 打开金融课件第 17 页，选中 Market Imperfections，问原问题 | 解释与当前课件相关，来源没有那几份无关论文，点击能回第 17 页或实际使用的其他页 | 待验收 | |
| 用一份目录需要续页的长笔记，找到旧截断范围以后的章节 → 读取该节 → 在回答中引用 → 点击引用 → 关闭并重开 App、恢复会话 → 再点同一引用 | 后部目录可以取得；读到的是目标节，读取额度没有被抬高；点击打开目标笔记并到达该节；恢复后的同一引用仍到达该节 | 待验收 | |
| 在上述资料问答中继续问本材料的其他位置，再问其他课程有没有相关内容 | 可以按需要继续查读和扩大范围，多个位置可区分，只引用实际使用的内容 | 待验收 | |

第二行是必须做完一次的功能连通验收；不是要求 Agent 平时每次都列目录、读取、引用。现有日志用于核对实际查询范围、返回片段和引用，模型可以自由选择合理的工具顺序；不把“恰好调用一次”或“必须先搜后读”写成通过条件。100 字同样不是验收门槛，检查的是工具是否遵守该次实际请求的额度。

## 十一、交付边界

当前交付物是这份可实施计划和官方依据。定案后的实现从最新主线建立一个隔离工作目录、一个短分支和一个草稿合并请求。修改共享宿主文件及来源显示公共部分前，按现有项目规则登记占用，避开正在进行的会话渲染工作。

实施任务应一次推进到全部范围完成、本地验证和 CI 有结果、完整候选闭环可验收。是否已合并、是否已构建候选、是否经过真实 App 验收分别汇报；计划完成不等于修复完成。正式发布仍按已有授权边界执行。

本次不安排向量库建设、历史数据迁移、全库文件导出、新权限确认、自动回答评审或长期检索评测平台。正常输入检查、文件访问边界、读取失败和防止笔记覆盖的数据保障继续使用现有实现。
