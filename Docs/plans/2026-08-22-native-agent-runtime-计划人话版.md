## 1. 为什么做这件事

魏碑 App 现在 113 MB，其中 72 MB 是一个叫 Pi 的"租客"。Pi 是别人写的通用 agent，
用 TypeScript 写的，Mac 跑不了这种语言，所以它必须随身带一个翻译器（Bun）——
那 72 MB 的大头就是这个翻译器，不是 Pi 的代码本身。

我们要做的事：**把 Pi 干的水管活用自己的代码（Swift）接过来，把 Pi 连人带翻译器请出去。**

三个动机：

- **体积**：App 预计瘦到 40–50 MB（go 门槛：未压缩 .app ≤ 55 MB）。
- **所有权**：以后 tutor 模式要给 agent 加任何能力，不用看别人的路线图，不用穿进程边界。
- **合规**：那个翻译器（Bun）内部静态链接了一些 LGPL 协议的组件，现在我们靠"披露声明"
  放行；Pi 走了，这个尾巴就彻底没了。

## 2. Agent 到底是什么

别被名字吓到。Agent 的核心就是一个**循环**，四步：

1. 把「你的问题 + 背景资料 + 一本工具清单」发给模型；
2. 模型看完，要么直接回答，要么说"我想先用一下某个工具"；
3. 如果它要用工具，**我们**替它执行（模型自己碰不到你的文件，只能"请求"），
   把结果塞回去，再问它一次；
4. 重复，直到模型给出最终回答。

真实例子。你问："利率这一节讲了什么？"

- 第一圈：模型想"我得先查"，请求调用 `课程搜索("利率")` → 我们执行，把搜到的段落给它；
- 第二圈：模型看了段落，请求 `读取正文(第三节)` → 我们执行，给它正文；
- 第三圈：模型写出带引用的回答。结束。

**这就是 agent 的全部魔法。** 剩下的全是水管活：怎么跟模型公司收发数据、怎么记聊天、
怎么登录、怎么中途停。Pi 现在干的就是这些水管活。

## 3. 现在谁干什么（你最该安心的一点）

逐行核实过代码，结论：

- **Pi 在干的**：跟模型公司收发数据（协议翻译）、跑上面那个循环、登录流程、
  存"内部版"聊天记录。
- **早就是魏碑自己 Swift 代码的**：课程数据、笔记、学习记忆、引用校验、
  "建议笔记但不动手写"、可视化渲染、界面、错误文案。

灵魂本来就是我们的一行不动；收回来的只是水管。所以这件事是"收编"，不是"重写魏碑"。

## 4. 要造的积木（一块一块讲）

### 4.1 翻译官（协议适配器）

各家模型公司说话格式不同：OpenAI 一种、Claude 一种、Gemini 一种。翻译官负责双向翻译。
设置页里 41 个服务商入口，其实只需要 **4 种翻译格式**——35 家小厂商（DeepSeek、
月之暗面、OpenRouter……）都说同一种"OpenAI 兼容方言"。所以不是 41 份活，是 4 份活。
以后哪家改接口就改哪族，缺新族就添一族，社区需要就社区 PR。

### 4.2 流式接收

回答是一个字一个字蹦出来的，因为模型边想边说，数据像快递包裹分片到达。经典坑：
一个汉字可能被切成两个包裹；包裹在路上卡死要会识别。这些坑别人（DSH）都踩过，
我们直接抄答案。

### 4.3 工具花名册（ToolRegistry）

每个工具登记三样东西：名字、参数格式、真正干活的 Swift 函数，外加一个**权限等级**
（读类自动放行 / 写类要你确认 / 破坏类要你确认两次）。模型只能调用名册上的工具。
课程隔离、Chat 隔离、目录越界这些**铁律**放在一个特殊护栏层：它只能否决、不能许可，
所以没有任何新功能能绕过它。而且工具的实现必须调用和界面按钮**同一套**能力方法，
不许写平行实现——这是"按钮和 agent 走同一套能力层"这个设计哲学的第一步落地。

以后 tutor 加能力 = 名册上登记一行，引擎不动。这就是"拓展性"的落点。

### 4.4 会话账本（Ledger）——最重要的新东西

现在的隐患：你看得见的聊天记录是魏碑存的，但**模型的"内心戏"**（它哪一轮调了什么
工具、工具返回了什么）存在 Pi 的私有文件里。Pi 一走，老对话就失忆。

所以我们自己记账：每一轮发生什么，追加进一个**只增不改**的日志文件。好处：

- **续聊**：关掉 App 重开，把账本放给模型看，它接着聊；
- **查 bug**：出问题回放账本，每一步都看得见；
- **tutor 分叉**：以后"从第三节课这里岔开讲"就是复制账本前缀，天然支持；
- **考试变简单**：后面讲。

你已经拍板：将来真删 Pi 的时候，老对话的可见历史全保留，"内心戏"不迁移
（续聊从账本重新开始），不为它做额外迁移工程。

### 4.5 循环本体 + 停止按钮

就是第 2 节那个循环写成代码。讲究在**取消**：你中途点停止，要同时做到——回答立刻停、
账本记"这轮被取消了"、**没开始执行的工具补记一条"没执行"**。最后这条保证账本永远
"有问必有答"，不然下次续聊模型会混乱。崩溃重开也同理：自动补齐结尾。

### 4.6 凭证文件（按你的决定，不用系统钥匙串）

延续现状的形态（Pi 现在也是存明文文件）：存在魏碑自己的数据目录里，一个只有本 App
能读的文件（系统权限 0600），加原子写入和损坏自动备份恢复。OAuth 登录拿到的令牌也存
同一个文件。好处是简单、不出钥匙串授权弹窗。

### 4.7 ChatGPT 订阅登录（OAuth）

流程：App 弹浏览器 → 你用 ChatGPT 账号登录 → 浏览器跳回 App → App 拿到令牌存好 →
快过期自动换新。OpenAI 官方 Codex 的这套流程是开源的，我们照着实现；你也判断开源
生态里用这条订阅路径的先例很多，被拦的可能性低。它仍然放在最前面验证——万一不通，
退路已经预裁决：API key 先行、订阅入口暂时隐藏，**不留 Pi 混合形态**。

### 4.8 技能包（Skills，正经的渐进披露）

现在的技能机制是独苗（只有一个画图技能，就是模型读一个 md 文件）。正经做法：

- 平时模型只看到每个技能的**名字 + 一句话简介**（50 个技能也不占地方）；
- 它判断需要时，才把**完整说明书**读进来照着做；
- 技能包格式预留"附带工具"的位置，但第一版加载只做指令注入，不乱动名册。

**技能现在就可用**（不只在 tutor）：以后给助手添一个"费曼复述"或"错题讲解"，
就是加一个文件。

### 4.9 两个新能力（文稿 + 子智能体）——引擎具备，普通模式先关掉

- **文稿**：模型产一份完整 HTML/Markdown（"把这章整理成一页讲义"），存成课程正式
  文档，沙箱里打开、可导出。
- **子智能体**：派一个子 agent 领自包含的任务（"给这三段出五道题"），跑完交结论。
  关键规矩：失败了也交回半成品；子级权限自动收窄；递归深度有硬上限。

这两个能力**引擎里都建好，但 Assistant（普通问答）模式默认关掉**，等 tutor 需要时再开。
技能则在 Assistant 模式立即可用。

## 5. 向 Cordis/DSH 学了什么

Cordis 是 DSH 底层的插件框架（本体只有 2693 行）。它的五个核心思想：服务注册表、
依赖声明、**可逆注册**（登记任何东西同时拿到一把"撤销钥匙"）、四种事件分发
（广播/接力/并行/瀑布，每个事件定死用哪种）、作用域层叠（全局能力 + 每个会话的
覆盖层——"普通模式关掉某些工具"就靠它）。

我们派 5 个子代理精读了源码，结论是**借纪律、不借运行时**——它的热插拔、配置组装
是为开放生态付的税，我们用不上。最值钱的一条：**"模型看到的东西必须能从账本重建"**——
这条规矩让大考变成"对比两边账本"，而不是对比文字（文字本来就有随机性）。
其余 15 条（瀑布关卡、铁律层、取消配平、技能披露、子智能体窄接口、流式词汇表、
错误归一、重试分层……）全列在计划 §3.1，每条注明出处。

## 6. 四棒：每一步干什么、为什么、怎么算完

顺序逻辑只有一条：**风险前置，先证明"不比旧的差"，再加"新的能力"。**
全程一个草稿合并请求，不滚动合并——四棒都叠在上面，最后你拍板一次性合并。

### 第一棒：打地基 + 拍现状照片

- **先拍照**：写任何新代码前，用现在的 Pi 把 12 个固定场景各跑一遍录下来——
  这是后面所有"有没有退化"的对照物。
- **再动手**：造事件总线、账本、循环、花名册、凭证文件，把 12 个工具搬回 Swift
  （其中 8 个原来是 TypeScript 写的，按契约等价重写，并顺手从"读快照"升级为
  读实时数据），写第一种翻译格式（OpenAI 兼容族，一族覆盖 35 个入口）。
- **怎么算完**：编译/测试/自测全绿；用 DeepSeek 的 API key 验证连通，并跑通
  "问答 → 搜索后回答 → 中途取消"三闭环（全程命令行，不用开 App）；默认旧引擎零变化。

### 第二棒：最硬的骨头（ChatGPT 订阅）+ 补齐翻译

- 实现 OAuth 登录 + OpenAI Responses 格式 + Claude/Gemini 两种格式。
- **真账号六步验证**：登录 → 发消息 → 触发工具 → 中途取消 → 令牌过期后自动刷新 →
  退出后凭证文件无残留。需要你本人在场登录一次（凭证不经过任何 AI）。
- Claude/Copilot/Radius 三家订阅：口径是 **"Pi 能跑通我们就跟"**（他开源的我们干嘛
  不跟）——逐个验证 Pi 现在能不能登录发消息，能就做技术验证和实现方案，不能就如实
  标注下架依据。
- 过不了就停在这一棒如实记录，绝不造假。

### 第三棒：长新能力 + 起草考卷

- 技能系统建好，画图技能迁移成第一个技能包，新写一个教学技能（比如"苏格拉底追问"）
  验证多技能共存；**Assistant 模式演示技能可用**。
- 文稿和子智能体引擎具备、普通模式默认关闭，用开关演示可用。
- **起草新评测集**：不少于 40 题，混合来源（模型生成题、网络习题、真实学习场景
  会产生的疑问、闲聊场景、要求深聊的场景），每题带评分要点，**不含 GenUI/可视化题**。
  **必须你审定后才能用**——旧的 56 题已经作废，谁用谁返工。新教学技能的内容也一起
  给你审定。

### 第四棒：大考 + 报告

前置条件：你已审定考卷。全程命令行驱动（不用开 App），新旧引擎同场考试，
产出对拍报告和 go/no-go 建议。

## 7. 大考怎么考

- **账本对拍**（主战场）：同一问题两边各跑一遍，对比两边账本里的事件序列
  （调了哪些工具、参数、来源、取消点）——比对比文字可靠一个量级。
- **12 场景行为差分**：普通问答、课程搜索、正文引用、记忆更新建议、课程档案建议、
  笔记/关联建议、可视化（只看结构合法）、图片输入、中途取消、401/429/断网/超时
  错误归类、旧会话续聊、多工具并行。引用完整、来源可跳转这些**功能性指标**在这里考，
  不进质量分。
- **质量双评**：新评测集两边各答一遍（主用 ChatGPT 订阅的 `gpt-5.6-luna`，low 推理档），
  **我（Kimi，独立 judge，不是干活的那个）**按三维评分标准逐题打分：**正确性 /
  语言流畅度 / 回答长度合理性**；你可以全量过目，差异大的题附原文对照。
- **性能实测**：冷启动、首字时间、整轮时延、峰值内存、常驻进程，各测 5 次取中位。
- **体积实测**：同一份代码出两个包（含 Pi / 不含 Pi），对比真实数字。

**六条 go 门槛**（缺一就不删 Pi）：12 场景零高危差异 / 评测集均分不掉且无单题大回退 /
性能不降 / 安装包实测 ≤55MB / ChatGPT 登录六步全通 / 默认旧引擎零变化。

## 8. 风险和最坏情况

- 登录被拦 → 预裁决退路：API key 先行、订阅入口隐藏，不留混合形态；
- 订阅移植后被厂商封 → 以 Pi 现状为基线，风险你已知情承担；
- 评测集编不好 → 你审定那关打回重编；
- **最坏情况**：这个实验分支不删任何东西，默认引擎还是 Pi。考不过 = 白得一份详尽
  审计报告，App 行为零变化。删 Pi 是报告出来后你单独拍板的另一个动作。

## 9. 执行纪律（执行 Agent 要遵守的规矩）

从最新主线拉 `codex/native-agent-runtime` 分支，当天推送并建**草稿**合并请求；
动共享核心文件要提前声明占用；每棒必跑编译、测试、自测、CI；**全程草稿、不滚动
合并**——报告通过、你拍板后才转正式合并。不绕过检查、不造假、不打标签、不发布。

## 10. 你要出面的只有三个时点

1. **第二棒**：本人在场登录一次 ChatGPT（凭证不经过任何 AI）；
2. **第三棒末**：审定新评测集和新教学技能的内容；
3. **第四棒后**：看对拍报告，拍板合并与删不删 Pi。

草稿合并请求第一天就在，进度随时可看。

## 一页纸总结

Pi 是个 72 MB 的租客，干的是水管活；灵魂（课程/笔记/记忆/引用）本来就是我们的。
我们照着一个成熟框架（DSH/Cordis）的解题思路，用九块积木把水管活收回来；
四棒按"先拍照留证 → 先啃硬骨头 → 长新能力 → 同场大考"推进；考过了你拍板删 Pi，
考不过什么都不变。
