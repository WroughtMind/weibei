## 0. 执行总则

### 0.1 顺序与停机线

按阶段 0 → 1 → 2a → 2b → 2c → 3 → 4 → 5 串行执行。下一阶段只在上一阶段的
完成条件全部满足后开始。

以下任一情况发生时立即停下，保留现场并报告，不自行绕过：

- 命令返回非零，或实际路径、分支、文件数量与本文快照不一致；
- 目标目录非空、备份无法读取、逐文件校验有差异；
- 工作区出现清单外改动、HEAD 未被 `origin/main` 包含、目录仍有进程占用；
- 共享核心文件已有其他活跃任务占用；
- 需要删除、覆盖或丢弃本文未精确列出的文件。

阶段 0 是手工数据迁移，不创建 PR。阶段 1 的工作目录清理也不创建 PR；所有代码或
仓库内容改动各自使用一个从最新 `origin/main` 创建的短分支、工作目录和 PR。
每个 PR 等用户合并后再进入下一阶段。

### 0.2 删除授权

本文列出的是候选项，不构成自动删除授权。执行任何 `git worktree remove`、`rm`、
`git restore`、本地或远端分支删除前，先向用户展示精确绝对路径、验证证据和将执行的
命令，取得本次明确确认。远端分支、迁移备份和 `/tmp` 源目录始终只列清单，不删除。

`./script/build_and_run.sh check` 会在执行 `swift test` 时因缺少 XCTest 模块失败，

import sys
