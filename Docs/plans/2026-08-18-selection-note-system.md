# 魏碑选区问记系统执行计划

## 目标

把现有“选区提问 + 一步摘录”升级为围绕同一原文持续生长的问记系统：

```text
原文选区
├── 问：问题、回答、后续追问
└── 记：摘录、用户札记、后续补充、AI 回答附件
```

最终产品规则：

1. 选区胶囊只显示“问 / 记”，问和记的面板都不重复显示原文。
2. 每份材料拥有一本懒创建的专属摘抄本。
3. 普通笔记只有在编辑器真实可见、打开的是普通笔记且已经就绪时才同步插入。
4. 摘抄本与普通笔记不是两份数据，而是同一条札记的不同投影。
5. 所有札记块统一为“原文 → 用户札记 → 可选 AI 回答”。
6. 摘抄本默认按原文顺序，也允许用户拖动、恢复原文顺序。
7. 问过保留细下划线，记过保留页边朱砂短记，两种状态可以叠加。
8. Ask 回答可以记入札记；从札记继续问时必须由用户输入问题。
9. 草稿、撤销、失败保留、删除语义、材料失效保护和外部 Markdown 可读性全部保留。

## 实现边界

- 不新增依赖、数据库、通用事务框架、功能开关或回退路径。
- 复用现有 SwiftUI 浮层、工作区持久化、课程携带状态和 Milkdown 编辑器。
- 旧选区提问数据只做一次转换，转换后删除旧运行模型。
- 每阶段最多补一个与真实风险直接对应的定向检查，不建立新测试体系。
- 六个阶段顺序实施；共享核心文件不并行修改。

## 阶段一：统一选区线程与原文锚点

- 以 `SelectionThread` 统一原文、提问消息、札记条目、回答附件、普通笔记投影和草稿。
- PDF 保存页码、文字偏移和标准化矩形；HTML、Markdown、纯文本保存稳定块或字符范围。
- 同一句话出现在不同位置时形成不同线程。
- 把现有 `SelectionAskThread` 一次性转入新结构，保留线程和消息身份。
- 移除 80 条上限，更新工作区和课程携带状态。

验收：旧提问可重开；同文不同位置不串线；空草稿不显示为问过或记过。

## 阶段二：问 / 记浮层与最小保存闭环

- 将现有浮层统一为胶囊、问、记三个模式。
- 删除“来源”、直接“摘录”和 Ask 顶部原文预览。
- 空输入为摘录，有输入为记下，已有线程为续记。
- 问、记草稿独立保存；支持 `Command-Return` 和两段式 Escape。
- 懒创建材料摘抄本；从第一版使用最终 Milkdown 札记节点。
- NOTE 未打开时只写摘抄本；普通笔记真实可见且就绪时双投影；当前摘抄本不重复。
- 保存不切布局、不打开 NOTE、不抢焦点。

## 阶段三：原文标记与专属摘抄本

- 统一 PDF、HTML、Markdown、纯文本的 `SelectionMark`。
- 问过使用细下划线，记过使用朱砂短记，两种点击热区分开。
- 阅读标题附近提供“摘抄 · N”。
- 摘抄本出现在 NOTE 列表，可打开、重命名、搜索、导出。
- 默认按原文位置排序；支持整体和线程内拖动、自定义顺序、新条目邻近插入及恢复原文顺序。

## 阶段四：普通笔记投影与编辑器能力

- 编辑器报告当前笔记身份、就绪状态、稳定光标和当前札记块。
- 在光标位置插入；文本选区时插到选区末尾；无有效光标时追加末尾。
- 光标位于同线程块内时追加补充，否则创建新投影。
- 支持拖动、编辑、聚焦、同步、移除、转为普通正文和三层删除语义。
- Markdown 保存稳定身份与可读正文；外部破坏身份标记时保留正文并解除当前投影同步。

## 阶段五：问记互转与完整视觉

- 原文朱砂短记进入续记，补充独立保存和展示。
- AI 回答支持“记入”，可与用户理解一起保存，也可单独保存或不附回答。
- 保存回答不可变快照；默认折叠，悬停预览，点击固定展开。
- 札记“继续问”携带有限相关上下文，但不自动生成或发送问题。
- 完成纸签浮层、原文优先札记块、分割线、来源悬停动作和主题适配。

## 阶段六：完整性、失效保护与旧路径清理

- 依次保存线程、摘抄本、普通笔记投影和原文标记。
- 摘抄本失败时不显示记过且保留草稿；普通笔记失败时保留摘抄本并允许重试。
- 撤销同步恢复条目、投影、标记和首次创建的空摘抄本。
- 材料变化时按锚点、原文与前后文重新定位；无法定位仍保留全部札记。
- 材料删除后札记转为孤立札记，不删除摘抄本或普通笔记投影。
- 删除旧 `appendSelectionToNote()`、旧浮层预览、旧线程运行模型、文字相同即合并和 80 条上限。
- 核对搜索、Markdown/PDF 导出和课程携带状态。

## 验证与交付

- 普通 Swift/UI 改动使用现有编译和核心自检。
- 工作区、课程和笔记数据改动使用现有数据安全检查。
- 编辑器改动使用现有类型检查、构建和编辑器自检。
- 全部阶段合入后，从干净 `main` 执行完整检查并构建唯一候选 App。
- Agent 只做一次最终初步冒烟；随后打开候选 App 交由用户完成普通使用验收。
- 未获得单独发布授权前，不创建标签、不上传正式安装包。
