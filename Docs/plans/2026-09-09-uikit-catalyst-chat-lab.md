## 1. 目标与授权边界

用户要求不以开发成本或现有技术栈作为排除 UIKit 的理由，以魏碑在 Mac 上的最佳实际体验为目标。独立验证 `Mac Catalyst + UIKit UICollectionView + MarkdownView/Litext` 是否能在保持必要功能和桌面交互的前提下提供更好的长会话体验。不预设它优于 AppKit、SwiftUI List 或 TextKit 2。

当前授权是建立这条实验分支和 PR，并写清后续实施要求。此提交不是已经启动的后台编码任务；实施者接手后沿用本分支和本 PR，不另开重复任务。未授权合并、正式发布、替换已安装 App、迁移用户资料，亦未决定把整个正式魏碑切换到 Catalyst。

“最佳体验”同时包含首次打开、持续滚动、回看、长单条回答、富内容、流式时延、窗口改宽、文字选择、中文输入和桌面操作。不得只追求热缓存下的平均 FPS，也不得以缺少图片、卡片或选择能力的精简版本宣布胜出。

## 3. 平台与应用形态

### 3.1 必须是真正运行在 Mac 上的 Catalyst 应用

建立单独的 Xcode 应用 target，启用 Mac Catalyst，以 UIKit 会话控制器为核心。使用正式公开 API 和 Mac idiom / Optimize Interface for Mac；记录实际 SDK、工具链、构建目标、运行系统与界面 idiom，确认没有把 iPad 缩放界面误当作 Mac 优化版本。[A1][A2]

不是 iOS 模拟器视频，不是 Apple Silicon 上直接运行 iPad App，也不是 AppKit 查看器换个标题。不要以普通 `swift build` AppKit 可执行文件作为 Catalyst 已构建的证据。依赖可以使用 SwiftPM，但应用宿主、资源、entitlements 和构建目的地必须按 Catalyst 正确配置。

整体建议：

```text
独立 Mac Catalyst App
└─ 桌面工作区外层（允许使用适合复用的 SwiftUI）
   ├─ 会话标题、菜单、输入区、可调整宽度的阅读区
   └─ UIKit 会话控制器
      └─ 单列 UICollectionView
         └─ 可复用消息 cell
            ├─ MarkdownView / Litext 的 UIKit 正文
            ├─ 公式、代码、表格、图片和交互内容
            └─ 来源与消息动作
```

SwiftUI 如用于外层，通过正式 `UIViewControllerRepresentable` 连接 UIKit 控制器。不要在现有 AppKit 进程中强塞 UIView；不使用私有桥接、窗口叠放、截图转发或隐藏辅助进程伪装同一个工作区。[A1][A5]

### 3.2 不先重写整个魏碑

当前主线 `Package.swift` 面向 macOS，`WeiBeiCore` 也链接 AppKit；它不是可以整体不改就给 Catalyst 使用的平台无关业务包。实现前逐项检查 API 可用性，不整包强行链接，不通过删除功能让构建变绿。

实验先在独立目标完成有代表性的会话能力；纯数据结构或必要算法可以从已合并主线按最小范围引用或适配，标明来源。正文、列表和平台行为由本分支自行实现，不为实验新增第二套生产存储。

阅读器、笔记编辑器、菜单、文件访问、多窗口和跨区域摘录的完整 Catalyst 适配属于后续采用评估。实验要展示关键交互的可行性和缺口，但不能把本 PR 当作已获授权的全应用迁移。若整套方案胜出，再据实际结果提出正式整合范围。

## 5. 会话实现约束

### 5.1 数据、排版与 cell 生命周期分开

消息 ID 与有效内容代次是展示身份，不能用不断变化的行索引作为长期身份。已解析文档、代码分词、附件准备和有效尺寸独立于 cell；cell 离屏不等于删除全部准备结果，也不意味着把全部历史 UIView 永久保活。

普通滚动不重新处理整份历史正文、不逐条计算全文哈希。数据变化时更新对应展示记录；输入框或工具栏变化不能引发无关历史正文重新解析。

异步结果核对消息和内容代次，解绑时解除旧显示回调。动作卡草稿、折叠、必要横向位置和选择状态不能随复用丢失或串到另一条消息。复用到新正文时先安装正确快照，仅在显示基线匹配时应用增量。

### 5.2 测量与显示共享有效结果

列表尺寸查询应尽量读已有结果；首次或过期测量放在受控准备路径，避免布局查询中重复 I/O、解析、建立所有附件和递归布局。内容、实际正文宽度、字体度量或附件尺寸真正变化时才失效。测量与显示尽量使用相同排版结果，不测一遍又用另一套视图再排一遍。

允许一次完整测量并复用，不能因使用 Core Text 全文测量就判失败；必须同时记录首次成本、改宽、内存和显示时延。禁止在滚动回调中反复完整测量未变化内容，也不许提前计算所有历史后只报热缓存成绩。

对于超长单条正文，按实际热点采用可复用的内部块或局部显示。内部优化不把一条回答拆成多条假消息，选择、复制与阅读锚点仍按完整消息组织。只绘制可见行与只排版可见段落不是同一件事，报告中明确实际采用的机制。

遵守库中 MainActor 和 Core Text 线程要求。不能把 `Task {}` 当成已移到后台，也不能把主线程视图或同一可变排版对象随意并发使用。先减少重复工作；若实测仍有昂贵首次布局，再有针对性分离纯计算与 UI 应用，不先自研通用排版引擎。

### 5.3 流式只更新对应消息

使用一个正在准备的任务和合并的待处理输入，或等效的简单机制；不每个 token 启动任务，不打开历史就对每条消息启动高优先级工作。

对已显示 cell 进行必要的内容更新，保留稳定消息身份。结构变化才增删 items；内容更新可使用合适的 reconfigure 或直接正文更新，不每批字 `reloadData()` 或重建全列表快照。重配不等于自动完成准确测高，必须接好实际尺寸变化。[A3][A4]

流式中未改变的块不重复设置属性文本、重新高亮或重播动画。收到更晚输入不应无限丢弃仍有效且更接近当前内容的已完成结果。停止和完成沿用同一正文，最终尾字完整，不清空重播。实际改变前文的语法和引用必须处理，不能假设所有输入永远只影响末段。

库的提交节流、分词和公式异步更新与屏幕刷新率分开记录。合理合并输入可以保留，但不能通过延迟到生成结束、降低实际显示内容或省略中间状态赢得指标。

### 5.4 只有一个外层滚动决策者

UICollectionView 所属控制器协调布局和阅读位置；正文、图片和卡片仅报告变化。禁止各自调整同一个外层 contentOffset。

区分跟随最新与阅读历史。用户向上阅读后，尾部增长不拉走用户；前插历史和图片增高保住当前阅读处。改宽时使用消息 ID、正文位置及相对视口偏移，不仅保存旧绝对 Y。复用后的正文位置重新映射，不能保存已失效的布局对象。

布局事务前后的锚点补偿考虑系统已做的移动，避免重复补偿。正常手势滚动不恢复旧锚点；旧异步任务不能覆盖更新的用户意图。不要以多段固定延时反复滚到底解决裁切或位置问题。

### 5.5 富内容和桌面交互是必要功能

- 代码、公式、表格准备结果按真实有效条件复用；长表和长代码不因一次进入视口重建所有重控件。保留缩进、空行、可读复制、公式基线和必要横向访问。
- 图片在明确的加载生命周期处理，尺寸查询不启动重复读取和解码；图片到达只更新所属消息。正常图片不能被替换为链接后算“性能通过”。
- 来源、wiki/callout、Mermaid/GenUI、消息动作须标明接入程度。专用网页组件可保留其实际能力，不用网页或截图兜底所有普通正文。
- 鼠标选择、跨段复制、右键菜单、键盘快捷键、中文输入法组合态、焦点、长附件横向滚动与外层纵向滚动都需要真实 Mac 验证。Mac idiom 下检查控件 API 可用性，不直接照搬手机交互。[A2]
- 不通过默认折叠长答案、截断正文、减少历史可访问量、关闭选择或简化表格来取得优势。

## 6. 分阶段实施：阶段是里程碑，不是以 Demo 结束

### A. Catalyst 应用与依赖资格

在 `Experiments/CatalystChatLab/` 建立独立 Xcode target、共享 scheme、资源与实验构建入口，先生成真正可在 Mac 运行的候选。核验 UIKit 路径、Mac idiom、正文库、中文及数学资源、选择与基础流式重放。

采用合成内容，不连接模型、Keychain 或生产资料库。可运行一个正文组件只证明候选资格，不能标记整个实验完成，不能冒充魏碑正文对照。

### B. 独立完整会话候选

沿用 A 的代码，在同一目标完成消息列表、输入区、历史前插、行高、阅读锚点、主要附件、来源和动作卡。提供接近魏碑的实际字号、配色、内容密度与可调整窗格宽度。用固定事件重放或用户明确提供的脱敏副本走真实消息到显示的路径，不只比较两个空白 Demo。

主要操作必须有实际行为，不能靠占位按钮宣布完成。尚未连接的真实模型、文件写入或工作区操作明确标注为实验限制，不改正式存储。会话候选就绪后可独立交付，不等待 #449/#451。

### C. Mac 上的端到端比较与采用评估

在同机、同样本、同正文宽度和字号下，与记录清楚的可运行主线候选比较；#449/#451 可用时再追加各自完整候选，不读取其施工分支作为输入。基线若不能运行或未取得用户数据，明确缺口，不编造。

交付真实候选和结果，说明完整 Catalyst 工作区需要的 API/功能适配、是否存在体验阻断。会话更流畅只说明该部分值得采用，不自动证明完整魏碑迁移成功；正式迁移和发布另行决定。

## 7. 验证与判断

只覆盖真正有辨别力的场景，不新增大量组合测试、基准服务或通用框架：

| 场景 | 必须观察 |
| --- | --- |
| 多消息长历史 | 首次打开、连续滑动、返回已读内容、历史前插；准备结果复用和重对象数量 |
| 少消息但单条特别长 | 长中文段落、代码、公式、表格和图片；首次进入成本、局部绘制与完整尾段 |
| 阅读中内容变化 | 生成、停止、完成、改宽、图片到达；是否掉帧、跳位、丢选区或重播 |
| 桌面操作 | 输入法、键盘和右键、跨段复制、卡片草稿、附件滚动；不拿手机手感替代 |

每次比较记录真实 App 来源 SHA、库锁版本、Release/Debug、系统、架构、刷新率、正文宽度、样本特征和冷热状态。记录可用 Instruments 中主线程热点、布局/分配及卡顿；真实帧数据才能称 FPS，不用组件毫秒或平均 CPU 换算帧率。[A4]

两边分别测首次准备和热回看，不让一边预热而另一边冷启动；同样内容不因为重复模板更容易命中缓存而误判。内存包括准备数据、cell、附件和缓存；不承诺无限历史恒定内存。

不同架构的整套结果不能全部归因于 UIKit 或 Litext。不能只比较有旧回弹缺陷的一边与已修复的一边，再把正确性修复当渲染速度提升。

保留与本次根因相匹配的少量自动行为验证；每项能用产品语言说明保护什么。不测试源码字词、实现类名或无依据阈值，不放宽断言掩盖失败。按照实际改动运行定向检查；当前纯文档提交只检查范围、内容、链接和差异，不运行 App 构建充数。

只有通过必要功能、性能和桌面体验验证，才可提出采用建议。结果接近或证据不足时如实报告，不为证明新框架正确而强行选它。

按 Xcode 的 Catalyst bundle 规则处理资源与签名，不照搬 SwiftPM AppKit 的手工装包假设。构建、链接、资源、签名、运行、性能是不同证据，失败保留原始原因。单架构成功与另一架构实机验收分开；实际最低运行系统从 SDK/target 产物验证，不能静默提高正式魏碑的最低系统要求。

不读取、覆盖或迁移生产资料，不访问 Keychain 凭据。脱敏样本由用户明确提供或使用自建数据；日志不含私聊正文、路径密钥和凭据。仅允许停止本实验自己的进程，不终止正式魏碑或其他实验。
