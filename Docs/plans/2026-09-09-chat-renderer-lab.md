# 魏碑会话正文实验：先验证，再决定替换

状态：实验计划，不是正式迁移决定。用户授权开实验分支；未授权合并、发布或替换已安装 App。

## 1. 要回答的问题

MarkdownView + Litext 的原生 macOS 正文，是否能在保留魏碑必要功能的前提下，比当前正文更顺畅？把“值得试用”与“已证明更好”分开。本实验不预设获胜者，不以 README、iPhone 视频或编译成功作性能结论。

主线取证提交：`429a86fc91a147f43a6f3be8d45d8db6d8e23673`。
实验分支：`codex/chat-renderer-lab`。
候选库：`Lakr233/MarkdownView@757b6fcc4b3095e84f4c0613f4b98147f49dcd09`；记录实际解析出的 Litext 和所有传递依赖版本。

原先“正文必须继续 TextKit 2”的约束在本实验中取消；也不反向规定必须替换成 Litext。原方案文档不作为已验证结论。

## 2. 不干扰并行工作

当前存在 #449 原生会话列表改造、#448 重排后手动滚动回弹修复、#450 构建编号改造。本实验第一阶段只新增 `Experiments/ChatRendererLab/`、本文和独立实验工作流，不修改生产 `Package.swift`、正文、WorkspaceStore、现有构建脚本或三个 PR。不要关闭、重置或批量迁入这些分支。

#448 的修复是独立的正确性因素：后续比较若两边没有相同的回弹修复，不得把差异归因给渲染器。#449 的列表未达到可比较状态时，先做候选资格验证；不能把当前旧列表与候选新列表的结果叫作正文 A/B。

进入生产入口对照之前，与 #449 明确同一份列表宿主和消息输入边界；只迁入经审查的必要接线，不整分支合并。仍使用本实验的一个分支、一个工作目录和一个 PR。

## 3. 已核实与未核实

已核实的源码事实：候选 Package.swift 声明 macOS 13 和 Swift tools 6.0；MarkdownTextView 有真实 AppKit 实现；支持 Litext 选择与附件接口。`trackedScrollView` 的公开注释指选择拖拽时自动滚动，不把它误当成已实现全文视口虚拟化的证明。

候选依赖 mgriebling/SwiftMath 和 swift-cmark；魏碑固定了 WroughtMind/SwiftMath fork 与 swift-markdown。必须验证包身份、版本约束、中文数学字体回退、资源装配，不得为解决依赖图偷偷删除魏碑的数学修复或升级整个生产依赖树。

上游明确不是完整 CommonMark 渲染器，图片、列表中复杂块、HTML 等存在设计取舍。wiki/source 链接、callout、图片、Mermaid、GenUI、中文加粗、代码复制都必须由实际样本确认；未知就是未知。

Innei/lody-ios 仅作为内容准备、测量复用和流式块身份的参考。截图视频尚未关联到一个经过确认的源代码提交，不能宣称此实验复现了视频中的 10000 条消息或 120 FPS。不能把 UIKit 源码直接当成 AppKit 实现。

## 4. 三个阶段，每个阶段只回答自己的问题

### A：macOS 候选资格验证（本分支先交付）

独立 SwiftPM 包和小型 AppKit 查看入口，直接调用锁定候选库，完全不读取魏碑用户资料，不连接模型，不改变正式 App。用合成内容验证依赖解析、Release 编译、AppKit 挂载、基础 Markdown、公式表格代码、连续追加后尾字、改宽、可读选择复制。

保留最少的行为检查和运行日志，不另建测试平台。候选单独编译不能证明它与魏碑同进程链接成功。先产出真实阻塞再做最小处理，不禁用失败检查、不把缺功能结果计为通过。

只有候选查看器不是性能 A/B，不创建一个简化的 TextKit 替身来冒充当前魏碑。若本阶段没有同场景基线，所有耗时只能叫候选局部处理数据。

### B：同容器、同内容的正文 A/B

锁定一份已通过基本功能的 macOS 消息列表宿主。A 使用真实魏碑正文；B 使用候选正文。外层列表、消息顺序、实际正文宽度、字体大小、主题、数据和生成事件序列相同。变动列表、正文、出字节奏的结果不得混成一个指标。

测试接线仅存在于实验入口；不增加生产偏好开关或永久多引擎框架。两种正文需互斥运行/展示，不能并排让双倍后台工作污染对照。切换时重建实验会话，分别记录冷启动与准备后回看；必要时交换运行顺序。

新库自带的 throttle、代码高亮后台任务和动效必须记录并协调，不能通过少显示内容、降低流式更新次数或延迟到末尾再显示来赢得指标。允许一次任务内合并尚未显示的输入，但两边接收完整原始内容且报告最终显示延迟。

重要生命周期：内容准备数据不依附可回收行；新视图先安装正确文档再接差量；消息 ID、版本与旧异步结果核对；动作卡草稿和选择状态不因复用丢失。几何由当前显示面管理，不能让浮窗和主窗口争同一个布局对象。

### C：真实会话入口与采用判定

候选在 B 中值得保留后，再接入实验版真实 AgentPaneView 路径，保留来源、动作、历史、轨道、三栏、沉浸、浮动问答现有行为。完整适配所需功能，不能在 A/B 前假定库能全覆盖，也不能为追求接入规模先改资料库或模型请求。

当前主线、修复后 TextKit 基线和候选的测量分开列出；从更换正文得到的改善与从列表改造得到的改善明确区分。最终只采用一条生产路径；删除实验开关，不让用户选引擎。

## 5. 功能与公平性

| 场景 | 通过条件 |
| --- | --- |
| 普通回答 | 中文英文、标题、列表、粗体、链接、引用正确，最后一句完整可达 |
| 长回答 | 一两条多屏正文也顺畅，不只测试大量短模板；改宽后不跳到别段 |
| 数学与表格代码 | 公式不截断且中文不丢；表格对齐、复制、横向滚动；代码缩进空行与复制保留 |
| 富扩展 | 来源定位、wiki/callout、图片、Mermaid/GenUI 按现有产品语义，不能默默变成链接或源码 |
| 流式 | 连续追加与语法后闭合正确；生成完成不清空重播；停止/重试与最终尾字正确 |
| 滚动复用 | 回看不反复解析未变化文本；选区、卡片草稿不串行；历史前插不跳位 |
| 用户意图 | 阅读历史时不强拉到底部；重排后继续手动滚动不被旧锚点撤销 |

缺失图片或 GenUI 的早期候选仍可用于定位某一性能现象，但必须标注能力缺口，不得胜出或替换生产。

## 6. 性能验证只做必要的三组

1. 多消息历史：首次进入与已准备内容往返分开；越过已加载页边界；不靠减少历史条数优化。
2. 少消息长正文：中文长段、公式、表格、代码有代表性即可；不能只复制同一文本让缓存过度命中。
3. 阅读中变化：流式尾部、历史前插、实际改宽；记录阅读位置、末尾可达及最终显示延迟。

同机、同系统/架构、同窗口/字号、Release、同一数据、顺序交错。工具使用本机可用的 Instruments/现有性能入口。记录主线程长任务、必要布局、创建/重复解析、内存是否持续增长。组件操作毫秒不等于屏幕 FPS；CPU 平均下降也不能遮掩尖峰。显示刷新率由运行机器记录，不要求不支持高刷的屏幕证明 120 FPS。

对照首先排除 #448 的回弹问题，区分“被拉回”与真正掉帧。所有通过/失败要有操作与结果，未运行写未运行。新增测试用一句产品语言说明保护什么，不锁代码词或凑数量；专项性能复现可以留一个窄入口，不建平台。

## 7. 决策规则

- 候选显著改善实际热点、必需功能完整、内存/改宽/尾字不退步：进入最终接入和单路径清理。
- 两者接近：不为换技术而替换，保留已通过实测的一方，说明理由。
- 候选有可局部解决的缺口：同分支修复并再比较，不把缺口隐藏在性能结果里。
- 候选有重大性能/功能/依赖阻断：记录证据，停止宣称适合；是否更换其他 fork 需明确新的版本与理由，不随意漂移实验对象。

## 8. 运行、隐私和交付

实验包与生产 App 分开，独立 Bundle ID，不读 Keychain、资料库或会话历史；用户主动提供脱敏样本后再增加。Agent 操作真实桌面遵守 AGENTS.md 的画中画规则；没有能力就不抢桌面，说明限制。CI 可验证编译和隐藏窗口组件，不冒充实机手感。

本任务只新增实验专用脚本。现有 `script/build_and_run.sh`、版本编号和正式打包不动。依赖锁文件与实际 SDK/架构一并保存为实验记录。阶段 A 的单架构通过不冒充全部系统/架构通过。

最终汇报区分：分支/PR 已建立、阶段 A 编译/行为检查、阶段 B 同容器对照、阶段 C 真入口、真实用户体验、采用决定。没有完成的阶段不打勾。计划和实验源码可以提交，主线不变、不发布。
