# 通用资料大列表性能与目录导入防线

## 目标

- 通用资料保留现有 507 条真实记录时，进入和滚动不再因一次创建全部行而卡顿。
- 文件夹导入不再递归登记 `node_modules` 中的依赖文件。
- 单次手动导入超过 500 个支持文件时零写入并明确提示，避免静默截断。
- 课程周期扫描忽略新的 `node_modules` 内容，同时保留已经登记在该目录内的旧课程记录。

## 最小实现

1. 资料选择器改用按需创建行的 `LazyVStack`，并在一次界面刷新中只计算一次行数据。
2. 目录递归统一按目录名（忽略大小写）跳过 `node_modules`；用户直接选择具体文件仍允许导入。
3. 手动导入对全部所选路径统一去重计数：500 个允许，发现第 501 个立即返回超限；调用方在任何资料写入前停止并提示。
4. 课程周期扫描记录被忽略的目录前缀，对已有登记记录跳过“文件失效”处理。

## 不做

- 不自动删除或修改现有通用资料、笔记、关联、学习位置和会话。
- 不新增分页、缓存、第三方依赖或新的列表框架。
- 不排除 `build`、`dist`、`vendor`、`Pods` 等可能承载真实课程内容的目录。
- 不修改正式安装版，不在本任务内发布版本。

## 验证

- 自动检查覆盖大列表只创建可见行、`node_modules` 递归跳过、具体文件直选、500/501 边界、跨多个文件夹的总上限，以及旧课程记录保留。
- 在隔离工作区复制 507 条现有数据做候选 App 冒烟；验证进入、连续滚动、首中尾点击、右键菜单和返回。
- 通过项目编译、核心自检、安全专项测试、增长检查和 GitHub CI。
