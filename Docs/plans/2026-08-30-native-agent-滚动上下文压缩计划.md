# Native Agent 滚动上下文压缩计划

日期：2026-08-30
状态：已实施，待组合候选应用验收
范围：Assistant 与未来 Tutor 共用的模型上下文滚动压缩

> 本计划从 Pi 借用五个动作：按真实容量触发、选择安全切点、生成滚动摘要、让模型看到“摘要＋近期原文”、下一次用“旧摘要＋新退出内容”更新摘要。魏碑只统一触发压缩所需的最小公共用量，不建设服务商用量报表、模型能力库或本地分词系统。

## 1. 产品边界

滚动压缩只改变下一次发给模型的上下文，不改变用户数据：

1. 用户可见聊天不删除、不折叠、不替换；
2. JSONL 运行账本继续追加，原始事件始终保留；
3. 旧消息只退出模型上下文，不退出界面和本地记录；
4. Assistant 直接使用，未来 Tutor 接入同一主循环后自然复用；
5. 不增加手动压缩按钮、设置、后台任务或摘要展示。

这项机制解决的是长会话超过模型上下文的问题，不顺带承担学习者画像、跨会话记忆、本地内存或启动优化。

## 2. Pi 对照与魏碑采用方式

实施以 Pi 当前源码为行为参照：

- [`compaction.ts`](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/src/core/compaction/compaction.ts)：用最后一条有效 assistant 用量作为容量主体，只粗估该用量之后尚未计量的尾部，选择安全切点并生成摘要；
- [`agent-session.ts`](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/src/core/agent-session.ts)：在阈值前主动压缩；服务商明确报告上下文溢出时，压缩后只恢复一次原调用。

魏碑对应完成五个动作：

1. 从最后一条有效 assistant 用量判断已占容量；
2. 只在完整 `turnEnd` 或已完成 `stepEnd` 后切分；
3. 用当前模型、无工具、无联网生成一个延续摘要；
4. 后续请求只包含系统提示、最新摘要和近期原文；
5. 再压缩时，把旧摘要与本次新退出窗口的原文一起更新为唯一新摘要。

魏碑不照搬 Pi 的编程任务摘要格式，也不照搬任何整份请求的字符估算作为权威容量。

## 3. 模型可见上下文必须一致

### 3.1 本轮定位进入账本

当前材料、页码等本轮定位信息，在用户模型消息写入账本时一并持久化。删除真正发送前临时追加定位的路径，使账本事件本身足以重建模型当时看到的用户消息。

### 3.2 每个主循环只派生一次投影

每次模型步骤从账本派生一次模型可见投影，并据此构建本步请求。正常发送、压缩历史截取和候选请求重建都复用这份投影，不各自重建消息。

投影覆盖：

- 系统提示；
- 用户与 assistant 消息；
- 工具定义、工具调用参数和工具结果；
- 图片；
- 已持久化的材料与页码定位；
- 最新滚动摘要。

## 4. 容量判断

### 4.1 最小公共真实用量

四种协议只解析压缩判断所需的公共字段：

- OpenAI Chat Completions：仍解析服务端主动返回的 `prompt_tokens`、`completion_tokens`、`total_tokens` 和缓存读取；只有已验证支持且确有生产 `contextWindow` 的 Amazon Bedrock 精确 `amazon.nova-lite-v1:0` 主动发送 `stream_options.include_usage`，其余兼容或自定义端点默认不发，避免回归；
- OpenAI Responses：完成事件内的 `input_tokens`、`output_tokens`、`total_tokens`、缓存读取；
- Anthropic Messages：`message_start` 与 `message_delta` 内的输入、输出、缓存读取、缓存写入；
- Gemini：`usageMetadata` 内的输入、输出、总量、缓存读取。

统一计算规则只有一条：

```text
若 totalTokens > 0：容量主体 = totalTokens
否则：容量主体 = inputTokens + outputTokens + cacheReadTokens + cacheWriteTokens
```

OpenAI 的缓存 token 是输入 token 的子集，Gemini 的缓存内容 token 也包含在提示 token 中；两者进入公共结构时先把 `inputTokens` 归一为“总输入减缓存读取”，避免 `totalTokens` 缺失时重复相加。Anthropic 的输入、缓存读取和缓存写入本来就是分列字段，保持分列后相加。

用量必须落到完成的 assistant 模型记录上。只有工具调用、没有正文的 assistant 步骤也必须保留用量；投影仍把该 assistant 的工具调用与后续工具结果作为完整结构处理。

只有 `stop`、`toolCalls` 或 `length` 完成原因的用量有效。`error`、`aborted` 或没有完成标记的流即使返回过 usage，也只保留原始流事件与部分正文，不得成为后续容量基准。

选择最近一条非零有效 assistant 用量作为容量主体。旧检查点之前的用量不参与新投影，避免用压缩前的陈旧大上下文重复触发。

### 4.2 未计量短尾与安全切点

真实用量之后新增的短文本尾部，以及选择安全切点时保留的文本，只采用与 Pi 同类的单一粗估：

```text
粗估 token = 文本字符数 / 4，结果向上取整
```

该粗估不区分中文、英文或 ASCII，不设语言倍率；只统计短尾中的消息文本、工具调用标识/名称/参数和工具结果文本，不估整份请求。

图片既不使用固定 token 常数，也不把 base64 字节数冒充 token。未计量图片不做主动预判，等下一条服务商真实用量校正；如果服务商先明确报告上下文溢出，则走一次溢出恢复。

没有有效真实用量时不主动压缩，不以字符粗估整份请求替代真实用量。

### 4.3 固定触发规则

```text
回答预留量 = min(16_384, 上下文上限 / 4)
输入警戒线 = 上下文上限 - 回答预留量

当且仅当：最近真实用量 + 其后未计量短尾粗估 > 输入警戒线
才主动压缩。
```

摘要最大输出为 8,192 token；近期原文目标最多约 20,000 token。上下文较小时，近期窗口缩小为警戒线扣除摘要最大输出后的可用量。这些均为内部固定机制，不提供设置。

## 5. 已核实模型上限

容量必须绑定“已核实供应商＋精确模型 ID”，不能只按模型字符串全局匹配。只为以下组合返回上限：

| 供应商 | 精确模型 ID | 上下文上限 | 官方依据 |
|---|---|---:|---|
| OpenAI 官方 API | `gpt-4.1` | 1,047,576 | [OpenAI GPT-4.1 模型页](https://platform.openai.com/docs/models/gpt-4.1) |
| Google 官方 API、Google Vertex | `gemini-2.5-flash` | 1,048,576 | [Google Gemini 2.5 Flash 模型页](https://ai.google.dev/gemini-api/docs/models/gemini-2.5-flash) |
| MiniMax 国际区、中国区 | `MiniMax-M2.5` | 204,800 | [MiniMax API 概览](https://platform.minimax.io/docs/api-reference/api-overview) |
| Amazon Bedrock | `amazon.nova-lite-v1:0` | 300,000 | [Amazon Nova 模型规格](https://docs.aws.amazon.com/nova/latest/userguide/what-is-nova.html) |

以下内置默认值不做主动映射，但仍可在服务商明确溢出时恢复：

- `gpt-5.6-luna`：当前没有可随源码稳定核验该精确订阅后端模型容量的权威元数据；
- `grok-4`：当前官方目录不能确认这个精确旧名称的稳定上限；
- `mistral-large-latest`：浮动别名不能证明当前一定对应某个固定上限；
- `deepseek-chat`：官方已在 2026-07-24 停用该旧别名，本计划不顺带迁移模型名；
- `claude-sonnet-4-5`、`claude-sonnet-4`、`anthropic/claude-sonnet-4`：旧别名或网关路由的实际默认上下文会受当前供应商与能力头影响，不能只凭模型家族猜测。

GitHub Copilot 即使使用同名 `gpt-4.1`，没有 Copilot 自身权威容量依据也返回 `nil`。自定义端点、其他网关和用户手输模型即使名称与表内模型相同也一律返回 `nil`，不猜测，不新增模型能力数据库。生产界面选定供应商与模型后计算一次可选上限并传入共用运行时，子 Tutor 复用同一值；循环内部不再只按字符串推断。

## 6. 账本检查点与投影

删除未使用的 `surface/replace` 事件与消息下标替换字段，不保留兼容分支。

唯一检查点为 `contextCompaction`。除事件公共封装外，只保存：

- `summary`：最新滚动摘要；
- `firstKeptSeq`：仍作为近期原文进入模型上下文的第一条原始事件序号。

投影只读取最新检查点：先注入一条内部 `user` 摘要消息，再派生 `firstKeptSeq` 及之后的原始事件。更早检查点和更早原始事件不再进入模型上下文，但仍完整留在账本中。摘要不进入用户可见聊天。

## 7. 安全切点

程序只判断容量与结构，不自行提取语义：

1. 优先在完整 `turnEnd` 后切分；
2. 单轮工具循环过长时，允许在已完成 `stepEnd` 后切分；
3. 工具调用与对应结果永不拆开；
4. 未完成步骤不进入摘要窗口；
5. `firstKeptSeq` 必须落在上述原始事件边界；
6. 单条消息本身超限时不建设分块系统，保留服务商错误。

## 8. 摘要生成与主循环接线

### 8.1 摘要合同

摘要复用当前模型与适配器，不提供工具、不联网、使用低推理档、最大输出 8,192 token，输出普通文本或 Markdown。

提示词只在内容真实存在时保留：当前问题、用户理解与困惑、最新纠正、已经解释或尝试的内容及效果、未结束问题、资料位置/名称/数字/来源。不得虚构目标、进度、结论或下一步。

第一次输入较早历史；再次压缩输入“旧摘要＋新退出历史”。始终只有一个最新摘要。

### 8.2 主动压缩顺序

1. 从账本派生一次投影并构建本步请求；
2. 获取精确模型上限；未知上限跳过主动判断；
3. 用最近有效 assistant 真实用量加其后短尾粗估检查警戒线；
4. 超线后从同一投影选择安全切点；
5. 生成候选摘要并重建“系统提示＋摘要＋近期原文”；
6. 摘要成功后才追加检查点；失败不写检查点；
7. 追加正常 `stepStart`，调用模型。

### 8.3 明确上下文溢出只恢复一次

如果服务商在本步尚未产出任何流式块时明确返回上下文溢出：

1. 立即从本步已经派生的同一投影选择安全切点；
2. 生成候选摘要；
3. 摘要成功后追加检查点；
4. 用压缩后的上下文重试原请求一次；
5. 第二次仍溢出则直接保留错误，不再压缩或重试。

已经产出任意流式块时不做恢复，避免重复正文或工具调用。即使本步刚完成过主动压缩，首次明确溢出仍会从最新检查点重新派生投影、选择更深的新切点并恢复一次；不得重复同一候选。这里不增加状态机、指数退避、多阶段降档或后台队列。

## 9. 实施落点与顺序

### 9.1 已完成的根因改动

1. 本轮材料与页码定位改为随用户消息落账本；
2. 删除发送前临时定位与旧 `surface/replace` 结构；
3. 账本投影支持最新摘要、近期原文、安全切点和 assistant 用量锚点；
4. 四协议接入最小真实用量；
5. 精确模型上限进入现有路由；
6. 主循环接入主动压缩和一次明确溢出恢复；
7. 摘要失败不落检查点，原始账本不删除。

### 9.2 组合候选验收

在独立候选应用中使用正常模型进行真实中文长会话，确认压缩后仍掌握：

- 用户最近纠正；
- 当前材料位置；
- 已经讲过或尝试过的内容；
- 尚未回答的问题；
- 完整工具调用结果。

同时确认用户聊天没有缺失或被摘要替换，第二次明确溢出不会进入循环重试。

## 10. 自动检查

只保留两项新增检查。

### 10.1 账本投影检查

覆盖一次和二次检查点，确认：

- 原始事件始终保留；
- 模型只看到最新摘要和 `firstKeptSeq` 后的尾部；
- 更早检查点不进入模型上下文；
- 工具型无正文 assistant 仍保留真实用量；
- 工具调用与结果没有被拆开。

### 10.2 完整循环检查

测试专用适配器在仅调试编译边界内提供小上下文上限，并在同一检查中覆盖：

- 最近有效 assistant 真实用量触发主动压缩；
- 摘要、重建、落检查点、继续回答；
- 服务商明确溢出后压缩并只重试一次；
- 自定义端点手输同名模型仍没有生产上限；
- 主动检查点早于 `stepStart`，溢出恢复检查点位于原步骤内且重试不另写 `stepStart`。

不新增四服务商测试矩阵、模型打分、语义基准、随机长文本、Tutor 专项或性能基准。

## 11. 完成标准

1. 正常发送、摘要截取与候选重建来自同一次账本投影；
2. 容量主体来自最近有效 assistant 真实用量；无用量时不估整份请求；
3. tool-only assistant 的用量不丢，调用与结果不拆；
4. 检查点只保存 `summary` 与 `firstKeptSeq`；
5. 完整账本和用户聊天不丢失；
6. 已知模型上限都有精确官方依据，未知与浮动别名为 `nil`；
7. 明确上下文溢出最多压缩并重试一次；
8. 两项新增检查、Native Agent 现有检查和 Swift 构建通过；
9. 独立组合候选应用完成真实中文长会话验收；
10. 产品中没有压缩按钮、设置、摘要展示或生产调试开关。

## 12. 明确不做

- 不用字符、Unicode scalar、UTF-8 字节或本地 tokenizer 权威估算整份最终请求；
- 不设计中文/英文/ASCII 权重表；
- 不给图片设置固定 token 常数，不以 base64 大小冒充 token；
- 不引入词表、BPE/tokenizer 依赖或运行时下载；
- 不引入状态机、指数退避、多阶段降档或多批摘要；
- 不做运行时回退、双压缩路径或生产功能开关；
- 不做独立 Tutor 压缩、多摘要、向量记忆、用户目标表单；
- 不做服务商原生压缩、用量报表或模型能力数据库；
- 不做后台/手动压缩、本地账本索引或单条超大消息分块；
- 不混入其他本地内存、运行效率或启动速度优化。
