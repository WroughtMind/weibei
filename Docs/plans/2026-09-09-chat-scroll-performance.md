## 当前实现

主会话已接入单列原生复用列表。工作区、输入框和原有动作控件保留；正文直接由每条消息的 TextKit 2 文本视图呈现，不经过 SwiftUI 测高。

- 展示状态归当前会话显示面所有，保留已解析文档、附件结果、选择、折叠状态和未提交动作草稿。复用时保留文本视图自己的原生文字系统，用完整文本编辑安装已准备文档；随后只同步发生变化的文字范围或属性，避免内容管理器替换遗留上一条消息的高度。准备结果不随行视图回收，流式差量始终作用于匹配的展示版本。
- 行高回调只读取记录。正文和附件变化合并为定向行高事务；宽度、字号、正文版本分别使相应记录失效。文字视口取真实可见区域，不进行普通滚动或改宽时的全文排版。
- 列表统一管理跟随最新、历史前插、轮次导航和消息内文字/附件锚点。共享浮动正文也区分改宽定位与用户主动滚动，继续处理估计坐标修正，用户开始滚动即结束定位。
- 代码高亮和表格解析在后台准备并复用；公式复用原生矢量排版结果；长表格仅建立当前可见单元格。附件尺寸查询只读结果，视图由系统在需要时建立。图片沿用原有安全加载边界，Mermaid/交互内容保留专用运行时。
- 附件尺寸变更通过文字存储的属性编辑通知更新布局和文档高度，不能只使某个文字片段失效。附件的横向位置随消息保留，避免视图回收后宽表跳回左侧。

退役主会话的离屏空白占位、逐条几何测高、全局可淘汰行高缓存和逐轮阅读探针；对应旧文件及其已失去消费者的测试删除。共享 Markdown 预览、浮动问答和专用图表入口保留。

PR #448 的重叠是共享正文阅读定位。本任务采用显式用户滚动状态结束改宽定位，并通过“多次改宽后仍能主动滚动、不回弹”的行为检查，不批量引入旧分支。

三、必须落实的技术约束

【内容准备与行复用】

WorkspaceStore 仍是原始消息与业务动作来源。当前会话只增加必要的派生展示数据：消息 ID、展示版本、已准备文档、附件结果和必要交互状态。几何与阅读锚点属于当前显示面，不能由主窗口和浮窗共享同一份可变布局状态。

滚动、hover、父容器更新不重新哈希或解析整份历史。只在内容变化边界处理对应消息；结构变化才更新行索引。复用现有后台解析、待处理输入合并和差量机制，不每个 token 建任务，不同时为全部历史启动高优先级准备。

离屏可回收重视图，但未变化的准备结果不随之删除。重新绑定新文本视图时，直接安装已准备文档；只有旧显示版本匹配时才应用相对于它的差量，不能把旧差量套到新 NSTextStorage。选择、附件身份、折叠状态和动作卡未提交草稿不能因复用丢失。

【行高和 TextKit】

本方案采用显式行高记录：usesAutomaticRowHeights = false；tableView(_:heightOfRow:) 只读已准备的完整行高或合理初始估计，不做 fittingSize、解析、附件创建、I/O，也不调用可能引起递归 tile 的表格几何方法。

完整行高包含正文、来源/动作控件、内边距和内部间距，但不重复计算表格 intercell spacing。记录随消息展示版本、实际正文宽度、字号和真正影响排版的条件失效；不能依赖粗宽度桶或可淘汰的全局缓存维持当前列表几何。

正文获得实际宽度，并以会话视口和自身可见区域的交集进行局部排版。不要因为消息行高二十屏，就把二十屏当作文本视口。优先使用系统公开机制，不能破坏 NSTextView 自己的 TextKit 管理或偷偷回退到 TextKit 1。

TextKit 修正估计高度是正常行为。让正文/附件把必要高度变化提交给同一个列表控制器，在必要的主线程布局事务中合并，并用 noteHeightOfRows(withIndexesChanged:) 定向通知。不要在 layout 或高度查询栈里递归更新；表格拥有行 frame，行只布局子视图。

禁止普通滚动和每次改宽时全文 ensureLayout、反复探文档末尾、冻结高度，或多层 asyncAfter/debounce 追赶布局。实际改宽时可见正文及时换行，屏外旧记录正确失效并在需要时更新；不每帧创建/测量全部历史。普通流式和估高修正不驱动整列弹动动画。

【滚动、历史和流式】

只有会话控制器可以决定外层纵向滚动。正文报告尺寸和位置，不各自 scroll 外层容器。

区分跟随最新与阅读历史。会改变可见坐标的布局事务前，捕获“消息 ID + 消息内文字/附件位置 + 视口偏移”；更新后先考虑系统已做的补偿，只修正剩余偏差。跨文本对象回收不能盲存旧 NSTextLocation。普通手势滚动不强行恢复旧锚点，程序滚动不误判为用户意图。

历史前插不跳位，读历史时流式不强拉底部，改宽保住同一处文字，跳到最新能看到最后一行。保留现有加载历史的产品行为，不以降低消息数量或截断回答获得性能。

每批流式只更新对应消息和必要行高，不 reloadData 整表，不重建生成→完成时的正文。首轮等待、停止、重试、错误、来源、动作、选择复制和最终尾字都保留。隐藏面可以不做无用布局，但原始内容照常接收，旧异步结果不能串到新会话。

阅读轨道共用一个滚动入口；轮次和摘要在消息变化时准备，不让每个轮次独立监听或滚动时正则处理全文。

【附件】

同一次交付修正公式、代码、表格、图片、Mermaid/交互内容的真实热点，不留作“下一轮优化”。

将昂贵准备、尺寸和 NSView 表现分离。问尺寸不能顺便启动加载或创建完整富内容。复用代码高亮、公式自然尺寸、表格准备结果和有效资源；内容改变时才更新必要部分。

普通行内公式不要建立不需要的块级操作容器；长代码和长表格验证内部真正可见范围，不能每次回看重建全部单元格。长表格可在附件内部局部按需显示，但不新增通用会话虚拟化框架。纵向滚动融入主会话，宽表/代码保留横向滚动、选择与可读复制。

图片沿用当前资源与路径安全边界，加载完只更新对应有效附件和消息。保留专用 Mermaid/GenUI 运行时，但不把 WebView 当普通正文失败后的兜底。不能截图、降级成源码、默认折叠或删掉富内容冒充完成。

## 同机 Release 性能证据

Apple M4，16 GiB，macOS 27.0；720 × 740 隐藏窗口。旧版使用 `429a86f` 源码归档，应用代码未修改，只接入完全相同的检查函数；它不是第二个开发分支。新旧回放函数及其后续辅助代码逐字一致；从 `func testMainConversationScrollWorkload` 开始至文件末尾的 SHA-256 为 `b8688cc08a43d8b95cccea6062530158ab5c7ff231800a50b19293284aada5b8`。

每个场景先等待 1 秒，让入口开始呈现；随后两轮各 80 次上下滚动。每次记录主线程滚动、布局、短暂处理事件及完整隐藏窗口绘制的耗时，使用仓库 `script/perf_p95.sh`，不丢弃样本。第一轮与回看分别统计。三种合成内容是 36 条历史消息、单条 160 段长回答，以及 120 行代码与 80 行含公式表格。测量按旧版、新版顺序执行，期间没有并行编译或采样；用户的正常桌面没有被暂停。

## 1812 快速滚动空白与抖动复查

用户在来源 `82bfcd02` 的 1812 候选上报告：卡顿减轻，但快速滚动后会话变成空白，停止滚动仍不恢复，并伴随抽动。1812 因此不能视为体验验收通过，前面的性能数字不能证明内容显示正确。

复查使用当前会话的段落和长度分布生成本地脱敏样本，未打印或上传私人正文；入库检查使用完全合成的 120 条交替长短消息，其中一条有 467 段。实际滚轮事件经主会话桥接、列表控制器和原生文本视图进入隐藏窗口，包含绘制和停止后的观察。

确认的问题及修正：

| 问题 | 实际证据 | 最终处理 |
| --- | --- | --- |
| 复用后沿用另一条消息的高度 | 16 字短消息首行高 18 点，原生总高度仍为 6722.6 点；视口位于尾部时没有任何文字行，停止后也不恢复。替换前使旧全文布局失效仍复现。 | 保留每个文本视图的原生 TextKit 2 连接，使用正常文本编辑安装已准备正文；后续增量和属性编辑通过准备存储的回调同步。 |
| 加载历史使已测短消息重新变高 | 31 条短消息的真实列表中，正文实际高 17 点，行中正文却保持 287.2 点。 | 宽度失效以实际已测宽度为准；正文每次合并布局回报当前高度，由行记录去重，避免正文缓存挡住必要修正。 |
| 快速滚动后行高事务漏掉当前位置 | 滚轮清除了旧阅读锚点，但已经排队的高度仍执行；停止后同一文字移动 378 点。该次没有越界回弹。 | 在应用排队高度前，沿用有效锚点或捕获用户最新位置，再补偿剩余偏差；保留连续改宽的文字锚点。 |

新检查保护两个用户行为：快速往返滚动后正文有实际可见文字、停下后同一处文字/附件不继续跳位；加载较早历史后已显示的短消息不膨胀为空白。停止检查先等待系统边缘回弹结束，避免将正常弹性滚动当成缺陷。现有富内容、选区/草稿、历史前插、生成与改宽检查继续保留。

最终 Release 对照、本地完整检查、CI 和候选信息随本轮实测更新；真实用户验收保持待复测，不以自动回放代替。
