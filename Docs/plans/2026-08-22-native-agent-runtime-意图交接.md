# 魏碑自研 Agent · 意图交接（Handoff）

**日期**：2026-08-22（grilling 两轮裁决后更新）
**执行依据**：`Docs/plans/2026-08-22-native-agent-runtime-实验计划.md`（v3.2.1：基准核查、机制取舍、四棒执行、对拍方案）
**本文档定位**：记录想法与意图（为什么、要什么、不要什么），供执行者与未来协作者对齐方向。执行细节以计划为准；两者冲突时以计划为准，意图冲突时以本文档为准。

## 一、出发点

魏碑安装包 113 MB，其中约 72 MB 是内嵌的 Pi + Bun 运行时。要瘦身，但**不能损失任何现在可用的能力**。已核实：Pi 干的是水管活（循环、协议翻译、登录、会话存储），而课程、记忆、引用校验、建议确认、渲染这些产品灵魂早已是魏碑自己的 Swift 代码。收归引擎是顺势而为，不是冒险重写。

## 二、愿景（方向感的来源，长期有效）

**北极星是 agent 设计哲学的一环，不是 tutor 模式的专属指标。**（2026-08-22 用户明确纠正）

1. **终极目标**：agent 像用户一样，对 App 拥有完全操控权。
2. **实现路径**：App 的每个功能收敛为可调用的 Swift 能力；**用户点按钮和 agent 调工具走同一套能力层**，工具只是薄封装（名称 + 参数格式 + 权限等级）。
3. **操控权由权限层调节，不动架构**：读类自动放行 / 写类用户确认 / 破坏类二次确认 / 硬护栏（课程、Chat、记忆隔离、目录越界）永远不可绕过。
4. **终态形态**：一份能力定义，派生三处——UI 命令、模型工具、测试入口（不追求第一天做到）。
5. **颗粒度原则**：暴露意图级能力（"跳转到第三章"），不做 UI 级模拟点击。

## 三、明确不要的

- 不做阉割版 agent：能力面必须可生长，tutor 模式要长在它上面。
- 不做"Pi 按需下载"之类的过渡形态。
- 不做子智能体精细预算体系（机制进引擎，深度常量防失控即可）。
- 重写不背负"创新"期待：它的价值是**所有权**（体积、合规、可控、能力自主权）；创新预算留给以后的 tutor 模式。
- 不长期养两套引擎：Pi 只是迁移期的参照物和对拍基线。
- **不滚动合并**：四棒全程草稿 MR，报告通过后用户最终拍板一次性合并。（2026-08-22 裁决 Q10）
- **评测不考 GenUI/可视化生成内容**。（2026-08-22 裁决 Q5）
- **质量评测不经真实 App**：走 CLI 通道，方便为先。（2026-08-22 裁决 Q5）

## 四、能力面（一等公民，随引擎一起交付）

- **12 个现有工具全部回迁 Swift**：4 个 host 工具（课程目录/搜索/正文/开网页）本就在 Swift；8 个 TS 工具（记忆读取、记忆更新、课程档案、笔记建议、关联建议、图片素材、可视化、read-skill）按契约等价重写，并从"读提问前快照"升级为读 live 数据；工具实现复用与 UI 相同的 store 能力方法，不写平行实现。
- **技能系统 v2（渐进披露）**：目录摘要注入上下文、正文按需加载；技能包 = SKILL.md + manifest + 可选附带工具 + 可选 JSC hook（hook 仅限内置签名技能，第三方技能永远纯声明式）。**技能在 Assistant 模式立即可用**。（2026-08-22 裁决 Q7）
- **文稿 artifact**：`create_document` 产出 HTML/Markdown/SVG，落盘为工作区一等文稿，沙箱 webview 渲染、可导出。**引擎具备、Assistant 模式默认关闭**。（2026-08-22 裁决 Q7）
- **子智能体**：`delegate` 工具递归调用循环；独立账本 + 工具子集 + 深度常量；窄接口、能力声明前置校验、失败走值、部分输出必回传父级。**引擎具备、Assistant 模式默认关闭**。（2026-08-22 裁决 Q7）

## 五、架构参照

参照 DSH/Cordis 的**机制纪律**（16 条取舍见计划 §3.1）：账本为唯一上下文真相、model-visible⟺logged 不变量、三段 waterfall 工具管线 + deny-only guard、能力缝三角色、注册返 disposer、作用域层叠、StreamChunk 词汇表、重试分层等。**不引入其运行时**：无热插拔、无配置组合层、无 JS 依赖。

## 六、供应商与登录

- 41 个入口全部保留；4 族协议适配覆盖绝大多数；未覆盖族显式标注，缺哪族接哪族。
- ChatGPT 订阅登录必须保留，放最前面真账号验证。用户判断被拦可能性低；预裁决退路：真被拦则 API key 先行、订阅入口暂时隐藏，不留混合形态。（2026-08-22 裁决 Q2）
- Claude / Copilot / Radius 订阅：**判定口径 = Pi 现状基线**——Pi 能实现（登录+发消息跑通）的，原生就要跟（他开源的我们干嘛不跟）；Pi 做不到的才不做。本实验完成技术验证与实现方案，实现可后续跟进。厂商政策风险用户知情承担。（2026-08-22 裁决 Q3/Q13）
- 维护哲学：开源；自己缺什么接什么，社区有需求就 PR。协议漂移是普通迭代，不是风险。
- 对拍凭证与模型：DeepSeek API key（验证连通即可）+ ChatGPT 订阅（质量测试主用，模型 `gpt-5.6-luna` + low 推理档）。（2026-08-22 裁决 Q6/Q12）

## 七、验证哲学

- 实验期新旧并存可切换，默认仍是 Pi；**不删任何东西**。
- 删除 Pi 时旧会话：可见历史保留，模型内部上下文不迁移（方案 a）。（2026-08-22 裁决 Q4）
- 对拍为主：账本结构化 diff + 12 场景行为差分 + 新评测集质量双评 + 性能体积实测；全程 CLI 通道，不开真实 App（真实 App 只保留一次轻量冒烟）。
- 评测集：≥40 题，混合来源（模型生成题 / 网络习题 / 真实学习场景疑问 / 闲聊场景 / 要求深聊的场景）；Grok 起草、用户审定后才可用；旧 56 题作废。（2026-08-22 裁决 Q14）
- 质量 rubric 三维：正确性 / 语言流畅度 / 回答长度合理性；引用完整性、来源可跳转属功能性指标，归行为差分覆盖，不进质量分。（2026-08-22 裁决 Q15）
- 评分独立性：judge 不是执行者（预定 Kimi），用户可全量过目。（2026-08-22 裁决 Q5）
- 体积门槛：未压缩 .app ≤ 55 MB 卡 go；DMG 只记录。（2026-08-22 裁决 Q8）
- 条件 go：主流四族 + 实际使用入口全绿即 go；未覆盖长尾显式标注不阻塞。（2026-08-22 裁决 Q9）
- go/no-go 硬门槛（计划 §5.5）；报告出来后由用户拍板，删除 Pi 是独立的后续动作。
