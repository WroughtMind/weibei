经 12+20+20+26 次真实请求对照（全程 Luna/low，记录见下方链接），结论：

1. **框架层三个缺陷已修复**：续接状态丢弃（#504 已合并）、搜索被拒静默降级（#506 待合并）、工具可选参数被服务端 strict 归一化变必填（#508 已合并）。

4. 九类新技能加载协议已修通，但「能加载 ≠ 事实可靠」，技能不作为事实问题的修复方案。

### 已核实的现状（2026-09-18 查 [DeepSeek 官方 Responses 文档](https://api-docs.deepseek.com/guides/responses_api/)）

**DeepSeek 已原生支持 Responses API**，当前路由的协议配置是对的，不要改：

- `family: .openaiResponses` ✅：端点 `https://api.deepseek.com/responses`，与 `OpenAIResponsesProvider` 的拼接一致
- `webSearch: .responsesTool` ✅：DeepSeek Responses 支持服务端执行的 `web_search` 工具
- 不支持 `previous_response_id` / 会话存储、始终 `store: false`——与魏碑现有行为恰好一致，无需适配
- 支持 input item 类型：message / function_call / function_call_output / custom_tool_call / custom_tool_call_output / reasoning

**唯一确认要改的**：`NativeProviderRouting.swift` 第 171–178 行 `defaultModel: "deepseek-chat"` 是 Chat Completions 时代的旧名；Responses 文档列的模型是 `deepseek-v4-flash` / `deepseek-v4-pro`（旧名据称路由到 v4-flash，需实测确认）。建议改为 `deepseek-v4-flash`，并以实测为准。
