# Agent 用量、缓存与长对话管理计划

日期：2026-09-16
实施基线：`ed0119bf`，合并前已接入 `a13ffabd` 的官网更新（应用源码无变化）；工作分支：`codex/agent-token-accounting`

## 目标与边界

让每次模型调用的消耗可核查，消除重复工具说明，使默认 ChatGPT 订阅模型能在窗口耗尽前压缩。完整学习对话、来源和用户纠正优先于降低 token 数字。

本次交付为代码、自动检查、合并请求与验证记录。不替换安装中的 App，不发布版本。12,000 字符的单次材料正文额度不调整，不删除历史，不增加用量面板、手动压缩按钮或新依赖。

## 已核实的问题

1. 系统提示重复拼接接口工具定义里的名称与完整描述。
2. 回答的成功用量保存在助手事件上，但标题与摘要请求忽略用量；取消和失败的覆盖也不完整。账本没有逐次模型身份，无法可靠分模型统计。
3. 提前压缩依赖少数静态窗口登记；默认 `gpt-5.6-luna` 没有登记。已有模型目录接口只提取名称，丢弃服务端提供的窗口信息。
4. 材料读取已有预算和连续游标。12,000 是单次额度，不是全文总上限；暂未有证据支持改变该数字。

## 实施方案

### 1. 统一模型调用记账

- 在现有模型适配器外复用一个记账入口，覆盖主回答、工具续跑、标题、压缩及子任务。请求注明用途；每次实际适配器调用分配唯一调用编号。
- 沿用现有追加式 JSONL 格式，在会话目录写入独立用量账本 `usage.jsonl`，记录所属请求、供应商、协议、模型、用途、窗口信息、状态与供应商返回的用量；不额外记录提示正文或凭据。
- 请求开始先落记录，收到用量更新后保留供应商累计值，正常结束、失败、取消分别收口。没有用量为未知，绝不补成零；进程退出留下的开始记录也不能当成零消耗。
- 同一次流式调用的累计用量取逐字段最大值，不把累计快照相加。重试有独立调用编号。助手原有用量只用于上下文容量判断，报表只认专用调用事件，避免重复计费。
- fork 只复制对话账本，不复制用量账本；汇总按调用编号去重，避免累计快照或复制记录重复计费。标题用量不参与对话压缩容量判断。
- 提供只读命令汇总本地账本，按用途与模型展示调用数、未知记录、未缓存输入、缓存读写、输出。缓存率按总缓存读取除以总输入加权计算；缺失缓存字段单列覆盖率，不能被当作零命中。

### 2. 消除重复说明

- 删除系统提示中的整份工具名称／描述目录，保留接口原生工具定义、整体检索规则和按需技能目录。
- 保留排序、固定系统提示和历史前缀稳定性；动态修订号仍只追加到本轮用户消息。
- 验证四种协议里的工具名称、描述和参数仍完整；验证连续工具调用和跨轮消息的稳定前缀。

### 3. 补齐默认模型的压缩覆盖

- 复用现有官方 ChatGPT 模型目录请求，读取精确模型的 `context_window` 与 `effective_context_window_percent`；只接受有效数值和精确模型匹配。
- 短期缓存同一账号的目录，避免每个回答重复查询。目录缺失、失败或模型未知时明确保留未知状态，不根据类似名字推断容量。已有明确超限处理仍只尝试一次，不能伪装为已启用提前压缩。
- 将窗口能力通过实际适配器传到共用循环，子任务同样继承；已有明确供应商与型号登记继续适用，自定义接口不套用官方同名模型数值。
- 沿用现有输出／新增内容余量（最多 16,384 token）、真实用量锚点、完整轮次／工具步骤切点。短尾字符估计只是近似，不是账单 token，不借此宣称所有超限都已消除。
- 摘要成功才记检查点；失败不替换原历史。不改变近期原文与摘要预算，不压缩普通短对话，不在这次优化中新增更激进的裁剪策略。

### 4. 保留材料分页并验收

- 继续允许模型请求更小的正文额度，最大与默认额度保持 12,000 字符。
- 用含中文、公式和表格的长材料串联分页，断言逐页拼接等于原文，游标推进，没有重复、丢字或错误宣称全文已读完；页码／章节和原有来源机制保持有效。
- 此检查证明传输完整性，不冒充模型阅读质量或真实 App 体验验收。

| 失败项 | 证据与判断 | 处理 |
