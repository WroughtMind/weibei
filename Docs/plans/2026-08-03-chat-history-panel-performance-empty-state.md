## 已证实的问题与根因

| 问题 | 已证实根因 | 修复方向 |
| --- | --- | --- |
| 重开会话后向上滑，只容易看到最近一批消息 | 消息没有丢失；会话视图默认只展示最近 30 条。现有滚动探针只知道“离底部多远”，到达顶部时不会触发现成的“展开更早消息”能力 | 让滚动探针同时报告顶部位置；用户真实上滑到顶时自动展开一页，并恢复原来的阅读锚点；保留顶部按钮作为兜底 |
| 有会话窗格时拖动任意分隔条明显卡顿 | 原生分栏本来已经逐帧移动框体；会话宽度探针又把每一个像素写入 SwiftUI 状态，导致整棵会话消息树及其网页视图重复刷新 | 直接复用原生分隔条已有的拖动开始／结束回调：拖动期间只移动原生框体，结束后一次提交最终语义宽度 |
| 空白页中间靠上有白色短竖线 | 空白页组件主动绘制了一条居中的 1 像素装饰矩形，并非输入光标或系统分隔线 | 删除这条装饰，不改空白页其他层次、分隔线或背景 |

## 用户结果

1. 用户重新进入一个长会话后，持续向上滑可以自然看到更早内容，不需要反复碰运气或寻找小按钮。
2. 展开更早消息时，当前阅读位置不会突然跳走；顶部按钮仍可手动使用。
3. 文稿、笔记、会话三个窗格的打开、收回与分隔条拖动不再因为会话树逐像素重建而割裂。
4. 会话框体仍连续跟手；可见内容接受真实父框体尺寸，拖动结束后只做一次必要的最终测宽。
5. 流式文字、Markdown、公式、表格、列表、代码块、消息操作和输入框行为保持现状。
6. 全部内容窗格关闭时，空白页不再出现白色短竖线。

## 不可回退清单

- 不关闭或降级 Milkdown、KaTeX 和富回答网页渲染。
- 不把公式、表格、列表或代码块改成能力更弱的原生纯文本展示。
- 不取消流式前缀、打字机效果、流式高度保护或消息最终态切换。
- 不取消最近 30 条的首屏控制，也不一次性挂载全部历史消息。
- 不替换现有 AppKit 窗格动画，不通过缩短到近乎无动画来伪造顺滑。
- 不改会话持久化格式、协议、Agent 输入框和无关视觉。

## 实现方案

### 一、历史消息自然加载

复用现有的分页窗口、展开动作和锚点恢复能力，只补齐触发链路：

1. 滚动探针报告“离顶部”和“离底部”的距离。
2. 仅当用户已经完成初始定位、正在向上浏览并真正到达顶部阈值时，自动展开一页更早消息。
3. 加入一次展开的重入保护，避免一次滚动连续加载多页。
4. 展开后恢复原顶部消息的视觉位置，防止内容跳动。
5. 保留“查看更早消息”按钮，作为辅助功能和异常情况下的手动兜底。

这部分不改存储层，因为当前证据已经确认历史消息存在，故障发生在展示触发层。

### 二、会话窗格开合性能

不重写消息列表，也不动富文本协议；在现有原生分栏生命周期里消除重复状态回写：

1. 识别“打开或关闭某个内容窗格”这一段结构切换动画。
2. 动画进行时固定会话内部阅读列宽，外层窗格仍按现有 0.24 秒动画移动和裁切。
3. 动画结束后只提交一次最终测量宽度，让可见富文本消息完成一次必要重排。
4. 普通分隔条拖动直接使用原生开始／结束回调；进行中不把每个像素再次发布给 SwiftUI，包含吸附动画的真实终点只提交一次。
5. 可见内容仍由真实父框体提案连续布局；只让屏幕外网页渲染器在运动期间保留旧宽，避免无意义逐帧重排。
6. 流式生成期间沿用当前高度冻结和最终态交接逻辑，不引入第二套渲染或缓存状态机。

公开资料对这条路线有直接支撑：Apple 建议优先减少高频几何值引发的不必要 SwiftUI 更新，并使用原生分栏的 resize 生命周期管理工作边界。截图替身虽可用 `WKWebView.takeSnapshot` 实现，但会增加异步捕获、交互交接和清晰度风险，本次不采用。

技术依据：

- [Apple：理解并改进 SwiftUI 性能](https://developer.apple.com/documentation/Xcode/understanding-and-improving-swiftui-performance)
- [Apple：NSSplitViewDelegate 分栏生命周期](https://developer.apple.com/documentation/appkit/nssplitviewdelegate)
- [Apple：实时缩放期间保留未变化内容](https://developer.apple.com/documentation/appkit/nsview/preservescontentduringliveresize)
- [Apple：WKWebView 网页快照能力](https://developer.apple.com/documentation/webkit/wkwebview/)

### 三、空白页白线

只删除空白页中央的装饰矩形。它没有交互和状态职责，不增加条件开关，也不为它建立新抽象。

## 计划改动边界

| 区域 | 计划动作 | 边界 |
| --- | --- | --- |
| 会话展示模块 | 补顶部探测、自动展开保护、运动期间阅读宽度稳定 | 不改存储、消息协议和 Markdown 渲染能力 |
| 原生分栏协调模块 | 只发出分隔条拖动开始与真实结束信号 | 不改尺寸算法、动画时长、吸附规则和持久化 |
| 空白工作区模块 | 删除白色竖线装饰 | 不改其他空白页布局 |
| 自检模块 | 增加最小回归检查 | 只检查本次三个契约，不扩建测试框架 |
| 工作区状态模块 | 仅在代表性性能场景需要丰富历史夹具时占用 | 不改变生产业务逻辑 |

共享文件占用：`Sources/WeiBeiSelfCheck/main.swift` 用于最小回归检查；`Sources/WeiBei/Views/StableDocumentWorkspace.swift` 只发出已有分隔条生命周期的开始／结束信号。释放条件是工程验证、画中画复核和草稿合并请求更新完成。
