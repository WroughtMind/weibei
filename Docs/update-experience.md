# 魏碑更新体验设计建议（按用户批注修订）

2026-10-22。状态：按钮反馈、主题与说明浮窗已调整；完整应用的鼠标悬停与点击验收仍需记录。

## 核心交互

悬停阅读说明，点击执行操作，过程和阶段在更新按钮上体现。说明面板不承担更新操作。

| 状态 | 更新按钮 | 悬停面板 | 点击行为 |
|---|---|---|---|
| 有更新 | 下载图标；默认不展示“有更新”常驻文字 | 版本、日期与本次实际更新说明 | 立即下载 |
| 下载中 | 图标区域的环形真实进度，旁边百分比 | 保留本次更新说明 | 不重复触发下载 |
| 解压、准备 | 同一位置显示阶段，如“准备中” | 保留本次更新说明 | 等待准备完成 |
| 就绪 | “安装并重启” | 保留本次更新说明 | 先保存最新编辑内容与工作区，成功后安装重启 |
| 失败 | 重试入口 | 简短具体原因，再保留更新说明 | 重试失败的操作 |

鼠标悬停按钮才打开说明面板；移入面板仍可阅读、滚动；离开按钮和面板后收起。点击按钮不会把面板锁定。后台状态变化不主动弹出面板。

入口保留在窗口左上角独立区：阅读工作区紧随前进／后退之后，资料库与课程页位于返回工作台按钮旁。默认保留 24pt 红色下载徽标，点击区域为 30pt；下载、准备、就绪、失败时向右展开，使用当前主题的浮起表面、文字与细描边。红色表示可下载或失败，绿色表示已就绪。

悬停立即改变按钮底色、描边与阴影，按下时压缩并加深底色。停留 250ms 后显示更新说明，离开按钮和面板 220ms 后关闭；两者分别记录悬停，避免过渡时误关。点击先取消待弹出的说明，执行更新，并抑制说明立即重开；忙碌时不能重复点击。

Mac Catalyst 的说明浮窗由原生 AppKit 承载，以按钮实际位置为锚点，并由应用的悬停状态负责关闭。它不建立 UIKit 模态遮挡层，避免系统先截走点击去关闭说明；按钮仍只通过原本的按钮动作触发更新。面板跟随内容高度变化，关闭窗口或应用失去焦点时同步收起。内容复用工具栏已有的 UIKit 宿主，随原生容器正确挂载、调整尺寸并拆除。浮窗使用应用共用的浮层表面：纸色主题呈现对应纸色，深色主题呈现对应深色，玻璃主题使用原有材质。版本与日期分列，分组只用文字层级和留白，正文保留完整条目、行内 Markdown 和滚动，不额外叠加白色容器或分类色条。

资料库与课程页隐藏原生工具栏，页头中的更新按钮改以同一场景的内容窗口为锚点，转换页面按钮的实际位置；不要求按钮属于工具栏项目。回归检查分别覆盖工具栏与普通页头，要求说明打开和重新打开后，第一次鼠标点击都到达原按钮。

下载完成后保留“安装并重启”，等待用户点击。删除“继续使用”按钮；删除退出时安装的说明文案。更新完成后恢复原资料、阅读位置、笔记与工作区，并给出轻量完成反馈。错误不清空工作现场。

## 说明面板内容

版本和发布日期放在头部，下面直接列本次真实变化。新增、改进、修复在本次内容需要时分组。只有一项修复，就写这一项。必要的使用变化、系统要求或已知问题按实际发布内容说明。

采用魏碑既有主题、字体和细分隔线，靠文字排版和留白保证阅读。不添加宣传标题、收益导语、装饰插画、额外操作底栏，也不规定每次条目数量。长说明自然滚动，鼠标进入面板可以继续读。

## 成熟参考

- [Apple 浮窗设计规范](https://developer.apple.com/design/human-interface-guidelines/popovers/)与[应用管理关闭的原生浮窗](https://developer.apple.com/documentation/appkit/nspopover/behavior-swift.enum/applicationdefined)：参考锚点定位和短内容阅读，使用不会先截走底层操作的关闭方式。
- [待办工具 Things 的 Mac 更新说明](https://culturedcode.com/things/support/articles/1100684/)：版本、日期、适用系统和直接的变更条目。其 3.22.12 只有一项简短内部调整。参考其信息量按实际变化决定的写法，不照搬系统要求栏，也不据此声称它用悬停更新面板。
- [Mac 编辑器 Nova 的版本记录](https://nova.app/releases/)：日常修复版本按具体问题逐条列出。参考正文的具体性，不照搬大版本的功能宣传结构。
- [开发工具 IntelliJ IDEA 的悬停文档](https://www.jetbrains.com/help/idea/documentation-tool-window.html?keymap=primary_default_for_windows)：支持鼠标悬停查看说明。仅作为悬停读信息的交互参考，不是其更新界面的证据。

没有找到足以证明某款成熟应用完整采用“悬停更新说明、点击直接下载、同一按钮进度和重启”的官方资料。本版是按用户批注组合后的魏碑设计决策，不冒充竞品复刻。

## 必须同步实现的行为

- 下载和解压使用更新组件提供的实际数据。下载总量不可用时显示真实阶段，不制造百分比。
- 下载完成不得直接批准重启，应等待用户点击安装。没有操作时正常使用魏碑。
- 安装前等待最新笔记与工作区保存成功；失败停在错误状态，允许重试。正常退出路径也要保证保存完成。
- 重启恢复实际阅读位置和编辑现场，需要真实应用验证，设计预览不等于已经实现。
- 按实际安装阶段接通延期和重新进入安装的行为，不通过取消更新伪造就绪，也不依靠额外文案补救错误流程。

实现采用一个工具栏更新组件，共用原有更新服务。构建与检查结果记录于合并请求；未操控用户正在使用的应用。
