# 公式节点视图覆盖技术预研

日期：2026-08-19
结论：**走路径 A。可以在不复制 Schema 的情况下，直接给现有 `math_inline` / `math_block` 注册自定义 NodeView。** 工作包 D 不需要先重写公式解析器，也不需要新增第二套公式节点。

## 代码证据

1. `@milkdown/plugin-math@7.5.9` 已导出并注册 `mathInlineSchema`、`mathBlockSchema`；节点名固定为 `math_inline`、`math_block`。
2. 行内公式源码保存在节点 `textContent`；块公式源码保存在 `attrs.value`。插件现有 `parseMarkdown` / `toMarkdown` 已负责 Markdown 往返。
3. 编辑器已经在 `editorViewOptionsCtx` 的 `nodeViews` 中用同一机制覆盖 `code_block`（`WebEditor/src/editor.ts:2531-2536`）。给同一个 map 增加两个公式键即可，ProseMirror 会优先调用 NodeView，Schema 和序列化规则不变。
4. 当前 `.use(math)` 位于编辑器插件链（`editor.ts:2577`），所以创建 EditorView 时两个节点类型已经存在；NodeView 只负责 DOM、交互和更新，不参与 schema 创建。

## 最小实现边界

- `nodeViews` 增加 `math_inline` 与 `math_block` 两项，共用一个很小的工厂，按节点类型决定行内/块级外壳。
- `update(node)` 只在节点类型一致时复用 DOM，并从 `textContent` 或 `attrs.value` 读取最新源码重渲。
- 未选中显示 KaTeX；进入编辑态才显示输入框。选区、Backspace、方向键和提交/取消按工作包 D 的验收补最小事件处理。
- `ignoreMutation` 只忽略 NodeView 自己维护的 KaTeX DOM；编辑框输入必须由 transaction 写回节点，不能另存一份状态。
- 删除现有 `upgradeDisplayMath()` 全局 DOM 扫描；块级 `displayMode` 由块 NodeView 自己传给 KaTeX。

## 已知边界

- 旧公式插件为 7.5.9，主 Milkdown 为 7.21.3；本机依赖树显示插件自带 `@milkdown/utils@7.5.9`，主工程使用 7.21.3。当前解析、输入规则和真实 WKWebView 检查已经在这组版本上运行，但这不等于插件可以永久保留。
- NodeView 覆盖不会新增版本耦合，因为只按现有节点名和节点数据读取；工作包 D 必须用所有公式夹具锁住 parse → serialize → parse、行内/块级源码和金额 `$5` 防误判。
- 如果后续实测发现旧插件 schema 在 7.21.x 下无法稳定创建，才切路径 B：本地最小移植现有两份 Schema 与 input rule；不要建立兼容层。

因此，当前不复制 Schema；先覆盖 NodeView，并把移除旧插件留到运行时收口工作包。
