# `noteText` 生产与消费方审计

日期：2026-08-19

范围：`Sources/WeiBei` 中全部生产代码；测试与自检夹具只记录、不作为迁移需求。
结论：活动笔记正文有 57 处直接引用。工作包 B 不能只替换编辑器绑定；必须先给 **Agent、内容写入、保存/切换/退出、搜索和文件操作** 加“取得指定 revision 最新快照”的闸门。标题、目录、标签和来源 revision 不应继续靠读取全文刷新。

## 分类口径

| 类别 | 含义 | 工作包 B 的处理 |
|---|---|---|
| A | 动作的正确性依赖当前最新正文 | 动作前向 Web 请求 snapshot，并等待 `revision >= minimumRevision`；切换文档后拒收旧 generation |
| B | 允许使用最近一次完整 snapshot | 继续读 `WorkspaceStore.noteText`，不因每次按键刷新 |
| C | 只需要标题、目录、标签、revision、dirty 等元数据 | 改读增量事件或独立元数据，移出全文依赖 |

## A 类：必须取得最新正文

| 生产/消费方 | 当前真实用途 | 风险 | 迁移动作 |
|---|---|---|---|
| 编辑器本地草稿与 `updateNote`（`NotesAgentView.swift:451-452, 533-540, 709-724, 813-852`；`WorkspaceStore.swift:10804-10847`） | Web 全文回传到本地草稿，220ms 后发布到 Store，再调度落盘 | 这是旧的每键全文热路径 | 改为 dirty/revision 事件；只有 snapshot 回来时更新 `noteText` 和正式保存队列 |
| 切换笔记、关闭页面、失焦与 App 退出（`NotesAgentView.swift:523-532, 805-852`；`WorkspaceStore.swift:10154-10220`；`WeiBeiApp.swift:44-99`；`WorkspaceStore+NotesPersistence.swift:615-665`） | 切换前 `persistCurrentNote`，退出时同步冲刷暂存与保存队列 | 最近 snapshot 落后时会保存旧正文并切走 | 把切换/失焦/退出设为高优先级 snapshot 请求；保存完成或明确失败后再完成生命周期动作 |
| Agent 发起请求（`WorkspaceStore.swift:16276-16384`） | `performAgentRequest` 先冲刷暂存，再把当前笔记正文和 revision 放进 Agent 上下文 | Agent 可能读到停止输入前的旧 snapshot | 建立 fresh snapshot gate；构造 `projectAccess`、`sentNoteText` 与 source revision 前等待最新 revision |
| Agent 确认写入与撤销（`WorkspaceStore.swift:9104-9280, 9498-9603`） | 读取当前正文、比 digest、追加/撤销建议并立即持久化 | 旧正文会造成错误冲突判断或覆盖新输入 | `agentActionNoteMarkdown` 访问活动笔记时先请求最新 snapshot；非活动笔记维持现有读盘/缓存路径 |
| “把选区写入笔记”“把回答写入笔记”（`WorkspaceStore.swift:15905-15922`） | 直接执行 `noteText + block` | snapshot 落后会丢掉尚未同步的尾部输入 | 不再在 Swift 拼全文；优先改成 Web 端结构化插入。若仍需 Swift 拼接，必须先 fresh snapshot |
| 空白笔记首次实体化（`WorkspaceStore.swift:10804-10879`） | 从 `noteText` 取得首次非空正文并创建真实笔记文件 | 使用旧 snapshot 会创建空或残缺文件 | 首次实体化由 dirty 事件触发意图，真正创建前请求 snapshot；创建后继续用 document generation 关联 |
| 活动笔记重命名（`WorkspaceStore+NotesPersistence.swift:95-305`） | 用活动 `noteText` 改写标题，再移动/原子写文件 | 重命名可能把旧正文写到新路径 | 重命名事务开始前取得最新 snapshot，再沿用现有备份、身份和 digest 守卫 |
| `persistCurrentNote` 的无 pending 分支（`WorkspaceStore+NotesPersistence.swift:615-625`） | 直接 `persistNote(noteText, for:)` | Store snapshot 未追上 revision 时写旧内容 | 仅允许保存 `savedRevision` 对应 snapshot；生命周期调用先通过 fresh snapshot gate |
| 课程根重绑的保存与回滚（`WorkspaceStore.swift:2863, 2982, 3017`） | 暂存/恢复活动正文，或采用 portable state 中的正文 | 重绑期间如果活动编辑器仍脏，会丢掉未快照输入 | 事务冻结前请求最新 snapshot；回滚同时恢复 document generation 与 snapshot revision |
| 外部文件刷新冲突基线（`WorkspaceStore.swift:18679-18888`） | 用活动正文 digest 判断磁盘是否等于当前显示内容；后台读盘只在显示内容未变化时覆盖 | 最近 snapshot 不代表 Web 中实时正文 | 判断改用 dirty/currentRevision/savedRevision；外部刷新前先同步或明确进入三方冲突流程 |
| 课程首页全文搜索（`WorkspaceStore.swift:8110-8145`） | 活动笔记直接把 `noteText` 作为搜索正文 | 用户刚输入的词搜不到 | 用户显式搜索时对活动笔记请求 fresh snapshot；后台索引刷新仍可使用 B 类 snapshot |

## B 类：可以使用最近 snapshot

| 消费方 | 当前用途 | 迁移判断 |
|---|---|---|
| 非活动笔记的 `notesByItemID` / `loadedCourseNoteTextByItemID` / 读盘路径（`WorkspaceStore.swift:9498-9545, 10119-10149, 18767-18842`） | Agent、列表和搜索读取非活动笔记 | 非活动文档没有活跃 Web revision，维持现有缓存优先与安全读盘 |
| 笔记列表的正文标题回退（`WorkspaceStore.swift:10055-10068`） | 无自定义标题时从 Markdown 第一段推导列表名 | 接受最近 snapshot；活动标题更适合由 C 类 outline/title 事件更新 |
| 旧来源关系迁移（`WorkspaceStore.swift:13320-13335`） | 启动/迁移时从 Markdown 中扫描“来源”文字 | 一次性、低频；最近落盘 snapshot 足够，不进入输入热路径 |
| 课程项目访问清单与非当前笔记 revision（`WorkspaceStore.swift:13848-13882, 15529-15548`） | 生成各项目源 revision，校验课程画像引用 | 非活动笔记继续用缓存；活动笔记在真正发 Agent 请求时由 A 类闸门刷新 |
| 加载、创建、导入、删除、导航恢复时给 `noteText` 赋初值（`WorkspaceStore.swift:977, 7044, 7850, 8549, 8584, 8850, 10168, 10220, 10982, 11218, 12056, 12668, 12914, 12950, 20427`） | 文档打开/关闭时载入最近安全正文 | 这些是 document load 生产方，不要求每键最新；必须携带新 generation，避免旧 Web 回调覆盖新文档 |
| 后台课程笔记读取（`WorkspaceStore.swift:18679-18748`） | 把磁盘正文放入缓存，编辑器没有本地变化时才采用 | 继续保留“显示内容未变才覆盖”，但比较对象应是 generation + dirty，而非字符串碰巧相等 |

## C 类：只要元数据，不该继续读全文

| 消费方 | 当前用途 | 应替换为 |
|---|---|---|
| 写作目录 `noteRailItems`（`NotesAgentView.swift:726-755`） | SwiftUI 每次 body 重算都逐行扫描全文标题与摘要 | Web 的 `outlineChanged` 增量事件；内容未变不发送 |
| 活动标题 `agentNoteTitle`（`WorkspaceStore.swift:9978-9994`） | 从全文推导浮动标签名 | `outlineChanged` 中的首个可用标题/文档标题元数据；自定义标题仍由 Store 管 |
| 侧栏标签订阅与提取（`CourseSidebarModel.swift:165-176`；`WorkspaceStore.swift:10070-10117`） | 每次 `noteText` 发布使侧栏重建，并重新解析标签 | `tagsChanged` 或统一 `documentMetadataChanged`；非活动笔记继续用 snapshot/索引 |
| 项目 source revision（`WorkspaceStore.swift:13861-13865, 15536-15540`） | 用完整 Markdown 重新算 revision | 活动笔记直接使用 editor revision/content digest 元数据；只有正式快照写入时再算持久化 digest |
| 编辑器目录定位状态（`NotesAgentView.swift:756-769`） | Swift 依据扫描结果生成 heading index，再发滚动命令 | outline 事件返回稳定 heading id/index；Swift 只保存选中 id |

## 生产方与状态所有权

| 生产方 | 当前行为 | 迁移后唯一职责 |
|---|---|---|
| Web `markdownUpdated` | 每个 docChanged transaction 全文序列化并回传 | 删除注册；transaction 层只发 revision/dirty |
| `NotePaneView.draftNoteText` | 活动正文的 SwiftUI 实时副本 | 删除实时正文权威；视图仅持 document identity 与展示元数据 |
| `WorkspaceStore.noteText` | 实时正文、最近缓存、持久化输入三种角色混在一起 | 仅表示“最近一次被 Swift 接受的完整 snapshot” |
| 磁盘/课程文件 worker | 打开与外部刷新时生产 Markdown | 保持文档加载来源；载入命令带 documentID/generation |
| Agent/结构化插入命令 | 通过 Swift 拼接全文或向 Web 发 command | 活动文档优先在 Web transaction 中修改；落盘仍走正式 snapshot 链路 |

## 不进入生产迁移的同名引用

- `WorkspaceStore.swift:14117, 14714` 是安全自检专用的 fixture 注入与秘密泄漏断言，只需在 Bridge V2 自检改造时同步更新。
- `WorkspaceStore.swift:14421-14519, 16529` 的 `noteText` 是函数参数或模型字段标签，不是 `WorkspaceStore.noteText` 的读写者。
- `WorkspaceStore.swift:342` 是属性声明本身。迁移期保留这个属性，但语义收窄为最近完整 snapshot。

## 工作包 B 的最小迁移顺序

1. 先加 `documentID + generation + revision` 和单飞 snapshot 请求，保留现有安全写盘器。
2. 先接 A 类：Agent 请求/写入、切换、失焦、退出、重命名、外部刷新、显式搜索。
3. 再移除 `markdownUpdated` 与实时 Binding；`noteText` 只在 `snapshotReady` 时更新。
4. 最后把目录、标题、标签、source revision 切到 C 类元数据事件，删除全文订阅。

未发现独立的“导出当前笔记”生产入口；当前 Markdown 文件本身就是互操作出口。以后若新增导出/分享，必须直接归 A 类。
