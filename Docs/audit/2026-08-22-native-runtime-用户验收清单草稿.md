# Native 提案能力用户验收清单草稿

日期：2026-08-22  
范围：CLI live 无法真正落库提案（无真实笔记库 / 工作区），闭环改在真实 App 里逐条确认。  
用法：只填「是否通过 / 问题备注」。不必记 SHA、哈希、窗口、provider、日志、截图或录屏。

**切换步骤（先做这一条）：** 打开设置 → 对话 → 打开「调试（临时）→ 使用 Native 引擎」→ 之后四条都在 Native 下验收。关掉开关即回到默认 Pi。这个开关只为这次验收存在，冒烟通过并删除 Pi 后会去掉。

| 用户怎么操作 | 应该看到什么 | 是否通过 | 问题备注 |
|---|---|---|---|
| 打开一门课的 Chat，说：我刚搞懂了复利，请记下这个进度，但先给我看你打算怎么写，不要直接改记忆。 | 给出学习记忆更新建议；记忆本身还没改；需要确认才会写入 |  |  |
| 接着说：更新这门课的知识档案建议，我已掌握单利，复利还不熟。 | 给出课程知识档案建议；档案还没被直接改掉 |  |  |
| 说：把「利率是资金使用价格」做成一条笔记建议，并给出证据句。 | 给出笔记正文和证据；确认前笔记列表里没有这条新笔记 |  |  |
| 说：建议把这条笔记关联到利率课文，先给我确认。 | 给出关系建议；确认前不会悄悄建好关联 |  |  |
