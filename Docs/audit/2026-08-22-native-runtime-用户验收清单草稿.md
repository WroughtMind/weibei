# Native 提案能力用户验收清单草稿

日期：2026-08-22  
范围：真实 App 开 Native 调试开关后，四条提案走与 Pi 相同的产品行为。  
用法：只填「是否通过 / 问题备注」。不必记 SHA、哈希、窗口、provider、日志、截图或录屏。验收前先在设置 → 关于里核对版本行里的提交短哈希，须与本次候选包一致。

**切换步骤（先做这一条）：** 打开设置 → 对话 → 打开「调试（临时）→ 使用 Native 引擎」→ 之后四条都在 Native 下验收。关掉开关即回到默认 Pi。这个开关只为这次验收存在，冒烟通过并删除 Pi 后会去掉。

记忆默认校验通过即写入，回答下方出信息标签，**不走确认卡**。用户明确要求「先给我看 / 不要直接改记忆」时，只展示拟写内容，在对话里确认后才落库。档案仍是校验通过即写入。笔记与关系走确认卡，确认前不落库。

| 用户怎么操作 | 应该看到什么 | 是否通过 | 问题备注 |
|---|---|---|---|
| 打开一门课的 Chat，说：记下进度，但先给我看怎么写、不要直接改记忆。 | 不调用写入工具；回答里逐条展示拟写内容；无「已更新学习记忆」标签；等用户确认 |  |  |
| 接着说：可以，就这么写。 | 此时才调用写入工具落库；revision 变化；回答下方出现「已更新学习记忆」标签 |  |  |
| 接着说：更新这门课的知识档案建议，我已掌握单利，复利还不熟。 | 自述条目真落库（revision 和条目数变化）；回答下方出现「已更新课程知识档案」标签；不需要确认 |  |  |
| 说：把「利率是资金使用价格」做成一条笔记建议，并给出证据句。 | 出现可编辑的笔记确认卡；确认前笔记列表里没有这条新笔记；确认后在本课程新建笔记 |  |  |
| 先确认写入上一条笔记，再说：建议把这条笔记关联到利率课文，先给我确认。 | 出现关系确认卡；确认前不会悄悄建好关联；笔记还没写入时不应出关系卡 |  |  |
