## 结论

1. **可以**不用 Bun 单文件，用 Node 运行官方 Pi JS 包。
2. 官方 `@earendil-works/pi-coding-agent@0.82.1` 入口为 `dist/cli.js`（`#!/usr/bin/env node`），`engines.node >= 22.19.0`。
3. 在 Node v24.13.0 上，`--mode rpc --offline` 与魏碑相近的 CLI 参数可启动；RPC `get_state` / `get_commands` / `abort` 成功，响应形态与当前内置 Bun 单文件对照一致。
4. 这**有助于**绕开 G0.4 中“再分发 Bun compile 单文件”的 LGPL 静态链缺口，但**不等于**整包变成纯 MIT；若迁移，仍需声明 Node 与 npm 依赖。
5. **不能**据此宣布生产已切换；宿主集成、体积、原生可选依赖、签名与完整对话回归仍待 G0.5b–d。

## 复现命令（摘要）

```bash
mkdir -p /tmp/pi-node-feasibility && cd /tmp/pi-node-feasibility
npm init -y
npm install @earendil-works/pi-coding-agent@0.82.1 --no-fund --no-audit
./node_modules/.bin/pi --version
# => 0.82.1

SESSION_DIR=$(mktemp -d)
SESSION_ID=$(uuidgen | tr '[:upper:]' '[:lower:]')
# 保持 stdin 打开，发送 JSON 行：
# {"id":"1","type":"get_state"}
# {"id":"2","type":"get_commands"}
# {"id":"3","type":"abort"}
./node_modules/.bin/pi \
  --mode rpc --offline \
  --session-id "$SESSION_ID" \
  --session-dir "$SESSION_DIR" \
  --no-builtin-tools --no-extensions --no-skills \
  --no-prompt-templates --no-themes --no-context-files --no-approve \
  --system-prompt "You are a test agent." \
  --name "Feasibility"
```

对照：魏碑当前缓存的 Bun 单文件  
`script/prepare_pi_runtime.sh` 产出路径下 `bin/pi`（Mach-O，约 72MB）在相同 RPC 探测下行为一致。
