# 首次公开发布

目标不是一次把所有概念讲完，而是让第一次看到的人在十秒内明白：这是一个 macOS 阅读与笔记工具，提问围绕资料发生，答案可以回到出处。

## GitHub 首页

首屏顺序：

1. 完整 hero；
2. `本地学习用的 macOS 工作台。`
3. 两段真实动机，不写品牌宣言；
4. 一张三栏工作区截图；
5. 六条可完成任务；
6. 一段课程对话的边界与来源说明；
7. 运行方式和当前状态。

GitHub Social Preview 使用 `assets/github/github-social-preview-1280x640.png`。仓库头像使用 `github-avatar-512.png`。README 不要连续堆三张品牌图；产品截图比 Logo 更能解释用途。

## 宣传网站

一个长页足够：

- Hero：`读、记、问，在同一张纸上。`
- 30 秒核心流程视频；
- 三个工作面：阅读、对话、笔记；
- 证据：点击引用回到 PDF 页 / HTML 章节；
- 本地：哪些留在 Mac，哪些请求模型服务；
- 支持格式与系统要求；
- 下载 / GitHub；
- 当前限制与开发状态。

视觉沿用连续纸面，不把每一段做成圆角卡片。背景只在 hero 使用轻纸纹，正文区域保持干净。

## 三条视频

### 1. 30–45 秒：核心闭环

打开课程 → 选择一段 → 围绕选区提问 → 点击引用 → 回到原文 → 确认写进笔记。全程录真实界面，少用转场，不配“AI 正在思考”的特效。

### 2. 20 秒：来源不是脚注装饰

连续点开三个不同来源：HTML 章节、PDF 页、课程笔记。画面只强调定位和回跳。

### 3. 20 秒：写入由用户决定

展示 Agent 建议、差异、拒绝和确认。它解释了产品为什么不是自动改笔记的聊天壳。

## 发布帖模板

> 我做了一个 macOS 学习工作台，叫魏碑。它把课程资料、提问和 Markdown 笔记放在同一个窗口里。回答里的引用可以回到文件、PDF 页或 HTML 章节，写进笔记前也会先让你确认。现在支持 HTML、PDF、Markdown 和纯文本，还在开发中。

然后放一段核心流程视频、GitHub 链接和三条已知限制。不要把功能列表复制成十段口号。

## 发布节奏

1. 先用 5–10 个真实课程做内部试用，修掉引用失效、滚动丢失和写入不确定性；
2. 发布 GitHub README、一个核心视频和可重复安装步骤；
3. 收集“看完首页后以为它是什么”“第一次任务在哪卡住”两类反馈；
4. 第二轮再讲课程索引、学习记忆和高级布局，不在首发把所有概念压给用户。

## 判断是否讲清楚

- 十秒后，用户能否说出它是 macOS 阅读 / 笔记工具？
- 能否看出 Agent 围绕资料工作，而不是通用聊天？
- 能否理解引用可以回到原文？
- 能否知道数据哪些在本地、哪些会发给模型服务？
- 是否有一个不读长文也能开始的安装入口？
