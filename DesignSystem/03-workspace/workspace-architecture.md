# 工作区架构

## 三个可重排工作面

仓库中的真实 pane 是 `reader`、`agent`、`notes`，默认顺序 `[reader, agent, notes]`，用户可以重新排序。Logo 的三柱因此不解释成固定步骤，而解释为三个平等界面被同一课程上下文连接。

底部连接结构代表共享上下文；朱砂落点代表阅读、提问和记录最终都能落回真实位置。

## 模式

`ContentView.swift` 已支持：

- 两栏与三栏；
- 对半布局；
- 沉浸阅读；
- 沉浸对话；
- 沉浸写作；
- 课程目录、内容轨道和可恢复 pane 状态。

设计变更必须保护 `PersistentPaneHost` 的连续性：切换布局不能重建阅读器、丢失滚动位置、打断输入或重置对话。

## 各工作面的角色

| 工作面 | 角色 | 不应变成 |
|---|---|---|
| Reader | 第一主工作面，展示资料与选区 | 网页浏览器工具栏堆栈 |
| Agent | 围绕明确范围检索、解释和引用 | 占据最大面积的通用聊天首页 |
| Notes | 第二主工作面，沉淀用户确认的内容 | Agent 自动改写的输出区 |

课程目录负责导航和组织，不参与三柱含义，也不应抢占主要阅读宽度。

## 缩放原则

窗口空间不足时：先收起课程目录或休眠非当前内容轨道，再进入两栏，最后进入单一沉浸工作面。不要把三个栏同时压窄到低于可读阈值。模式变化应由用户动作或清楚的空间条件触发，不能在编辑中突然发生。

## 状态连续性

以下状态必须跨 pane 切换保持：

- 阅读文件、页码、章节和滚动位置；
- 当前选区与引用来源；
- 对话范围、未发送输入和流式回答；
- 笔记光标、选择、撤销栈和保存状态；
- 用户调整过的栏宽与排列顺序。
