# 无障碍

## 基线

- 正文与交互文字满足 WCAG AA；
- 状态不只靠颜色；
- 所有核心流程可以仅用键盘完成；
- 焦点环清楚且与石青行动语义一致；
- 支持 Reduce Motion、Reduce Transparency 和 Increase Contrast；
- 字号增大时优先切换布局模式，不压缩正文。

## VoiceOver 顺序

课程目录 → 当前可见工作面，按用户实际 pane 顺序读取。由于 `reader / agent / notes` 可重排，不能把辅助功能顺序硬编码成固定左中右。

引用的读法应包含动作与位置，例如：`打开《计量经济学》第 12 页`。定位后把辅助功能焦点移动到目标段落，并宣布当前位置。

## 颜色与纹理

- 朱砂和石青不能承担唯一差异；
- 当前出处同时提供形状、文字或可访问标签；
- 墨石主题不是简单反相，正文和次要文字都要实测；
- 纸纹不能影响文字边缘和选区对比度。

## 内容边界

扫描 PDF 没有可检索文本、索引未完成、联网失败、只检索到部分文件时，要直接告诉用户。对辅助技术用户同样暴露进度、范围和失败原因，不能只显示视觉 spinner。

## 键盘

以下动作必须有稳定路径：打开课程、选择资料、切换 / 重排工作面、聚焦阅读、围绕选区提问、打开引用、聚焦笔记、确认或拒绝写入、打开命令面板。

拖动分隔条之外还要提供键盘调整宽度的方法，或至少提供预设布局动作。

## 发布前实测

- VoiceOver 完成一次“阅读 → 提问 → 打开引用 → 写入笔记”；
- 200% 字号下完成同一流程；
- Reduce Motion 和 Reduce Transparency 同时开启；
- 增强对比度下检查纸面、石青链接和朱砂落点；
- 仅键盘重排 pane 后，阅读顺序与视觉顺序一致。
