# 魏碑独立会话候选 · PR #451

本分支把 MarkdownView／Litext 正文接入魏碑原有会话入口。使用自己实现的 macOS 消息列表，不获取、不迁入、不等待 #449 或 #452 的代码、宿主、源码快照和构建产物。正式 App、模型请求、资料库与笔记写入流程继续使用主线已有实现；实验身份和数据独立。

尚不能把“编译通过”解释为已经适合替换正式版。运行记录区分完整候选、隐藏窗口行为、组件成本和用户体验；没有触控板或帧率数据就不作这类结论。

2026-09-09 用户反馈的斜体、标题层级、块公式、顶部空横条和流程图底色已修正，同时补齐高亮、行内脚注、双链图片和引用内富内容。表格保留用户已认可的样式。详见[本轮样式修正](#本轮样式修正2026-09-09)；自动检查与画中画证据不替代最终候选的用户体验验收。

## 构建和体验入口

需要 macOS 14+、支持 Swift 6 的 Xcode、Node.js 22 和已锁定的依赖。构建脚本使用本仓库原有编辑器资源入口，保留数学字体、代码高亮、图示资源、PDF helper 和签名校验，不修改正式打包脚本。

```sh
# 完整会话候选：原有魏碑工作区、会话、来源、动作卡和输入框。
bash Experiments/ChatRendererLab/script/build_conversation.sh package
# 隐藏窗口检查同一个消息列表和原有气泡、流式与动作入口。
bash Experiments/ChatRendererLab/script/build_conversation.sh verify
# 同一份合成内容，编译主线原有列表/正文路径，用于端到端比较。
bash Experiments/ChatRendererLab/script/build_conversation.sh package baseline
# 三组真实会话入口取证，两个包顺序运行，结果不是 FPS。
bash Experiments/ChatRendererLab/script/build_conversation.sh benchmark candidate
bash Experiments/ChatRendererLab/script/build_conversation.sh benchmark baseline
```

完整候选输出为 `.artifacts/conversation-candidate/魏碑-会话实验-451.app`，标识 `com.weibei.experiments.conversation451`。基线为 `.artifacts/conversation-baseline/魏碑-会话基线-451.app`，使用另一标识。两个包均不安装到 Applications，也不进入正式更新通道。

候选首次启动创建三份合成会话：“长历史 · 384 条”“少量消息 · 长正文与代码”“富内容 · 来源与动作”。菜单“会话实验”可以切换样本、重放和停止合成流式回答。重放明确标为合成输入，通过魏碑已有的会话流式和停止入口运行。正常提问入口仍在；真实模型需在实验 App 中单独配置，不读取已安装魏碑的凭据。

普通运行的数据在 `~/Library/Application Support/com.weibei.experiments.conversation451/`，资料库与工作区分开放置。验证模式每次使用自身结果目录里的全新合成资料。不要向实验版导入生产资料来替代脱敏样本。

每个包的 `Contents/Resources/environment.txt` 和 `Info.plist` 记录提交、工作区是否有改动、构建模式和系统；同目录包含实际 `Package.resolved`。结果目录保留编译、资源、签名及行为记录。最终体验应使用记录为干净提交构建的包。

打包沿用正式版的 `strip -x` 清理可执行文件中的本地符号，再签名；完整调试符号单独保存在结果目录的 `WeiBei.dSYM`，校验构建身份一致。两条正文路径都只使用 Latin Modern，保留其完整字体、数学表及全部许可证，不打包另外 11 套未使用的公式字体。高亮保留全部语言、初始化必需的 pojoaque 配色和当前使用的 xcode 配色；深浅外观仍由原有动态颜色映射处理。

## 样式保留后的性能修正（2026-09-09）

样式补齐后，原三轮记录中首次会话几何稳定增加约 57 / 87 毫秒，回看与改宽接近。继续沿用同一消息宿主与富内容，修复实际日志、采样和调用链确认的三处问题：

- 标题缩放通过字体名称重建已解析的中文系统字体，会触发错误替换；长回答旧包每次记录 147 条字体提示。改用 Core Text 复制字号与字体特征，保留实际中文字体及粗斜体，不重新用内部字体名称查找。样式检查增加标题与正文的中文字体族一致、实际粗体和斜体字形核对。
- 输入框本来已经为空，创建时再次写入空字符串会触发系统的文字选择、输入界面与写作工具初始化。创建与后续更新现在都只在文字不同时赋值；保留非空草稿、输入法、焦点和系统功能。
- 原依赖遇到任何公式就禁用整份正文的段落缓存，因此代码高亮完成还会重复处理未变化的标题、正文和斜体。缓存现在校验公式原文与渲染图像，匹配时复用；公式、主题或段落变化仍更新。继续保留引用内代码／表格的视图归属规则。

沿用完整会话检查，新增一项行为检查：实际异步高亮完成后不再加工未变化的含公式正文，文字和样式保持一致；修改公式后显示与复制必须更新。现有性能入口额外记录各阶段累计解析／正文加工次数，并计入首次聚焦输入框和输入文字的成本，避免只把停顿转移到首次输入。阅读阶段峰值与输入及连续改宽后的峰值分别记录；原四段对比的计时边界、样本、字号、宽度与稳定等待保持原样。另连续改变窗口宽度 740→480→740，并在现有长文检查中验证来回改宽后仍是原处文字。

最新来源、三轮对比和未验证项以原 PR 及候选包随附记录为准；后面的样式修正记录与更早审计保留各自来源，不混用成当前性能结果。

后续主线程采样发现，阅读位置索引、引用边界及富内容定位只使用文字范围和行位置，却同时计算了每段字形的图像边界。现有 `layoutRuns` 增加跳过该计算的参数；需要精确字形矩形的调用保持原行为。补丁记录在 `script/litext-line-geometry.patch`，沿用同一准备和打包入口；原样式检查同时核对两种方式得到的文字范围及行矩形完全一致。原有内容、字号、表格及阅读锚点算法没有变更。

此前长历史首开三轮中位数 483.9→1146.7 毫秒仍保留为该批次结果；当时没有整机内存压力及换页记录，不能将差距直接归因为代码或内存。后续同机交错对比同时保留整机压力、换页和候选进程占用，采样与性能计时分开进行。

| 图片与正文扩展 | 双链图片显示为图片，普通图片接回打开入口；高亮和行内脚注不再裸露标记。非图片的双链仍为笔记链接。 |
| 流程图 | 会话附件去掉额外代码底板；紧凑只读预览使用透明背景和完整不透明度，图中文字与节点使用当前主题颜色。 |
