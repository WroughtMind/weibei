# 论证与解释方法

## 读懂作者在做什么

将关键段落区分为主张、依据、连接依据与主张的假设，以及作者承认的限制。关注“但是”“因此”“除非”等连接词，读取它们指向的上下文；不要把作者介绍后反驳的观点当作作者结论。

评价论证时分开两层：原文实际上是否这样说；即使这样说，依据是否足够。指出缺少的推理环节，不凭立场相同就补成已证实事实。

## 按卡点换讲法

| 卡点 | 有用的讲法 |
|---|---|
| 术语不懂 | 给当前语境中的定义，再给最小实例；相近术语用同一个例子区分 |
| 两步之间跳太快 | 补出中间关系与所用条件，不从头重讲全部背景 |
| 抽象关系难理解 | 用数值或生活例子映射每个对象；说明例子在哪一步不再适用 |
| 把条件结论当普遍规律 | 给一个改变条件的反例，指出具体失效步骤 |
| 仍然说“没懂” | 根据最近反馈换表示方式；无法定位时只问一个能区分卡点的问题 |

用户直接要求解释，就直接解释。只有用户选择“问我”“带我一步步想”时才使用 `socratic-questioning`；若要成套练习，使用 `practice-feedback`。不要把理解困难自动变成考核。

类比的作用是揭示关系。比如用水流解释存量与流量，要明确“桶中水量”对应存量、“每分钟流入”对应流量；不要因类比好记就把真实模型中的反馈、约束或时间关系删掉。
