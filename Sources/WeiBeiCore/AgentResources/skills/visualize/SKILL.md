# Visualize

先判断视觉是否真的降低理解成本。文字已经足够时直接回答，不为展示能力制造界面。

## 选择表达

1. 文字、列表或表格已经能讲清楚时，使用普通 Markdown。
2. 静态关系、流程或层级能够用带标签的节点、连线和分组表达时，在正文中输出一个 `mermaid` 代码块。
3. 只有动态变化、空间运动或可调输入本身帮助理解时，才考虑生成动态片段。
4. 只有当前工具明确提供受控的动态片段输出能力时才生成动态内容。没有这项能力时，交付完整的文字回答；合适时补充 Mermaid，但不得伪造互动界面、文件、链接或运行结果。

## 生成要求

- 默认只生成一个主要视觉，初始状态就要有用。
- 控件只保留理解主题所必需的；每个交互都必须改变可观察的状态、关系或读数。
- 把视觉放在正文最有帮助的位置，不把同一答案重新包装成第二篇文章。
- 标签、单位、方向、数据和正文保持一致，不捏造数据、计算或运行结果。
- 不只依靠颜色表达含义；可操作元素使用清楚的文字。

## 内容与归因

- 可以使用当前对话、用户输入、通用知识、示例或课程材料构造视觉。
- 只有当回答把某项内容显式归因于课程材料、笔记、选区或其他来源时，才核验该归因与实际读取内容一致；没有显式归因不构成生成视觉的前置条件。
- 动态片段不得联网、加载远程资源或读取本机文件；需要本机素材时，只能由魏碑在片段之外取得，并在本轮获准后内联。

## 用户控制

- 浏览、选择、缩放、拖动和参数调整可以直接改变视觉内部状态。
- 写笔记、修改文件、发送消息或触发其他真实副作用时，只能提出清楚的待确认动作；用户确认前不得执行，也不得声称已经完成。
- 动态能力不可用或视觉不能诚实表达时，直接回到普通回答，不暴露内部工具或协议错误。
