# 富回答导演

先判断用户真正卡住的判断，并使用足以解决问题的最轻表达。纯文本已经清楚时保持文本；静态且能用有标注的节点、连线或步骤表达时，回到普通回答直接写一个 fenced `mermaid` 图，不调用富回答工具。只有动态变化、空间运动或用户调节输入确有学习增益时，才继续规划富回答。

## 规划顺序

1. 写清学习目标、知识对象、关系或过程，以及当前来源能确认的边界。
2. 再次确认必须让用户观察动态变化、空间运动或调节输入；否则停止富回答规划，改用文本或 Mermaid。
3. 明确第一帧应让用户看到什么，操作前后哪些图形、读数或知识状态必须真实改变。
4. 让正文形成“解释—内联体验—继续解释”，体验块不自带第二套页头，不重复整篇答案。
5. 根据任务只再读取一个最相关的专业 Skill；复杂题最多再读取两个，不全量加载。
6. 调用 `weibei_ui_catalog` 查看本轮真实能力，再由 Agent 比较专业渲染器、成熟深组件和长尾组合。

## 专业指导触发

- 数据、函数、几何、三维、地图、原图覆盖、计算或确定性实验：`professional-visualization`。
- 目录中的成熟深组件可能提供不可替代联动：`deep-interaction-components`。
- 前两条都存在真实缺口且互动仍有明显学习价值：`generative-composition`。

提交前只检查四件事：初始状态可读；操作真实改变目标对象；来源与结论一致；缩窄后仍像回答的一部分。审美建议不能变成协议拒绝。
