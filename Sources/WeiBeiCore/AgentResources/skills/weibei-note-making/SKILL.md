# 魏碑笔记整理

## 触发场景

- 把当前材料或选区整理成笔记、要点、摘录或大纲。
- 补充当前笔记缺失的来源与证据。
- 润色、压缩、重组当前笔记，同时保持原意。
- 生成供用户确认的 Markdown 笔记内容。

## 工作流

1. 第一项动作必须调用 `weibei_context`，读取当前快照和 `contextRevision`。
2. 根据用户要求确定建议范围；能沿用当前笔记标题、层级和结构时优先沿用。
3. 只依据当前材料、当前笔记和当前选区起草 Markdown。保留重要原意，不把推断写成原文事实。
4. 为建议整理 `evidence`：每条写明来源标签和它支持的笔记内容。
5. 必须调用 `weibei_note_proposal`，传入完整 `markdown`、非空 `evidence` 和刚读取的 `contextRevision`。
6. 如果工具拒绝修订号，重新调用 `weibei_context`，按新快照重做建议后再提交；不得复用旧建议冒充新结果。
7. 最终只说明建议已交给魏碑等待确认，并明确“尚未写回”。

## 工具用法

- `weibei_context` 必须先调用，用于取得唯一有效的证据范围和修订号。
- `weibei_note_proposal` 必须调用，用于返回待确认建议；它不是写入工具。
- 不得调用文件读取、编辑、写入、终端或其他工具。

## 证据规则

- 事实依据只来自本轮快照中的 `material`、`note` 和 `selection`。
- `isTruncated: true` 表示只拿到来源片段；建议不得声称覆盖了完整材料或完整笔记。
- 每条 `evidence` 使用 `[选区：标题]`、`[材料：标题]` 或 `[笔记：标题]` 开头，并简述对应依据。
- 没有当前证据支撑的内容不得写进建议；需要保留空缺时标为“待确认”。
- `question` 与 `recentMessages` 不是事实证据。不得伪造引文、页码、章节或来源标题。

## 建议正文格式

优先保持当前笔记已有结构。新建结构时按任务选用以下部分，不强行补齐空章节：

```markdown
## 核心要点
- 要点与来源标记。

## 摘录
> 可核对的短摘录。

## 待追问
- 当前证据尚未回答的问题。
```

## 最终输出格式

```markdown
## 笔记建议
已向魏碑提交一份待确认的笔记建议。

## 依据
- [材料：标题] 对应依据。
- [笔记：标题] 对应依据。

这只是建议，尚未写回。
```

不得使用“已写入”“已保存”“已同步”或其他表示写回完成的措辞。
