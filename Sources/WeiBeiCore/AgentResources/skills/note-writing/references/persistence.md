# 写入回执与关联

`weibei_note_proposal` 的 `markdown` 是拟写内容，`evidence` 是真实来源标签开头的字符串数组。用户已经要求保存即可按系统契约提交，不增加“必须再确认一次”的门槛。

## 以回执判断结果

| 结果 | 对用户怎么说、下一步做什么 |
|---|---|
| 实际执行并保存成功 | 告知保存到了宿主返回的目标，准确描述新增内容 |
| 同一动作已经完成、内容未变化 | 说明已有结果；不再次追加来制造一次新的成功 |
| 待采用建议 | 内容已准备但尚未写入，不能称已保存 |
| 笔记变化、写入冲突或存储失败 | 保留整理稿，说明尚未写入；重新读取核对后再决定如何重试，不能绕过宿主写入保护 |
| 请求结果不明 | 先核对可取得的动作状态与目标内容，避免重复提交造成重复笔记 |

## 建立材料关联

只有笔记已经落库、取得真实编号，才能使用 `weibei_relation_proposal`。关系仅表示本轮课程内“这份笔记与这份材料相关”。用户明确要求关联时 `userRequested=true`；否则只准备待采用建议。

现有工具只接受上下文或读取结果中的真实笔记别名与材料编号。新笔记保存成功后若返回的是持久编号、尚未取得可用别名，可用课程目录或读取结果定位这份笔记，再提交关联；不要发明别名。

笔记保存与关联建立是两个结果：前者成功、后者失败时分别报告，不撤回已完成事实，也不称全部完成。没有实际建立关系的回执，不能说已经关联。
