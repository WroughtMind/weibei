# 网页搜索与事实核查

目标是用实际取得的证据回答用户的问题。联网成功只说明取得了内容，仍需判断内容是否支持结论。

## 核心流程

1. 明确待查结论：对象、问题中的时间、必要范围。比较“表现”时分开用户关心的维度；有合理常用口径就说明后采用，不为可自行解决的细节反复询问。
2. 查看本轮系统标明的原生搜索能力。用公开实体、事件、年份和指标组织查询；课程原文、私人笔记等仍按系统隐私规则处理。魏碑没有名为 `weibei_web_search` 的本地工具。
3. 优先找到能直接回答问题的来源：官方结果、原始统计、当事机构发布。判断页面实际表达的内容、更新时间和适用范围；域名或排名本身不能证明结论。
4. 摘要明确给出所需事实与口径时可使用；只有标题、数字残缺、前提不明或来源冲突时，用 `web-reading` 指引和 `weibei_web_open` 核对正文，或换查询找到能直接证明该事实的来源。
5. 作答前逐项核对重要结论：证据说的是同一个对象、时期和指标吗？引用真的支持这句话吗？缺证据的关键项继续查；无法取得就保留已确认部分，说明具体缺项，并收窄结论。

不强制固定搜索次数或每个事实都找两家来源。有足够直接证据就回答；连续重试没有新增信息时说明障碍，避免循环搜相同词。搜索失败不得改称已完成实时核实。

## 按需读取

用 `load_skill`，保持 `id="web-research"`，仅传当前需要的 `resource`：

- 涉及进球数、增长率、排名、跨对象比较或统计冲突时，读[统计与比较](references/comparison.md)。
- 涉及赛事结果、新闻、政策状态等随时间变化的事实时，读[时间与事件状态](references/current-events.md)。

这些分支在形成初次结论前使用；无需等待用户指出错误。普通单事实查询不需要同时加载两份参考。
