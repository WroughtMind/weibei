# 魏碑细读

## 触发场景

- 解释当前选区、段落、概念或论证。
- 比较当前材料与当前笔记中的说法。
- 提炼作者结论、前提、证据、因果链或概念关系。
- 核对某个判断能否被当前内容支持。

## 工作流

1. 第一项动作必须调用 `weibei_context`，取得当前快照与 `contextRevision`。
2. 确定问题范围：用户明确指向选区时优先读选区；否则按问题使用当前材料和当前笔记。
3. 提取原文主张、支持证据、关键概念与它们之间的关系。
4. 将原文信息与推断分开。推断必须写明推断依据，不能伪装成原文事实。
5. 证据不足时停止补全，明确写“当前上下文未确认”以及缺少的证据。
6. 结论先行，随后给出处和必要拆解。
7. 论证关系、原文对齐、时间线、空间位置或数量关系仅靠文字不够清楚时，用 Pi 原生 `read` 按需读取 `rich-answer-director` 和最相关的一个专业 Skill，再调用 `weibei_ui_catalog` 与 `weibei_rich_answer`；不要把普通段落装进装饰卡片。

## 工具用法

- 必须调用 `weibei_context`；只有用户要求跨文件比较或查关联时，才调用课程地图或搜索。
- 任何富回答提交前必须先调用 `weibei_ui_catalog`；目录不贴合时重新调用目录或诚实退回文本，不得凭旧记忆写组件。
- 不调用 `weibei_note_proposal`；细读回答本身不是笔记写回。
- 如果工具结果的修订号失效，重新调用 `weibei_context`，不得继续使用旧结果。
- 富回答成功后，正文仍按下述结构给出简洁结论与依据；不得输出场景 JSON。

## 证据规则

- 当前文件事实来自本轮快照中的 `material`、`note` 和 `selection`；跨文件事实只能来自本轮课程搜索返回的索引片段。
- `isTruncated: true` 表示只拿到来源片段，不得把片段当成完整材料或完整笔记。
- `question` 与 `recentMessages` 只能帮助理解意图，不能作为事实证据。
- 引用使用 `[选区：标题]`、`[材料：标题]` 或 `[笔记：标题]`。
- 不得引入外部知识，不得伪造引文、页码、章节或来源标题。

## 输出格式

```markdown
## 结论
一句到三句直接回答。

## 依据
- [选区：标题] 证据与它支持的判断。
- [材料：标题] 证据与它支持的判断。

## 拆解
仅写理解问题所需的概念、关系或推理步骤。

## 未确认
只在证据不足时列出尚不能确认的内容。
```

没有内容的章节省略。不得声称任何笔记已经写入或修改。
